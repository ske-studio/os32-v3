# T4a-4: FEP の予約と最大負荷の測定

対象: `TASK_T4_T6_MODULES.md` §3-3 / §7-1 T4a-4。製品へ結線しない測定器具。
`make check-fep-budget-host MUTATE=0 HOST32_RUNNERS=qemu` で実行する。
CROSS_DIR とディスク上の TMPDIR を設定し、検査は `check_slot.sh` を通す。

## 測るもの

同梱 SQLite (製品の GNU89/config、ILP32) と実 `kernel/ime_dict.c`、実 VFS/FD を使う。
512KiB の MEMSYS5 に HEAP → GETMALLOC → MALLOC の順で計数 wrapper を設定する。
最小粒度は現行と同じ 64B。8B prefix の owner と実 xSize を使い、free 時の文脈に
依存しない。固定管理状態80Bを先に差し引いた524,208BをHEAPへ渡す。prefix の二冪丸め増と
MEMSYS5 管理 byte も同じ512KiBの内数 (T4a-3と同じ数え方)。
別ヒープは作らない。ホスト newlib の stdio 用 heap と RAM ファイルは測定対象外。
この wrapper は独立した測定用であり、固定状態は実際の構造体サイズを8Bへ切り上げる。
製品に採用するタグ方式へ統合したら、同じ入力で再測定する。

初期化は SYSTEM、辞書の open/search/learn/close は FEP、アプリの open/SQL/finalize/close は
APP として計上する。APP + SYSTEM の実占有に新要求を加えた値が
`MEMSYS5 capacity - reserve` を超えたら APP を拒否する。実容量は control byte を
引いた 516,096B、共通予約は 192KiB (196,608B)、APP + SYSTEM 上限は 319,488B。
この器具が測る同時 APP 接続上限は **1**。複数接続へ一般化しない。

入力は毎回使い捨ての DB。通常検査は長い値と多数の同音語を持つ合成 S/M/L
(4,096 / 16,384 / 65,536 語) であり、実配布辞書の語数とは区別する。
実 IPADIC の全 S/M/L は次のように指定する:

```sh
FEP_BUDGET_IPADIC=/path/to/ipadic make check-fep-budget-host MUTATE=0 HOST32_RUNNERS=qemu
```

製品の `tools/fep_to_sqlite.py` と同じ cost 定義・重複除去で生成する。
Python SQLite は入力ファイルの生成だけに使い、測定は同梱版で行う。
各 DB に学習 8,192 行を置き、完全一致 (2文字以下) と3文字前方一致の
最大ヒット読みを選ぶ。毎操作で両方を検索し、31B の読み・31B の漢字を
新規学習/更新して freq の増加を実 DB から照合する。
`INPUT` に語数・学習数・ヒット数・サイズ・SHA-256 が出る。
この学習数・SQL 群が検証した負荷の上限であり、任意 SQL/無制限の学習量の保証ではない。

## 受入と観測

1. `PROFILE` で各辞書の open/search/learn の定常量・peak・最大の二冪要求を記録。
2. APP は128行のインメモリ表を作り、(0) prepare 継続、(1) sort の VM を保持して
   prepare 継続、(2) sort + 異なるサイズの stmt の半数を解放して再 prepare、の3経路で
   実割当拒否へ到達する。拒否後も各辞書の検索と学習が成功すること。
3. APP を保持したまま、各経路で S/M/L → S/M/L の9通りを実 reopen で測る。
   `SWITCH` の `before/peak/extra` は MEMSYS5 全占有、`fep_peak` は FEP 占有、
   `request` は prefix 込みの最大要求。`max_free` は実 buddy allocator へ
   一時的に確保/即返却して調べた最大連続空き。総空きから推定しない。
   `from` へ戻してから各 `to` を測り、全27組を独立に通す。
4. 要求予約を `reserve + 64B` とした切替を試作 policy へ渡す。
   pending 設定だけ変わり、旧 DB/パス/占有が不変、旧辞書の検索/学習も成功すること。
   永続 settings 書込み・公開 facade の結線は T4b/c の対象。
5. 各負荷の close 後に APP=FEP=0、shutdown 後に SYSTEM も0を確認する。

`BUDGET` はラッパ込み予算、共通予約、APP上限、APP peak、拒否数、実 allocator の失敗数、
全経路の最大 FEP peak を出す。ホストの所要時間を P100/NP21/W の性能値にしない。

変異は PM が `MUTATE=1` で確認する。正常対照を先に回した後、APP 門だけを削った版は
`denied > before`、予約超過切替門だけを削った版は `pending == 0` の実行時検査で
rc=1となる。ビルド失敗・timeout・signal は変異検出に数えない。

## USER / 常駐の別採取 (PM、64MB NP21/W)

この段はゲスト操作・配備を行わない。PM は最新配備 binary を確認して、同じ起動で
`ver` → `mem` → 引数なし `allocator_bench` → `mem` を実行し、コマンドごとにログを保存する。
`allocator_bench` は既存 F-9 の親モードで6ケースの USER malloc を測り、
副 arena 最小64KiB (管理頁込み)、EXACT/丸め再試行、extent/owner/exit回収を観測する。
既存の O(N)・EFULL・realloc の既知の限界は変更しない。
`mem` の既存 `sbrk_used/sbrk_peak/sbrk_capacity/exec_peak/exec_capacity` を前後で採る。
exec_heap は既存固定256KiB分割を使う。

```sh
python3 tools/fep_budget_capture.py --budget t4a4_ipadic.log \
    --user allocator_bench.log --mem-before mem_before.log --mem-after mem_after.log \
    > t4a4_memory.json
```

収集器は全27切替、F9の全6ケース・exit/reclaim/result成功、常駐の個別上限未満を要求し、
MEMSYS5 / USER malloc / 常駐の3欄で出す。ゲスト値の欠落をホスト値で補わない。
ホストでの収集器の対照は書式検査でありゲスト採取の合格には数えない。

像/RAM ゲート (§7-2) は同じ構成の `make kernel` の map/圧縮像を前後で照合する。
この器具は host だけなので core 増分0。SLACK/free/max連続pages の実値は PM の
ゲスト採取が必要であり、ホスト MEMSYS5 の `max_free` と取り違えない。
