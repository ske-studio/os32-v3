# T3c3 F-9 の基準採取

契約: [TASK_T3_LAYOUT](../../docs/tasks/v3/TASK_T3_LAYOUT.md) T3c3 と §1 F-9。
製品割当器・KAPI は変更しない。ゲスト操作・配備は PM が行う。

## 採取

1. NP21/W 64MB、同じクロック・同じ CUI shell・同じ起動後の状態を使う。
   同世代 manifest / kernel / SDK / 配備先の `allocator_bench.bin` の hash を照合する。
   NHD の更新は停止→配備→再起動 ([D1])。HostDrv だけの更新を反映確認にしない ([V1])。
2. CUI の `mem` と `ver` を保存し、`/usr/bin/allocator_bench.bin` を引数なしで実行する。
   リモートの採取タイムアウトは 60 秒以上、遅い設定では十分延ばす。
   `F9 v=1` の全行と終了コード、終了後の `mem` を保存する。
3. 6 ケースの `phase=reclaim ... ok=1`、最後の `phase=result ok=1`、終了コード 0 を必要とする。
   途中の行だけで合格にしない。`ok=0`、fault、時計の取得失敗、確保失敗はそのまま残す。
4. 同じ起動条件で 3 回以上採り、生の値を保存する。T3c4 も同じ入力・同じ fixture を使う。
   比較はケース・phase・n・bytes ごと。時間と正しさの判定は別にする。
   最小/中央値に集約する場合も全回の raw 出力・構成・基点/hash を添える。

個別の調査は `allocator_bench small16|small64|small256|threshold|holes|realloc`。
個別起動は終了後の親による回収照合がないため、引数なしの採取を置き換えない。

## 入力と観測の意味 (v=1 固定)

- `small16/64/256`: 1 byte の sentinel を残し、CRT の初期 `sbrk_heap_limit` の直後を
  EXACT で 1 page 塞ぐ。このセットアップは計数・時間から除外する。
  4096 byte を N 個確保し、全バイトをケース固有パターンで照合後、確保順に free、trim。
  配置・副 arena サイズは製品どおり。降順に作る副 arena の先は、次の arena/exec heap が塞ぐ。
- `threshold`: 65535 / 65536 / 65537 byte を順に malloc→全バイト照合→free。
  閾値未満の nano と、以上の TOPDOWN の差を読む。
- `holes`: 65536 byte の大塊 70 個を確保、奇数 index 1,3,... の内側から free する。
  初めて本物の `OS32_ERR_FULL` を観測したら停止。`phase=efull` は slots=0、
  owner/extent 数が操作前と一致、errno=ENOMEM を必要とする。残った全ブロックの内容も照合する。
- `realloc`: 同じ虫食いを作り、まだ連続した部分の index 66 を 69632 byte に拡大。
  成功した新領域の旧サイズ全バイトを照合し、旧 unmap の EFULL と errno=ENOMEM を別に記録する。
  `phase=retained` は旧ポインタを再度 free して EFULL が再発することを確認するため、
  旧ブロックが allocator の一覧に残っていることも観測できる。失敗した free の対象と
  他の生存ブロックを全バイト照合。新旧を含む残存ブロックを意図的に exit へ渡す。

`ok=1` はこの既知の挙動が再現され、データ/原状維持/回収の条件が満たされた意味。
EFULL と realloc 後の旧ブロック残存を解決済みとはしない。正しさの扱い・性能の判断は T3c4。

## 出力の読み方

通常行は固定順で次の欄を持つ (数値は 10 進)。

```text
F9 v=1 case=... phase=... n=... bytes=... arenas=... large=... map=... exact=... exact_fail=... map_fail=... unmap=... unmap_full=... extents=... slots=... owner=... errno=... us_hi=... us_lo=... value=... ok=...
```

- `arenas`: primary 1 + 現在存在する副 arena。`large`: 現在存在する大塊の map 数。
  fixture 内の KAPI 表コピーで実 malloc/trim の map/unmap を転送し、成功した非 EXACT map を
  flags=0 (副 arena) / TOPDOWN (大塊) に分ける。成功 EXACT は範囲を伸ばし、成功 unmap は
  範囲を縮め/消す。失敗 unmap は計数上も残す。内部リスト/チャンクのレイアウトには依存しない。
  `MemStat.arenas` は kernel exec_heap の指標なので USER nano の arena 数に流用しない。
- `map`/`exact`/`exact_fail`/`map_fail`/`unmap`/`unmap_full` は子の計測開始以後の累積 syscall 数。
  `map` は EXACT も含み、`map_fail` は EXACT 失敗も含む。障害の注入・模擬失敗は行わない。
  転送 wrapper の計数・範囲検索の費用も時間に含まれる (最大 330 record)。
  これは同じ fixture 間の比較値であり、観測処理を除いた製品単体の時間ではない。
- `extents`/`slots`/`owner` は実 `mem_stat(-1)` の extent 使用数/空き/owner の物理頁数。
  ANON の隣接 map は併合されるため、arena/large 数と extent 数は一致しない。
- `errno` は対象操作直前に 0 を入れ、直後に保存する。成功でも先行 EXACT 失敗等の
  ENOMEM が残ることがある。小割当の errno 単独では失敗扱いにしない。
- 時間は `sys_time_now` の実 µs。`us_hi * 4294967296 + us_lo` が区間の経過。
  alloc/free/trim のループ本体を囲み、出力・MemStat・データ照合は区間外。
  穴作りの alloc/data/exit/retained 行の時間 0 は未計時。efull/realloc は対象の 1 操作。
  時計の AGAIN は最大 8 回再試行し、取得不能なら `ok=0`。代替の tick は使わない。
- `value`: alloc=成功個数、small free=free 個数、trim=返却頁数、efull/data=最初の失敗 index、
  realloc=期待する残存大塊数 (large と照合)、retained=旧 index、その他=0。

`phase=reclaim` は別書式。子の終了種別/rc/code と、親の前後の pool/owner/leftover 頁を表示する。
`ok` はさらに kheap/常駐 exec_heap/親 extent/親 exec_heap 使用量の不変と reclaim_count 増加を確認する。
子の全 USER mapping は終了処理へ渡し、物理 pool 復帰と leftover 不増加で回収を照合する。
最外 fixture 終了前後の常駐消費は `mem` も照合する。

ホスト試験 `make check-allocator-bench-host MUTATE=0` は実 nano と実 extent 方針を使い、
計数・書式・EFULL/旧ブロック保持・時計取得不能を確認する。page backing と時計はホスト試験用。
その時間は性能値ではなく、ゲスト実測の代用にしない。
