## 0. この試験が**触らないもの**

**NP21/W・エミュレータ・HTTP・実時間に一切触らない。** 待ち時間は 1 秒も無い。
ゲストは贋物 (`FakeGuest`)、時計は贋物 (`Clock`)、出力ファイルだけが本物の
一時ディレクトリのファイル。だから `make check` の列に入れてある。

## 1. なぜ「純粋な部分」と「触る部分」に割ったか

票 §5 の R7 がそう要求している。壊れると痛いのは

- 一覧 → **スクリプトの生成**  (順序・3 行の形・切り詰め)
- 出力 → **集計**              (終了コードと集計行の突き合わせ)
- **食い違いの検出**           (`0` なのに `FAIL`、`1` なのに `PASS`)
- **見張りの判定**             (伸びなくなった / 上限に当たった)

の 4 つで、どれも**エミュレータにも時計にも関係が無い**。`tools/guest_tests.py`
はこれを上半分の純関数に置き、下半分 (HTTP・ファイルの見張り・rshell の
開き直し) を薄く保って `run_suite(guest, ..., now=, sleep=, log=)` で
**注入できる**形にしてある。

| 純粋 (贋物の入力だけで全部踏める) | 触る (注入して同じ道を通す) |
|---|---|
| `parse_list` / `build_script` | `Np21Guest` (`/api/cmd` `/api/key`) |
| `parse_output` / `parse_summary` | 出力ファイルの読み取り・大きさ |
| `classify` / `aggregate` / `format_report` | `reopen_shell()` (ESC → `rshell` → `ver`) |
| `Watch` / `running_test` / `hostdrv_verdict` | `resolve_hostdrv_dir()` |

HTTP は `tools/np21w_mcp/np21w_client.py` を借りている (WSL 直結と Windows の
`curl.exe` の切り替えを既に持っているので作り直さない)。

## 2. RED (最初に踏んだところ)

試験を先に書いて回したときの実際の出力 (7 件):

```
== 5. 集計 ==
  FAIL 報告にも後続の cc が出る
== 12. 通し (全体の上限) ==
  FAIL 上限に当たったら非ゼロ (得たもの: 2 / 期待: 3)
  FAIL 上限に当たったと記録する
== 13. 通し (/host が無い) ==
  FAIL /host が無ければ前提不足で非ゼロ (得たもの: 2 / 期待: 4)
  FAIL 報告を作らない (合格にしない)
  FAIL 前提が無い時点で止まる (走らせない) (得たもの: 1 / 期待: 0)
  FAIL 断る理由を言う [V4]
```

中身は 3 種類だった。

1. **実装の欠陥 (直した)** — 「固まった」ことを `stalled_at` (名前) 1 つで
   表していたので、**固まったが名前が分からない**ときに
   `report_exit_code()` が「固まった」を見落として `2` を返していた。
   票 §3 は「どれで止まったかを言う」ことを求めているが、**名前が分からない
   ことは「止まっていない」ことではない**。`Report.stalled` (起きたか) と
   `Report.stalled_at` (どれか) を分け、終了コードは前者で決めるようにした。
2. **試験の台本の誤り (試験を直した)** — 上限の場面を「100 秒おきに出力」と
   書いたが、1 本あたりの見張り (60 秒) のほうが先に発火する。**伸び続けた
   まま全体の上限に当たる**台本 (30 秒おき) に直した。固まったのと上限に
   当たったのは別の事情なので、`not rep.stalled` も見るようにした。
3. **試験の足場の誤り (試験を直した)** — `/host` が無い場面を作るつもりで、
   贋物の下拵えが先に `<置き場>/test/` を作ってしまっていた。置き場が無い
   ときは作らないようにした。

## 4. 否定側 (`--mutate`) — 10 本すべて RED

実物の `tools/guest_tests.py` を 1 か所ずつ壊して、この試験が**実行時に**
落ちることを見る。どれも Python として正しく `import` は通る。
**「例外で死んだだけ」「構文が壊れただけ」は検出に数えない** — 検査が 1 つも
落ちていない変異は `**検査が 1 つも落ちていない (落ちただけ)**` として不合格に
する。目が働いた証拠は「検査が落ちたこと」だけ。

```
MUTATE 1 食い違い (0 なのに FAIL) を見逃す           RED (6 件)
MUTATE 2 見張りが発火しない                        RED (1 件)
MUTATE 3 固まった試験を名指ししない                    RED (3 件)
MUTATE 4 /host が無いのに合格にする (置き場の門)         RED (2 件)
MUTATE 5 ゲストに /host が無いのを見逃す (印の門)        RED (4 件)
MUTATE 6 落ちた試験 (139) で後続を打ち切る             RED (2 件)
MUTATE 7 前回の出力が混ざるのを見逃す (R8)              RED (1 件)
MUTATE 8 1 なのに PASS を見逃す                   RED (2 件)
MUTATE 9 予約値 (139) を合格として読む                RED (15 件)
MUTATE 10 全体の上限で結果を全部捨てる                   RED (1 件)
```

### 変異が最初に 2 本すり抜けた — 試験のほうを直した

最初に回したとき **4 (置き場の門) と 8 (1 なのに PASS)** が GREEN のままだった。
どちらも**別の門に隠れていた**もので、規則を見ていないのは試験のほうだった。

- **4**: `hostdrv_verdict(False, None, …)` しか踏んでいなかったので、置き場の
  門を消しても**印の門**が拾ってしまう。`hostdrv_verdict(False, "tk", …)` を
  足して、門を 1 つずつ踏むようにした。
- **8**: `classify(1, PASS 3/3)` しか踏んでいなかったので、種別の門を消しても
  **数の門** (`FAIL n/n` は有り得ない) が拾ってしまう。`classify(1, SKIP …)` と
  `classify(1, PASS 1/2)` を足した。`$?=1` なのに `SKIP` は「不合格」と
  「実行しなかった」を混ぜる実害のある形なので、踏む値としても正しい。

**片方だけ見ると、もう片方が壊れても気づけない** — これは票 §2-4 が
終了コードと集計行について言っていることと同じ形の穴だった。
