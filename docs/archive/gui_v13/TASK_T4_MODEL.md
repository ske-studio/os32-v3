## 1. 目的と境界

入出力捕捉やカーネルの待機契約に依存せず、端末の表示用状態をホスト試験で検証する。
FD、KAPI、物理番地、VRAM、実行中のgshell状態を参照しない。
既存lconsole/GUI描画のAPIや挙動は変更しない。

配置は `userland/libos32term/` の独立クレート (`[workspace]` を自身に持つ) とする。
クレート名は `libos32term`、edition 2021、no_std、依存なし。既存userland/rust・gshell workspaceには登録しない。
ホスト試験はリポジトリルートからmanifest指定で実行し、guest用Cargo設定を持ち込まない。
外部依存の追加、生成KAPI編集、既存workspace全体の再編は不可。

## 2. 契約

- 呼び出し側提供の固定容量ストレージを使用し、内部の動的確保を行わない。
- 次元・容量の不正、計算overflow、領域不足は明示的エラー。範囲外を読まず書かない。
- 幅判定は注入可能な変換境界に分離する。Unicodeのbyte数から画面幅を決めない。
- UTF-8は長さ付きchunk入力。未完了列を保持し、最終化時に未完了を処理する。
- 不正継続・過長・surrogate・範囲外を拒否し、常に入力処理を前進させる。
  置換の単位は実装前に明記し、chunk境界で置換結果が変わらないことを試験する。
- セルは単独/全角先頭/全角継続を識別。全角の片側上書きは旧ペアを解除する。
  右端残り1セルでは全角を分割しない。1列画面・ゼロ次元の扱いも定義する。
- 制御文字: CRは行頭、LFは次行の行頭、CRLFは1改行。BSは前の文字先頭へ戻るが消去しない。
  TABは現在行の次の4列境界まで空白を書き、行末でクランプし改行しない。
  x == colsのTABはセル・状態全体を保持して成功する。
  NULを文字列終端にしない。ANSI/VT解釈は対象外。
- 保存上限で無言の上書き・切捨てをしない。保持範囲と表示上限状態を返す。
- clipは半開区間。読み出すセル範囲は拡大してよいが、書込み許可画素矩形は拡大しない。
  負座標・整数端点・空交差を処理する。文字画素の描画実装はこの票の対象外。
- 画面の再露出ではdirtyの有無に依存せず保存セルを取得できる。

## 3. RED → GREEN の受入試験

最初に失敗するテストを実行してから実装する。実行結果とコマンドを報告する。

1. 2/3/4byte UTF-8、不正列、最終未完了、NUL入りの全分割位置で一括入力と同じ結果。
2. 全角の右端折返し、左右片側の上書き、BS、CR/LF/CRLF/TAB、連続改行。
3. 最小次元、容量ちょうど/不足/超過、巨大次元の算術overflow、不正入力時の状態。
4. 任意の操作後も孤立した全角継続セルがなく、保存領域の番兵が変わらない。
5. clipの四辺、負原点、空矩形、部分漢字、非セル整列境界で書込みclipが拡大されない。
6. スクロール/viewport取得/再露出の読み出しが保存モデルと一致する。

ホスト試験: `cargo test --manifest-path userland/libos32term/Cargo.toml --target x86_64-unknown-linux-gnu --offline`。
no_std本体の検査: `cargo check --manifest-path userland/libos32term/Cargo.toml --lib --target x86_64-unknown-linux-gnu --offline`。
後者はhost targetでのライブラリ検査であり、ゲストクロスビルドの代替ではない。
make checkへの登録は共有ファイル変更なので、PMが対象レシピを確認して直列に行う。
最初は独立試験コマンドでRED/GREENを記録し、ゲート登録後にmake checkでも実行する。

ゲスト画面、描画速度、実行時空き、CUI捕捉はこの票では未検証のまま。
