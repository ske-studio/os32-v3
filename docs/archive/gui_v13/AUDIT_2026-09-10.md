## 5. 提案 (決裁待ち)

1. **T5b パネルと「Display fixture」を gshell から撤去**する。T4/T5R は残す。
   `terminal.rs` は端末窓の実装時に「モデル所有と寿命」の参考として読める形で履歴に残る。
2. **T6a は破棄**し、`TASK_T5B_FINITE.md` を「hermes 案・不採用」として凍結する。
3. 端末の形を決める: **常駐型** (gshell が窓を持ち、CUI 子を top-level で 1 本実行、console は
   カーネルが端末モデルへ振る)。S1/S2/T9 と整合し、ローダの制約に触れない。
4. 上を決めたら、v1.3 の実装順は **入出力の芯から**:
   (a) カーネルの仮想コンソール (出力) → (b) 端末窓 (T4/T5R を Paint に接続) →
   (c) 入力統合 (kbd_getchar ← GUI イベント、FEP) → (d) 既存 CUI コマンドを実際に流す →
   (e) full-screen GFX 復帰 → (f) shell script → (g) 設定 S0〜。
   各段はホスト試験 + 実機。**固定 fixture の段は作らない**。
5. 設定 F1/F2a/F2b は、発注根拠を確認したうえで残す (設計書は範囲内)。
6. `RETROSPECTIVE_2026-09-09.md` に「v1.3 は hermes が独断で着手」を追記する。

## 6. 端末の形 — 再検討 (4 アプリ契約を土台に)

### 6.1 いまのカーネルが出来ること (静的確認)

| 事実 | 根拠 |
|---|---|
| 生きている ring3 アドレス空間は **1 つ** (`g_ring3_as`)。exec は**ネストのスタック** (`exec_ctx_stack[MAX_EXEC_NEST=4]`) で、並行ではない | `exec/exec.c:153,213`。ExecContext の注記「PD切り替え不要」 |
| 資源の所有者 = **exec のネスト段** (`res_owner_get()`)。FD / redirect / GUI 窓の回収はこの段で行う | `kernel/gui.c:14`、CLAUDE.md「by owner (exec nest level)」 |
| gshell 側は既に **4 スロット** (`GUI_SLOT_MAX`) と owner を持つ | `userland/gshell/src/wm.rs:404` |
| カーネル→常駐シェルの関数表コールバックの前例あり (`ime_set_render` / `IME_Render`) | `kernel/ime_render.h`、KAPI |
| `console_write` は TVRAM + rshell 時のシリアル複写のみ。差し込み口は無い | `kernel/console.c:322-329` |
| `kbd_getchar` はカーネル内 `hlt` 待ち。GUI の raw 取り込みとは別経路 | `drivers/kbd.c:351-393` |
| アプリ帯 PDE は**アプリごと**に作れる (`paging_addrspace_create_n`)。同じ仮想 0x500000 に別物理を置ける | `kernel/paging.c`、契約 T2a 可視性の注記 |

つまり **4 アプリ = T2a の実装**は、(i) アドレス空間を N 本生かす、(ii) ExecContext を
スタックから表にする、(iii) 所有者をネスト段ではなくアプリ ID にする (FD/redirect/GUI 回収
の鍵が変わる)、(iv) `OP_WAIT` の中で CR3・スタック・exec_heap 状態を切り替える、の 4 点。
カーネル K レーンの本格作業だが、**すべて凍結契約の範囲内**で新しい設計判断は要らない。

### 6.2 端末に共通で要るもの (形に依らない)

- **出力**: `console_write` / `shell_print` を GUI モード時に端末モデルへ振る差し込み口
  (`IME_Render` と同じ関数表方式が自然)。
- **入力**: CUI 子が `kbd_getchar` で待つ間に WM が動く点と、GUI イベント → cooked 入力の変換
  (FEP 込み)。カーネル側。
- **表示**: T4 セルモデル + T5R 描画アダプタ (残す)。

### 6.3 選択肢

| 形 | 内容 | 利点 | 代償 |
|---|---|---|---|
| **A. 常駐型 (いまのカーネルで)** | 端末窓を gshell が持つ。CUI 子は唯一のアプリとして top-level で `exec_run`。console 差し込み口で端末モデルへ | 4 アプリを待たずに端末が出る。S2/T9 と整合 | 端末が「アプリ」でなく WM の一部になる。T2a 実装後に外へ出すなら作り直し (T5b の轍) |
| **B. 4 アプリ (T2a) を先に実装 → 端末は外部アプリ** | v1.3 の最初の票を T2a にする。端末 = 通常アプリ (スロット k)。CUI 子 = 別アプリ (スロット j)、console はカーネルの差し込み口で端末アプリへ (SHM / イベント経由) | 契約どおりの姿。端末が普通のアプリで、gshell は WM のまま。「4 本」がこの時点で本物になる | 端末が画面に出るまでが遠い。所有者 ID 化 (iii) は exec/FD/GUI に横断的 |
| **C. 折衷** | 6.2 のカーネル部 (出力差し込み口・入力統合) を先に作り、端末窓は **A の形で一時的に** gshell に置く。T2a が入ったら B に移す | カーネル部は無駄にならない。端末が早く出る | 端末窓の部分は捨てる前提の実装になる。T5b で一度失敗した進め方 |

### 6.4 決めてもらうこと

「**T2a (4 アプリ) を v1.3 に入れるか**」の一点。入れるなら B、入れないなら A。
C は「T2a は入れるが端末を先に見たい」場合だけ。

**決裁 (2026-09-10): B。** K5 ([TASK_K5_multiapp.md](TASK_K5_multiapp.md)) を v1.3 の最初の票にする。
ROADMAP と PLAN.md は同日に追従済み。
