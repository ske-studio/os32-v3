## 改訂の記録

2026-09-18 (穴 H13 の後始末。ユーザ承認。**末尾追記のみ**):
1. ジャンプ表 118 (`os32gui_w_focused_in`) を追記、`nfunc` 118 → 119。
   引数は **WindowId**。`GUI_PROTO_VERSION` は据え置き (`nfunc` の照合で守られる)。
2. **既存の 77 (`os32gui_w_focused`) は意味を変えない。** 引数は窓スロットの添字のまま。
   意味を変えると、添字を渡している呼び手 (単一窓なら 0 が偶然当たる) が黙って壊れる。
   **77 はアプリからは使えない** (添字を引く口が無い) ので、アプリは 118 を使う。
3. 背景: アプリがフォーカスを問い合わせられず自分で追うしかなかったことが、
   穴 H13 (**文字は入るのにカーソルキーだけが死ぬ**) を踏む前提になっていた。
   [`TASK_EDIT_GUI.md`](../gui_v14/TASK_EDIT_GUI.md) §9 / §12。

2026-09-17 (票 TASK_EDIT_GUI 決裁 A1。**末尾追記のみ**で、既存の番号は動かしていない):
1. U6a — ウィジェット種別に `textarea` (`WK_TEXTAREA` = 8) を追記。`WK_TEXTBOX` (4) は不変。
2. ジャンプ表 111..=117 (`os32gui_w_textarea*`) を追記、`nfunc` 111 → 118。
   `GUI_PROTO_VERSION` は据え置き (版の照合ではなく `nfunc` の照合で守られる)。
3. 共有定数に `GUI_MAX_TEXTAREA_ROWS` / `GUI_TEXTAREA_ROW_CAP` /
   `GUI_TEXTAREA_INPUT_CAP` を追記 (C / Rust 両方)。

2026-09-05 (設計レビュー 7 件をユーザの指示で反映。凍結後の変更):
1. U2 — `Text` が 16B に収まらなかった。全種別を共通ヘッダ 6B + ペイロード 10B に確定、
   オフセットを C / Rust 双方で static assert。
2. T8 — WM の実行文脈 (X1 ハンドラ / X2 COMMIT / X3 WAIT / X4 ポンプ) と許される操作を明文化。
   WM 所有の UI が反応するのはアプリが `OP_WAIT` にいる間だけ、を v1 の限界として記録。
3. G4 / G2 — 可視領域 (互いに素な矩形 ≤ 16) を WM が持ち、`Paint` はその内側だけ。
   クライアントの基底クリップは `Paint` 矩形。露出の再描画も同じ規則。
4. T3 — 待ち行列型 / 導出型の区別、満杯時は Pointer を落とし → 取り込み停止 (欠落なし)、
   `tail` は WM、`head` はアプリが書く。
5. T9 — CUI ⇄ gshell はカーネルのシェル起動ループで入れ替える (`sys_switch_shell`)。
6. U2a — FEP が消費したキーは `Key` として配送しない。
7. G4 — commit 前の描画を表示面に出さないのはバックエンドの責任 (Cirrus は非表示 VRAM +
   エンジン BLT)。
追加: P2 (目標値と測定条件)、G0b (実装可能性の 5 筋書き)。

2026-09-05 (同日 2 回目。再レビュー 4 件 + 追従漏れ 3 件):
1. T3 — 「欠落しない」を取り下げ、保持件数 (リング 128 + カーネル 32 打鍵)、`dropped` 計数、
   `OVERFLOW` 後の復旧 (入力状態を未知に) を規定。
2. T3 — 導出型は `OP_POLL` 時に WM が同じリングへ追記 (入らない分は持ち越し)。`OP_POLL` の
   手順と `head` の消費確認、`OP_WAIT` が導出型の保留で眠らない条件を追加。
3. U2 — generation を載せない代わりに、破棄 index を所有者の次の `OP_POLL` まで再利用しない
   (検疫) + クライアントが破棄済み index 宛を捨てる。
4. G4 — 損傷の 3 状態 (dirty / issued / 一致)。`commit` は issued だけを転送。
追従: U2a の Text 分割 12B → 10B、G3 と K4 の「再起動」を切替に、P2 に入力取り込み tick。

2026-09-05 (同日 3 回目。境界条件 3 件):
1. G4 / T3 — 可視領域の外の dirty は配送対象でなく、`OP_WAIT` は「配送できる Paint」でだけ起きる。
2. U2 — index 検疫を撤回し、ヘッダ 8B (`window: u32` に generation) + ペイロード 8B に変更。
   Text は 8B/件。途中 `OP_POLL` の制限は不要。
3. T3 — 満杯時は「取り込まない」(カーネル待ち行列に残す)。その先の欠落はカーネルが
   `kbd_dropped` で数え、WM が `dropped` に合算して通知。G0b-3 に入力間隔とポンプ条件、
   3b〜3d を追加。
