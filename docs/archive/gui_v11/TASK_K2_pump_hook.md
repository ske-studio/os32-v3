# K2: syscall 境界の入力ポンプ (契約 T6)

> 発行: PM (2026-09-05) / 状態: **受入完了 (2026-09-06)**
> レーン: K / 前提: K1 完了 + W1 の `gui_pump()` が存在
> 親: [TASKS.md](../../tasks/gui/TASKS.md) / 契約: T6 / 設計: [DESIGN.md](../../tasks/gui/DESIGN.md) §9.4 (syscall 境界ポンプ)
> 排他: `kernel/**` `exec/**`

## ゴール

アプリが KAPI を呼んでいる限り、WM がキーボードとマウスの入力を取りこぼさない。
プリエンプション無しの範囲でできる「1 アプリが机を止める」対策 (Win16 の欠点解消の 1 つ)。

## 作業

1. **`int 0x80` 入口** (v2 M2 のトランポリン着地点、`kernel/*ring3*` / `exec/exec.c`) で、
   `gui_register` (K1) に保存した `pump` が非 NULL なら **上限付きで**呼ぶ。
   上限: 1 回の syscall につき 1 回、かつ前回の呼び出しから 1 tick (10ms) 未満なら呼ばない
   (KAPI を毎秒数百回叩くアプリで WM の処理が支配的にならないため。v2 PLAN §3 の
   実測 233/s が基準)。
2. **`pump` の契約** (契約 T8 の X4。W1 が守る側): 入力の取り込みとリングへの追記、
   それに**マウスカーソルのスプライト移動だけ** (数百バイトの VRAM 転送、上限付き)。
   WM の状態機械は進めない (メニューやドラッグはここでは動かない)、それ以外の VRAM
   書き込みをしない、KAPI を呼ばない、ブロックしない、数十 µs で戻る。K2 は呼ぶだけで
   中身を知らない。
3. **再入防止**: ポンプ実行中フラグ。gshell 自身の syscall (owner 1) からは呼ばない
   (WM は自分でポンプを回す)。
4. **強制脱出キー**: 純粋な計算ループには効かない (契約 T6)。現行の ISR 側 CTRL+STOP
   脱出が CPL=3 アプリを `fault_kill` 経路で落とし、gshell (owner 1) に戻ることを
   ring3_guard 相当のテストで確認する。落とした後に WM の `gui_owner_exit` (K1-5) が
   呼ばれて窓が消えること。

## 鉄則

- ポンプはカーネルの信頼境界の内側 (gshell は CPL=0)。ここで落ちるとカーネルごと落ちる
  ので、W1 の `pump` は「入力の取り込み + リングへの追記 + カーソルスプライトの移動」
  以外を禁止する (契約 T8 の X4。本票 2 と同じ)。
- `get_tick` を叩く回数が増えないこと (v2 M0)。上限判定は既存の tick 変数を読むだけ。

## 完了条件 (ゲート G3 の 1 項目)

- `userland/tests/gui_busy.c` (K2 が置く): `OP_INIT` 後に `db_query` 等の KAPI を毎秒
  100 回呼びながら 30 秒計算し続けるアプリ。その間、マウス移動でカーソルが追従し
  (screenshot)、押したクリックとキーはリングに溜まって計算終了後の `OP_POLL` で届く
  (契約 T3 の保持件数の範囲。超えた分は `OVERFLOW` + `dropped` で通知される)。
  **メニューは開かない** (契約 T8 の限界。開くのは `OP_WAIT` 中だけ)。
- 同じアプリを KAPI を一切呼ばない版にするとカーソルも止まり、CTRL+STOP で kill されて
  gshell に戻る (これが仕様どおりの限界であることを票に書き残す)。
- syscall 1 回あたりの追加コストが実測 10µs 未満 (`emu_prof` で `gui_pump` の占有率)。
