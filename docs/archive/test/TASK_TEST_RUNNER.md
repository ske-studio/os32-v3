## 0. 目的

所定の試験をゲストで**一括実行**し、合否を**ホストで機械が集計する**。
`make check-guest` として `make check` とは**別**にする (NP21/W の稼働が要るため)。

v3 の ABI 整理は「変更のたびに全試験をゲストで回せる」ことが前提なので、その前に作る。

## 1. 確認済みの事実 (2026-09-17、実機で確かめた)

**シェルにできること・できないこと**を実測した。設計はこの範囲に収める。

| 使える | 使えない |
|---|---|
| `>` `>>` のリダイレクト | **`;` での連結** (`echo a ; echo b` → `a ; echo b` と字面のまま) |
| `source FILE` / `.` | **ループ** (`for` / `while` は無い) |
| `$?` (スクリプト内でも正しい) | `if` は **1 行形だけ** (`if VAL1 == VAL2 CMD`) |
| `exit [N]` | |

**`/api/cmd` は複数行を受け付ける**が、**応答に乗るのは 1 行目の出力だけ**
(1 つ目の終端で応答が閉じる)。2 行目以降も実行はされる。
**`source` の出力も応答に乗らない** — 画面には出る。
→ **出力はすべてファイルへ落とす。画面もシリアルも当てにしない。**

**落ちた試験の扱い** (2026-09-17 実測、`crash` がガードで死ぬようになった後):

    start
    crash-rc=139          ← 例外で畳まれた試験の `$?` が正しく拾える
    (klibc_test の出力)
    klibc-rc=0
    end                   ← **スクリプトは落ちた後も続く**

これが 3 段目の土台。**落ちても止まらず、落ちたことは値で分かる。**

## 2. 設計

### 2-1. ゲスト側 — **生成した平らなスクリプト**

ループが無いので、**ホストが試験ごとに 3 行を並べたスクリプトを組み立てる**。

    echo RUN <名前> >> /host/test/out.txt
    <名前> >> /host/test/out.txt
    echo RC <名前> $? >> /host/test/out.txt
    ...
    echo RUNTESTS DONE >> /host/test/out.txt

これをゲストで `source /host/test/runtests.sh` する。
**生成なので、どの試験がどの順で走るかがホスト側に残る** (再現できる)。

### 2-2. ホスト側 — `tools/guest_tests.py`

1. **`/host` が使えるか確かめる。** 無ければ**断って非ゼロで終わる**。
   実機には HostDrv が無い ([`TASK_TEST_RESULT.md`](TASK_TEST_RESULT.md) §3)。
   **黙って合格にしない** ([V4])。
2. **rshell を開き直す。** 長く開いたままのセッションは腐ることがある
   (`$?` が固着し `source` が効かなくなる。[`POLICY_DEBUG.md`](../../POLICY_DEBUG.md) §4-36 系)。
3. 一覧 (§2-3) からスクリプトを生成して `/host/test/` へ置く。
4. `source` を投げる。**応答の時間切れは失敗ではない** — 走り続けている。
5. 出力ファイルを見張る。`RUNTESTS DONE` が出たら終わり。
6. **集計して、終了コードと集計行を突き合わせる**。

### 2-3. 走らせる一覧は**票ではなくファイル**に持つ

`tools/tests/guest_tests.txt` に 1 行 1 件。第 1 陣 (前段 §4 の 16 本) から始める。
分類 (c) の画面デモ・(e) の対話・末尾でキー待ちするものは**入れない**
(前段 §8 の分類)。理由を行のコメントに書く。

### 2-4. 集計 — **2 つの答えが一致することを見る**

前段の約束事は**終了コードと集計行の両方**を出す。ランナーは片方を選ばず、
**食い違いを不合格として報告する**。片方だけ見ると、約束事が壊れたときに気づけない。

| 終了コード | 集計行 | 判定 |
|---|---|---|
| 0 | `PASS n/n` | 合格 |
| 1 | `FAIL m/n` | 不合格 |
| 2 | `SKIP 理由` | 実行しなかった |
| 139 / 126 / 127 / 130 | **集計行が出ない** | **落ちた・起こせなかった** (値で種別が分かる) |
| 0 | `FAIL …` | **食い違い = 不合格**。約束事が壊れている |
| 1 | `PASS …` | 同上 |

## 3. 止まらないための仕掛け

**いちばん危ないのは、1 本が固まって全体が終わらないこと。**
ゲスト側からは手が出せないので、**ホストが見張る**。

- 出力ファイルが **N 秒伸びなければ**、直前の `RUN <名前>` を**固まった試験**として
  報告し、非ゼロで終わる。「どれで止まったか」が分かることが肝心。
- 全体にも上限を置く。上限に当たったら、**そこまでの結果を出してから**落ちる
  (全部捨てない)。
- [V3] 待ち時間を短く切らない。1 本あたりの見張りは 60 秒以上から始める。

## 4. `make check-guest`

`make check` とは**別**にする。NP21/W が動いている必要があり ([D1] の領域)、
`make check` はホストだけで完結する約束だから。
`tools/emu_agent/agent.py` の `MAKE_TARGETS` にも足す。

## 5. 受入

| ID | 反例・操作 | 期待 |
|---|---|---|
| R1 | `make check-guest` を通す | 一覧の全件が走り、結果が表になる。1 件でも不合格なら非ゼロ |
| R2 | 一覧の 1 本をわざと壊す (集計を FAIL にする) | その 1 本だけ不合格。**残りは走り切る** |
| R3 | 一覧に `crash` を入れる | `RC crash 139` が出て、集計行が無いことを「落ちた」と読む。**後続が走る** |
| R4 | 一覧に固まる試験を入れる | **どれで止まったかを名指しして**非ゼロ。全体が無限に待たない |
| R5 | 終了コードと集計行を食い違わせた試験 | **不合格として報告**。どちらか片方を採らない |
| R6 | `/host` を使えなくする | **断って非ゼロ**。合格にしない |
| R7 | ホスト試験 (`tools/tests/`) | 生成するスクリプトの形、集計、食い違いの検出、見張りの発火を贋物の出力で確かめる。`--mutate` で否定側 |
| R8 | 2 回続けて回す | 2 回目も同じ結果。前回の出力が混ざらない |

R7 が本体。**ゲストが要る部分と要らない部分を分ける** — 生成と集計はホストだけで
試験でき、そこが壊れていたらゲストで回しても意味がない。
