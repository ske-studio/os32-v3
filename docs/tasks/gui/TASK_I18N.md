# TASK_I18N — UI メッセージの多言語対応 (SQLite のメッセージ表)

## 1. 目的と範囲

ユーザーランドの UI に出す文字列 (GUI のラベル・ダイアログ・CUI コマンドのメッセージ) を、メッセージ ID ごとに言語別の翻訳で持ち、言語を切り替えられるようにする。

- **対象**: ユーザーランド (gshell、libos32gui、`userland/cmds`・`system` のコマンド、アプリ)。
- **対象外**: カーネルの `kprintf` (起動ログ・障害の表示は英語固定。表を引く経路を持たない)。apps/game (SDK が整った後に各自)。

## 2. 決定 (ユーザー、2026-09-30 — 再議論しない)

| # | 決定 |
|---|---|
| 1 | **既定言語は英語**。各バイナリは英語の文字列だけを内蔵し (最小)、翻訳表は上書き用。SQLite が無い構成 (FD 起動の MINIMAL、D21) や表が壊れている・無いときは英語で出る |
| 2 | **ID は名前方式**。ただし冗長な名前は避ける: **区分 (scope) + 短い名前 (key)** の 2 列。区分は `common` (アプリ共通の `ok` / `cancel` / `yes` / `no` / `close` / `error.nomem` など) と `app:<名前>` (例: `app:filer` の `copy.confirm`)。区分がアプリ名を持つので key にアプリ名を繰り返さない。引く順は **自分の区分 → `common`** (アプリが共通の文言を自分の区分で上書きできる)。key の長さの上限 (例 31B) と文字種 (`[a-z0-9_.]`) は `make check` で検査 |
| 2b | **名前は管理用、ビルドで番号に畳む**: 生成器が区分ごとの番号ヘッダ (C / Rust) を作り、バイナリには番号と英語の文字列だけが入る (名前の文字列は入らない)。`sdk/kapi.json` → 生成物の流れと同じ ([ABI1] と同じく生成物は手で直さない)。**一度使った名前の意味は変えない** (変えるときは新しい名前) |
| 3 | 読み込みは **アプリの起動時に自分の区分と `common` をまとめて読み、メモリに持つ** (1 行ごとに SQLite を引かない — MEMSYS5 512KB を全体で共有しているため)。`settings.db` と同じ「開いて読んで閉じる」 |
| 4 | **引数は番号付き** (言語で語順が変わる)。**車輪の再発明を避ける** — 独自の書式を作らず既存の規格に乗る (§3) |
| 5 | 表示できる文字: まず **英語 + 日本語**。CUI の KCG ROM は JIS の範囲だけなので、ハングル・簡体字・欧文のアクセント付き文字などは **GUI の OpenType 層 (T7b) の後** |

## 3. 車輪の再発明を避ける — 既存の規格・道具の候補 (設計票で確定)

| 部分 | 候補 | 理由・注意 |
|---|---|---|
| 翻訳の原本 (人が編集する形) | **GNU gettext の PO 形式** — `msgctxt` = 区分、`msgid` = key、`msgstr` = 訳文 | 翻訳者の道具 (Poedit など)、差分の取り込み (`msgmerge`)、未訳・あいまい訳の印 (`fuzzy`) がそのまま使える。ID を `msgid` に入れる「キー方式の PO」は一般的な使い方。英語の原文も PO (`en`) に置くか、ソースの内蔵文字列から抽出するかは設計で |
| ホストの生成器 | Python の PO 読み取り (`polib`、または GNU gettext の `msgfmt` で `.mo` → Python 標準の `gettext` モジュールで読む) → SQLite (`mk_settings_db.py` と同じ流儀で `messages.db` を作る) | 今は `polib` も `msgfmt` も入っていない — 依存の追加は設計票で決める (CI の `build.yml` にも) |
| 番号付き引数の書式 | **POSIX の `%n$` 書式** (`"%2$s を %1$s にコピー"`) | gettext の `c-format` 検査が引数の数・型の食い違いを見つける。**注意: 今の newlib は nano 構成 (`--enable-newlib-nano-formatted-io`、[08_build.md](../../08_build.md)) で、nano の printf は `%n$` を扱わない** — 選択肢は (a) 番号付きを扱う小さな前処理 (引数を並べ替えて通常の printf へ渡す)、(b) newlib の位置引数の構成 (`--enable-newlib-io-pos-args`、nano と両立しない — 容量の実測が要る)。どちらにしても書式そのものは POSIX のまま。Rust 側は `format!` の番号付き引数 (`{0}`) に写すか、同じ前処理を使う |
| 複数形・数の書き方 | gettext の `Plural-Forms` (英語・日本語では要るのは英語だけ) | 最初は英語の 2 形だけ。言語を増やすときに CLDR の規則へ |
| 言語の指定 | `settings.db` の `system` 区分に 1 キー (`locale/lang` など、値は BCP 47 の言語タグ `en` / `ja`) | [TASK_CONTROL_PANEL](TASK_CONTROL_PANEL.md) の項目に入れる |

## 4. 設計で決めること (設計票で答える)

| # | 問い |
|---|---|
| Q1 | 英語の原文の正典はどこか — ソースの内蔵文字列 (抽出して PO を作る) か、PO の `en` (生成してヘッダに入れる) か。片方から他方を作り、二重に持たない |
| Q2 | メッセージ表のスキーマ: `messages(scope, key, lang, text)` + `meta(schema_version)`。ファイルは `settings.db` と分けるか (分けるなら `/etc/messages.db`、配備で上書きしてよい — 利用者のデータを持たないため) |
| Q3 | 起動時の読み込みの API (`libos32cfg` に足すか、新しい小さなライブラリか) と、読み込み失敗時の扱い (英語のまま続ける、1 回だけ警告) |
| Q4 | `%n$` の実行時の扱い (§3 の (a) / (b)) と、訳文の引数が原文と合わないときの扱い (生成時に拒否) |
| Q5 | 表示幅: 訳文が長くなってボタン・窓に収まらないとき (ウィジェット側の切り詰めは UTF-8 境界、日本語は 2 桁) |
| Q6 | 言語の切り替えの反映: 再起動か、アプリの読み直しか ([TASK_CONTROL_PANEL](TASK_CONTROL_PANEL.md) Q2 の変更通知と同じ口) |
| Q7 | 検査 (`make check`): 名前の文字種・長さ、区分ごとの重複、未使用の名前、未訳 (言語ごとの件数を出すだけか失敗にするか)、引数の食い違い |

## 5. 依存と順序

- **前**: P1 の T4 (SQLite のモジュール化、`db_*` の経路が変わる)、[TASK_CONTROL_PANEL](TASK_CONTROL_PANEL.md) (言語を選ぶ画面)。
- **最初の版**: 英語 + 日本語、gshell と libos32gui の共通語 (`common`) から。コマンドは後から少しずつ。
- **後**: 他の文字体系は OpenType 層 (T7b) の後。

## 6. しないこと

- カーネルのメッセージの翻訳。
- 独自の翻訳ファイル形式・独自の書式記法 (§3 の規格に乗る)。
- 実行中に 1 行ずつ SQLite を引く方式。
