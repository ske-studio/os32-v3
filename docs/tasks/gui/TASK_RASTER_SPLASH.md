## 0. ユーザーの決定・指示 (2026-11-01、原文)

- 草案「os32-v3_raster_splash_design_draft.md」(外部の画像を起動のスプラッシュに、走査線ごとのパレットで 16 色より多くの色)。「別の部分なのですが、同時に行えますか？」
- 「実機は既定31khzですが、pc9801は24.8なのでそのへんを把握してから吸収できればいいなと」— 31.47kHz と 24.83kHz の両方の周期を把握し、起動時にモードを判定して吸収する。
- 「確かめは不確実でいいです。実機前で確認する時にでも」— 実機の 24kHz は受入の必須にせず、立会いの回のついで。
- 「120usがマジックナンバーの可能性」— `gfx/gfx_vram.c` の `RASTER_LINE_US=120` は NP21/W で合わせた値。既存のロゴのラスタも周期の定数と VSYNC からの位置の待ちに置き換える。
- 「原画はとりあえず何でも良いのですが、だいたいラスタライズやディザリングで256色でも遜色ない画像が良いですね」

- 2026-11-04 11:53、実機の観測の 2 回目 (S4 の 8 枚) をカメラで見て:「N8でも見られる程度に収まっています。」「採用します。」「差し替える画像をまた渡します。」— 凍結しない。可変 OUT (前の行から変わった成分だけを書く) の方式を採用。画像はユーザーが差し替える。
