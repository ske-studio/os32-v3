## 0. ユーザーの決定・指示 (2026-11-01、原文)

- 草案「os32-v3_raster_splash_design_draft.md」(外部の画像を起動のスプラッシュに、走査線ごとのパレットで 16 色より多くの色)。「別の部分なのですが、同時に行えますか？」
- 「実機は既定31khzですが、pc9801は24.8なのでそのへんを把握してから吸収できればいいなと」— 31.47kHz と 24.83kHz の両方の周期を把握し、起動時にモードを判定して吸収する。
- 「確かめは不確実でいいです。実機前で確認する時にでも」— 実機の 24kHz は受入の必須にせず、立会いの回のついで。
- 「120usがマジックナンバーの可能性」— `gfx/gfx_vram.c` の `RASTER_LINE_US=120` は NP21/W で合わせた値。既存のロゴのラスタも周期の定数と VSYNC からの位置の待ちに置き換える。
- 「原画はとりあえず何でも良いのですが、だいたいラスタライズやディザリングで256色でも遜色ない画像が良いですね」
- 「ホストのプレビューはPNGでそれっぽかったらとりあえずいいです」

## 1. 詳細設計 (確定) の要約

- 走査のモードは 09A8h の D0 で判定し、8 フレームの VSYNC の周期と ±1% で照合。行の周期はモードごとの有理数の定数 (SYNC の値から)。ラスタの時刻に `cpu_delay_us` を使わない。VSYNC の bit の高い幅で、非表示の全体型 (NP21/W) か VS 型かを判別して可視行 0 を決める。判別できなければ動くラスタをやめて静止画だけ。
- 割り込みは目標の 1 行前から 4 回の OUT までだけ止め、各区間の後に 1 行以上開ける。2 行未満の間隔のイベントは拒否。遅れは次の HBLANK に繰り越して数える。
- 画像は `.osri` (640×400・4 プレーン・RGB444・イベント列・CRC)。NORMAL の構成だけに配り、無い・壊れていれば内蔵のロゴ。起動 FD・MINIMAL は内蔵のまま。ホストの変換の道具は誤差拡散と、256 色に減色した原画と並べた PNG のプレビュー。
- 段 0 (測定と既存のロゴの置き換え) 〜 段 4 (2/1 行の実験) と受入・変異は確定設計 §7・§8。実機は 31kHz とカメラ (副尺の模様)、24kHz は台帳の立会いの行。
