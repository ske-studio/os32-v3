# 他アーキテクチャ移植調査 — 索引

> 発行: PM (2026-09-08) / 状態: **計画 (2026-09-08)**

> **快照**: この調査の本体は別リポジトリ `pw-sh4-research` で続いている。本リポジトリの写しは 2026-09-08〜09 時点のもので、ここでは更新しない (2026-09-16、PM 注記)。

*開設: 2026-09-08 / 種別: **調査記録の置き場** — 計画でもロードマップでもない*

OS32 は i386 専用 (保護モード / GDT / IDT / i8259 PIC / V86 / `int 0x80`) であり、
PC-9801/9821 のハードウェアに密着している。
それを **別のアーキテクチャや別の実機に載せられるか** を調べた記録を、比較できる形でここに集める。

ここにある文書はどれも「調べた結果」であって、**着手の決定を意味しない**。
実際に進めることになった対象があれば、そのとき初めて `docs/ROADMAP.md` と個別の計画文書を立てる。

## 2. 共通の調査軸

次の対象を調べるときも同じ順で書く。並べて比較できることが、この置き場の唯一の存在理由である。

| 軸 | 見るもの |
|---|---|
| **A. ISA と ABI** | 命令セット、エンディアン、非整列アクセスの可否、FPU の有無、呼び出し規約 (KAPI の `__cdecl` / System V i386 ABI をどう置き換えるか) |
| **B. 番地体系とメモリ** | 物理メモリ配置、`include/memmap.h` の帯域構成が成立するか、MMU の方式、キャッシュのコヒーレンシ |
| **C. 表示** | コントローラ、画素形式、フレームバッファの転送方式 (CPU 直書きか DMA か)、`gfx/` のバックエンドをどう足すか |
| **D. 入力** | キーボード / ポインタの接続方式、割り込みかポーリングか |
| **E. 記憶** | ブロックデバイスの経路。`fs/` (VFS / ext2 / FatFs) の下だけ差し替えて済むか |
| **F. 起動経路** | 独自コードを実行させる手段、失敗時に戻せるか (文鎮化リスク) |
| **G. 検証環境** | **最重要**。NP21/W ai-debug (`/api/cmd`, `emu_read_mem`, `make hotdeploy`) に相当するものが有るか。無ければ開発速度が桁で落ちる |
| **H. OS32 側の棚卸し** | 全廃 / 作り直し / 流用可 を領域ごとに。行数ではなく「中枢かどうか」で見る |
| **I. 未確認事項** | 実機または一次資料でしか埋まらない項目を分離して列挙する |

各軸の中身は対象ごとに違うので、**本文は各調査文書に置き、この索引には要約と表だけを置く**
(`docs/INDEX.md`「情報単位ごとの正典」の方針)。

## 3. 移植先を問わず先にやれること

どの対象を選んでも共通に効き、かつ **実機が無くても今日できる**作業。x86 のままでも潜在バグの発見になる。

1. ~~**非整列アクセスの監査**~~ → **実施済み** (2026-09-08): [M0_PORTABILITY_AUDIT.md](M0_PORTABILITY_AUDIT.md) §3。
   確定的な不具合 2 件、潜在 1 件。うち 1 件は **x86 のままでも危ない既存バグ**だった。
2. ~~**キャッシュ前提の洗い出し**~~ → **実施済み** (2026-09-08): [M0_PORTABILITY_AUDIT.md](M0_PORTABILITY_AUDIT.md) §6。
   ロードしたコードへ飛ぶ経路とページ表操作が該当。ARMv5 の VIVT キャッシュは PD 切替のたびに全消しが要る。
3. **ISA 非依存化の切り分け** — `.asm` 20 ファイルとインラインアセンブリ 12 ファイルが、
   どれが「中枢だから作り直し」でどれが「最適化だから C に戻せる」かの仕分け。**未実施**。
