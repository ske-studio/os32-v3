# P4 — 検査を設計から書き直す (U9。古い検査は動かさない)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

検査の本体は古い物を `tests/` に移さず、設計書から新しく書く (ユーザー決定 2026-11-25、DECISIONS の U9)。古い検査 (`tools/tests/`・`tools/checks/`・`tools/accept/` ほか、`data/scope.tsv` の担当 `P1-4` の 2,787 ファイル・登録 814 本) は今の置き場のまま今の CI で回し続け、切り替え (P7) で消す。P3 の波で直すのは古い検査の中のパスだけ。

**前提**: P3 が終わっている (新しい検査は `sys/` のパスで書く)。P6-1〜P6-3 (新しい登録・入口・7 つの状態) が動いている。形は P1-4 の設計書 `docs/design/tools/checks/tests_v2.md` と P1-5 の `registry_v2.md`。

## 新しい検査が満たす事

1. **期待の出所は設計。** 保証の表の行 (下の 1) が指す設計書の節・KAPI の定義・装置の資料から期待を書く。古い検査の期待の値・判定の条件は写さない (古い検査を読んでよいのは、支援の技法と、P5 の対応を付ける時だけ)。設計書に無い事を保証したい時は、先に設計書に書く。
2. **製品のソースを組んで試す。** 模型だけを試す検査は作らない ([TESTS](../../TESTS.md) §5 の R1)。コンパイルが通る事だけを見る物は L1 として登録し、動作の検査に数えない (仕様 §9)。
3. **1 本の検査は 1 つの所属の 1 つの契約。** 2 つの所属にまたがる物は `tests/integration/`。開発の段の名前を検査の名前にしない。
4. **PC-98 と PowerPC の両方が出す契約 (KAPI・FS・HAL) は判定を 1 つ**にし、実行の側だけを分ける (仕様 §10)。エミュレータで言えない項は L5 として登録に書く。
5. **保証の行ごとに壊し方 (変異) が 1 つ以上**あり、新しい検査が赤になる。変異は検査の中に持たず登録から宣言する (形は `registry_v2.md`)。同じ行・同じ条件を壊す変異を重ねない。
6. 置き場は `tests/<対象>/` (仕様 §6)、共通のハーネスと fixture は `tests/support/`、実行の基盤の試験は `tests/infra/`。
