# P4 — 検査を足していく (デバッグしながら。U9・U10)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

移動とビルドが済んだ木 (P3) の上に、検査を新しく書いて新しい CI (`P6.md`) に載せる。古い検査は移さない・直さない。**全部の所属を網羅してから先へ進むのではない** — 下の順 (ビルド → 起動 → 木の形 → デバッグで触った所。U10) で、要る所から足す。古い検査 (`tools/tests/` ほか。タグ `v3-pre-restructure` でも読める) は、不具合を追う時と書く時の参考に読んでよい。

## 新しい検査が満たす事

1. **期待の出所は設計。** 設計書の節・KAPI の定義・装置の資料から期待を書き、登録の欄に出所を書く。古い検査の期待の値を出所にしない。設計書に無い事を保証したい時は、先に設計書に書く。
2. **製品のソースを組んで試す。** 模型だけを試す検査は作らない ([TESTS](../../TESTS.md) §5 の R1)。コンパイルが通る事だけを見る物は L1 として登録し、動作の検査に数えない (仕様 §9)。
3. **1 本の検査は 1 つの所属の 1 つの契約。** 2 つの所属にまたがる物は `tests/integration/`。開発の段の名前を検査の名前にしない。
4. **PC-98 と PowerPC の両方が出す契約 (KAPI・FS・HAL) は判定を 1 つ**にし、実行の側だけを分ける (仕様 §10)。エミュレータで言えない項は L5 として登録に書く。
5. **検査ごとに壊し方 (変異) が 1 つ以上**あり、赤になる事を確かめてから載せる (POLICY_CI G12)。変異は登録から宣言する (形は `registry_v2.md`)。
6. 置き場は `tests/<対象>/` (仕様 §6)、共通のハーネスと fixture は `tests/support/` (要る分だけ作る)、実行の基盤の試験は `tests/infra/`。

## 足す順

| 順 | 何を | 中身 |
|---|---|---|
| 1 ビルドと一致（手元でビルド・一致と各変異を確認済み、CI 接続は P6-2） | `tests/infra/` | P6-0 の workflow がしている事 (全部の像のビルド、同じ入力から同じ生成物) を登録に載せる。共通の置き場のソースを PowerPC のコンパイラも通す事 (今の `common-compile`) |
| 2 起動 | `tests/system/` | PowerPC は QEMU で起動して決まった所まで進む事。PC-98 の起動の自動の確かめは案から (仕様 §19。NP21/W を CI から回せるかは runner の範囲と一緒に A1 で決める — P1-7a) |
| 3 木の形 | `tests/infra/`・`tests/tools/` | 所有 `src-owner` (追跡ファイルの全部に所属の行、P1-2 の入口から)、層 (共通 → arch・機種・装置の読みを止める。持ち主は所有の表から)、登録漏れ (`tests/` のファイルで登録の無い物)、文書の検査 (リンク・木・状態ほか — この時に文書の中の古いパスを直す)、KAPI の互換。仕様 §15 の残り (リンクの依存の向き、ビルドに登録されていないソース・登録されていて木に無いソース、HAL の契約 — P1-2 の表のとおり。重複実装は候補を `P8.md` に挙げるだけ)。道具を書き直すか今の道具を載せ直すかは D-12 (この順の前に決める)。旧登録の試験表は P7 で旧検査とともに撤去する |
| 4 デバッグで触った所 | `tests/<対象>/` | 不具合を直す時は、先にその不具合で赤になる検査を書く。機能の実装を再開した後は、触る契約の検査を同じ変更で足す (ROLES §0 の完了条件に入れる — P7-3) |
| 5 止めていた不具合 | — | [DEFERRED_TESTS](../DEFERRED_TESTS.md) §2 の行 (`SND-IRQ10-RA266` ほか) は、再開の時に 4 の形で |
