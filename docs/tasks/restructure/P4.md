# P4 — 検査の移動 (波。期待・判定・名前は変えない)

入口: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)。どの段も先に [RULES.md](RULES.md) を読む。

手順は P3 と同じ道具。合格は「P2-5 の集合の差が 0」と「CI の変異込みの全部の success」(目印がずれた変異は CI が赤にする)。生成物は触らないので P2-1 は「製品の生成物が同じ」の確かめだけ。

| 波 | 動かす物 (仮。P1-4 の対応表のとおり) | 気を付ける所 |
|---|---|---|
| T1 試しの波 | `tools/tests/` のうち 1 つの所属 (例: net) → `tests/net/` | 試験が製品のソースを相対パスで組む所 (`kernel_includes.py`、`ROOT / '…'` の形)、fixture の置き場、`build/checks.d/` の生成 |
| T2 | 共通のハーネス・fixture → `tests/support/` | 読む側が全部の試験。先に動かすと後の波が楽か、後に回すかを T1 の結果で決める |
| T3〜 | 所属ごとに `tests/<対象>/` (kern・arch・platform・dev・gfx・sound・input・fs・kapi・boot・lib・sdk・userland・tools) | 1 波は 200 ファイルまでを目安。重み (`tools/checks/weights.json`) は名前で引くので変わらない事を確かめる |
| Tn-2 | `tools/checks/` (登録の 1 検査 1 ファイル) と `tools/check_*.py` (静的な検査の本体) → `tests/` の該当の所 | 登録の読み込みの根 (`run.py`)、`make check-<名>` の生成、workflow が呼ぶパス (POLICY_CI R6: workflow を読む試験を同じ波で) |
| Tn-1 | `tools/ppc/` を道具 (残す) と試験 (`tests/arch/`・`tests/platform/`・`tests/system/`) に分ける、`tools/accept/` → `tests/system/` | PowerPC の PM (os32powerpc) の台本のパス。受入の道具は pc98emu・ノートへの知らせ |
| Tn | CI の道具の試験 → `tests/infra/`、結合の試験 → `tests/integration/` | — |

P4 の終わり: 完了の基準 (3)、`check-registered` の基準が空、集合の差 0 の記録が波ごとにある。[TESTS](../../TESTS.md) と `08_build` §8-3 の地図を直す。
