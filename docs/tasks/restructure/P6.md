# P6 — CI を一から作る (U1・U2。POLICY_CI R2・R3 の「別の workflow で先に動かし、並べて比べる」。TASK_CI_REWORK の S3〜S7 を畳む)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

始める前に PM が TASK_CI_REWORK の状態行を「残りはこの票の P6 に移した」に直す (二重に持たない)。今の check・build・sep は切り替え (P7) まで触らず、新しい workflow を別のファイルに一から書く (今の YAML を直して育てない)。形は U2: 途中の push は変更に関係する検査、main に入れる SHA は全件を変異込み。下の段は新しい入口と workflow の部品で、どれも今の関門に影響しない。

各段は設計書 `docs/design/tools/ci/ci_v2.md` の節を指す (P1-7a が段ごとに節を割り当てる。途中の push の選び方の入力は P1-7b)。

| 段 | 書き手 / 読み手 | する事 | 受入 |
|---|---|---|---|
| P6-1 登録の欄 | astra / sol | P1-5 の設計のとおりに `CHECK` の欄を足し、その時の登録の全部を機械で移す (母数は実装の基点の `run.py --list`。814 は P0 の時の数で、P5-6 の統廃合の後は変わる)。`--lint` が新しい欄を見る。YAML が要る情報 (組・環境・arch) は全部ここから出る | lint が通る。集合の差 0 |
| P6-2 入口を 1 つに | astra / sol | `make check-…`・`run.py --run`・`gate.py run` を 1 つの入口に (S3)。手元と CI で同じコマンド、同じ表 | 手元と CI で同じ結果の表。片方だけで落ちる検査が 0 |
| P6-3 7 つの状態 | astra / sol | 結果を PASS・FAIL・ERROR・NOT_RUN・NOT_APPLICABLE・DEFERRED・REUSED に (仕様 §14)。SKIP を出す所を全部どれかに振り分ける (S6)。DEFERRED は台帳の ID を持つ物だけ。REUSED は `tools/ci/reuse_success.py` の条件を仕様 §14 の 5 つの一致に | SKIP の行 0。道具の無い環境で ERROR (終了コード 2)。結果の行の無い検査が NOT_RUN で赤 |
| P6-4 YAML から一覧を消す | astra / sol | static-check の手書きの行、`tools/ci/ppc_scope.py` の置き場の一覧を、登録と所有の表から引く (S4)。文書だけの push で PowerPC の 21 ジョブが立ち上がらない形 (`CI-WAIT-PPC20` の案: 判定を 1 本の小さなジョブに) | 完了の基準 (4)。集合の差 0。文書だけの push のジョブの数 |
| P6-5 全部回して表に | astra / sol | 残りのジョブを「1 本落ちても残りを回す」形に、落ちた検査の名前・末尾・遅い検査を要約に (S5) | わざと 2 本落とした枝で残りが回り、表に出る (G12) |
| P6-6 選び方を影で測る | sol / astra | 変更の所属と依存 (所有の表・`.d`・`covers`・生成物) から「回す検査」を出す道具。**切り替えまでは関門に使わず**、push ごとに「選んだら外れていた検査」を記録する。全部の実行の結果と突き合わせ、外した検査が赤だった回 (見逃し) を数える。影響が決められない変更は全部に倒す (仕様 §12) | 20 回以上の push の記録: 見逃しの数・減る所要。ユーザーの A6 の材料 |
| P6-7 変異を分けて測る | sol / astra | 変異なしの回と変異込みの回の所要を分けて記録し、変異を回し直す条件 (検査が変わった・対象のソースが変わった・登録が変わった) の案と、その条件で外れる変異が赤だった回を P6-6 と同じ形で数える | 同上 (A6 の材料) |
| P6-8 成果物の状態 | astra / sol | CI の成果物に BUILT・VERIFIED・ACCEPTED を付ける (仕様 §16)。`tools/ci_fetch.sh`・`land_gate.py` が状態を読む。配布物の生成は検査を待たない (今の artifacts のジョブの形) が、取り込みは VERIFIED だけ | BUILT の成果物を取り込みに使うと止まる。実機の調べには BUILT を取れる |
| P6-9 新旧を並べる | sol / astra | 新しい workflow と今の check・build を同じ SHA で並べて走らせ、検査ごとの結果の差・所要を表に (R3・R8) | 10 回以上で結果の差 0 (差は原因を 1 件ずつ) |

P6-10 (A6 の後): P6-6・P6-7 の数字で、途中の push の選び方と変異の回し直しの条件を決め、新しい workflow に入れる (設計の往復から)。main に入れる SHA の全件は選び方に依らず必ず回す。
