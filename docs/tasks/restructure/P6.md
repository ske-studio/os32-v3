# P6 — CI を一から作る (U1・U2・U9。POLICY_CI R2・R3 の「別の workflow で先に動かし、並べて比べる」。TASK_CI_REWORK の S3〜S7 を畳む)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

始める前に PM が TASK_CI_REWORK の状態行を「残りはこの票の P6 に移した」に直す (二重に持たない)。今の check・build・sep は切り替え (P7) まで触らず、新しい workflow を別のファイルに一から書く (今の YAML を直して育てない)。形は U2: 途中の push は変更に関係する検査、main に入れる SHA は全件を変異込み。下の段は新しい入口と workflow の部品で、どれも今の関門に影響しない。**新しい CI が回すのは新しい検査 (P4) だけ** — 古い検査と古い登録 (`tools/checks/run.py`) には手を入れず、新しい登録・入口は別の物として一から作る (U9)。P6-1〜P6-3 は P3 と並べてよく、P4 の前提。P6-4 以降は P4 の検査が載ってから。

各段は設計書 `docs/design/tools/ci/ci_v2.md` の節を指す (P1-7a が段ごとに節を割り当てる。途中の push の選び方の入力は P1-7b)。

| 段 | 書き手 / 読み手 | する事 | 受入 |
|---|---|---|---|
| P6-1 新しい登録 | astra / sol | P1-5 の設計 (`registry_v2.md`) のとおりに、新しい登録と lint を作る。古い登録は変換しない。変異は登録から宣言する。YAML が要る情報 (組・環境・arch) は全部ここから出る | 見本の検査 (P1-5 の見本) が載り lint が通る。欄を欠いた登録・保証の ID が保証の表に無い登録で落ちる |
| P6-2 入口を 1 つに | astra / sol | 新しい検査を選ぶ・回す・結果を集める入口を 1 つ作る (S3。今の `make check-…`・`run.py --run`・`gate.py run` は切り替えまでそのまま)。手元と CI で同じコマンド、同じ表 | 手元と CI で同じ結果の表。片方だけで落ちる検査が 0 |
| P6-3 7 つの状態 | astra / sol | 結果を PASS・FAIL・ERROR・NOT_RUN・NOT_APPLICABLE・DEFERRED・REUSED に (仕様 §14)。新しい入口は SKIP を出さない (S6)。DEFERRED は台帳の ID を持つ物だけ。REUSED は `tools/ci/reuse_success.py` の条件を仕様 §14 の 5 つの一致に | SKIP の行 0。道具の無い環境で ERROR (終了コード 2)。結果の行の無い検査が NOT_RUN で赤 |
| P6-4 一覧の無い workflow | astra / sol | 新しい workflow は検査の名前とパスを持たず、登録と所有の表から引く (S4。今の static-check の手書きの行と `tools/ci/ppc_scope.py` の一覧は写さない)。文書だけの push で PowerPC の 21 ジョブが立ち上がらない形 (`CI-WAIT-PPC20` の案: 判定を 1 本の小さなジョブに) | 完了の基準 (4)。登録の全部がどれかのジョブで回る (登録と実行の結果の集合の差 0)。文書だけの push のジョブの数 |
| P6-5 全部回して表に | astra / sol | 残りのジョブを「1 本落ちても残りを回す」形に、落ちた検査の名前・末尾・遅い検査を要約に (S5) | わざと 2 本落とした枝で残りが回り、表に出る (G12) |
| P6-6 選び方を影で測る | sol / astra | 変更の所属と依存 (所有の表・`.d`・`covers`・生成物) から「回す検査」を出す道具。**切り替えまでは関門に使わず**、push ごとに「選んだら外れていた検査」を記録する。全部の実行の結果と突き合わせ、外した検査が赤だった回 (見逃し) を数える。影響が決められない変更は全部に倒す (仕様 §12) | 20 回以上の push の記録: 見逃しの数・減る所要。ユーザーの A6 の材料 |
| P6-7 変異を分けて測る | sol / astra | 変異なしの回と変異込みの回の所要を分けて記録し、変異を回し直す条件 (検査が変わった・対象のソースが変わった・登録が変わった) の案と、その条件で外れる変異が赤だった回を P6-6 と同じ形で数える | 同上 (A6 の材料) |
| P6-8 成果物の状態 | astra / sol | CI の成果物に BUILT・VERIFIED・ACCEPTED を付ける (仕様 §16)。`tools/ci_fetch.sh`・`land_gate.py` が状態を読む。配布物の生成は検査を待たない (今の artifacts のジョブの形) が、取り込みは VERIFIED だけ | BUILT の成果物を取り込みに使うと止まる。実機の調べには BUILT を取れる |
| P6-9 新旧を並べる | sol / astra | 新しい workflow と今の check・build を同じ SHA で並べて走らせる (R3・R8)。検査が別の物なので 1 本ずつは比べない — **SHA ごとの合否**と所要を表にし、古い方だけが赤だった回は、どの古い検査が何を見つけたかを読んで、保証の表に行を足すか `P5.md` の「引き継がない」に入れる。わざと壊した枝 (古い検査の変異から所属ごとに選ぶ) も同じ形で流す | 10 回以上で合否の食い違い 0 (食い違いは原因を 1 件ずつ)。壊した枝は両方が赤 |

P6-10 (A6 の後): P6-6・P6-7 の数字で、途中の push の選び方と変異の回し直しの条件を決め、新しい workflow に入れる (設計の往復から)。main に入れる SHA の全件は選び方に依らず必ず回す。
