# P6 — CI を一から作る (U1・U2・U9・U10。小さく始めて育てる)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

始める前に PM が TASK_CI_REWORK の状態行を「残りはこの票の P6 に移した」に直す (二重に持たない)。古い workflow と古い入口 (`tools/checks/run.py`・`tools/ci/gate.py`) は直さない — 移動 (P3) の変更で止め、P7 で消す。新しい CI は別のファイルに一から書き、回すのは新しい検査だけ。形は U2: 途中の push は変更に関係する検査、main に入れる SHA は全件を変異込み。設計は `docs/design/tools/ci/ci_v2.md` (P1-7a)。

| 段 | 書き手 / 読み手 | する事 | 受入 |
|---|---|---|---|
| P6-0 最小の workflow | astra / sol | **P3 の移動と同じ変更で入れる。** 全部の像のビルド (x86・PowerPC の 6 像)、配布物の生成、生成物の一致 (P2-1。基点との比べは移動の枝だけ、以後は同じ入力から同じ生成物)。検査の登録はまだ無い。1 本落ちても残りを回す形 | 移動の枝で success。わざとビルドを壊した枝で赤。配布物を `tools/ci_fetch.sh` で取れる (名前が変わるなら P0-8 の相手に知らせる) |
| P6-1 新しい登録 | astra / sol | `registry_v2.md` (P1-5) のとおりに登録と lint を作る。変異は登録から宣言する。YAML が要る情報 (組・環境・arch) は全部ここから出る | P4 の 1 の最初の検査が載り lint が通る。欄を欠いた登録で落ちる |
| P6-2 入口を 1 つに | astra / sol | 検査を選ぶ・回す・結果を集める入口を 1 つ。手元と CI で同じコマンド、同じ表。workflow は検査の名前とパスを持たず、登録と所有の表から引く。**ここから main の関門は「新しい CI の全部の success」** (`land_gate.py` を新しいジョブに) | 手元と CI で同じ結果の表。完了の基準 (4)。登録の全部がどれかのジョブで回る (登録と実行の結果の集合の差 0) |
| P6-3 7 つの状態 | astra / sol | 結果を PASS・FAIL・ERROR・NOT_RUN・NOT_APPLICABLE・DEFERRED・REUSED に (仕様 §14)。SKIP は出さない。DEFERRED は台帳の ID を持つ物だけ | 完了の基準 (5)。道具の無い環境で ERROR (終了コード 2)。結果の行の無い検査が NOT_RUN で赤 |
| P6-4 全部回して表に | astra / sol | 落ちた検査の名前・末尾・遅い検査を要約に。変異なしの回と変異込みの回の所要を分けて記録 | わざと 2 本落とした枝で残りが回り、表に出る (G12) |
| P6-5 成果物の状態 | astra / sol | CI の成果物に BUILT・VERIFIED・ACCEPTED を付ける (仕様 §16)。`tools/ci_fetch.sh`・`land_gate.py` が状態を読む。配布物の生成は検査を待たないが、取り込みは VERIFIED だけ | BUILT の成果物を取り込みに使うと止まる。実機の調べには BUILT を取れる |
| P6-6 選び方 (後で) | sol / astra | 途中の push で回す検査の選び方と、変異を回し直す条件。**検査が少ないうちは全部を回す** — 全件の所要が目標の時間 (P1-7a の案、A6) を越えた時に、影で測って (選んだら外れていた検査が赤だった回を数える) から決める。main に入れる SHA の全件は選び方に依らず必ず回す | 越えた時に: 20 回以上の push の記録。ユーザーの **A6** |

P6-0 は P3 と一緒。P6-1〜P6-3 は P4 の 1 と一緒に進める (検査の無い登録・入口を先に作り込まない)。P6-4・P6-5 は P4 の 2・3 と並べてよい。
