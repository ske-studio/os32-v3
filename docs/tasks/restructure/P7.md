## 票の完了の基準 (全文)

(1) 追跡ファイルのうち所有の表に行の無い物が 0 (検査 `src-owner` が新しい CI で通る)、(2) 最上位にカーネルのソースの置き場が `sys/` の 1 つだけ (`kernel/`・`mm/`・`exec/`・`init/`・`arch/`・`platform/`・`drivers/`・`hwdev/`・`fs/`・`gfx/`・`sound/`・`input/`・`net/`・`kapi/`・`include/` の各ディレクトリにソースが 0。arch/README.md と platform/README.md は文書として残す)、(3) 検査の本体が `tests/` の下にあり `tools/tests/`・`tools/checks/`・`tools/accept/` が 0 ファイル (古い検査は消して満たす)、(4) workflow の YAML に検査の名前とソースのパスの列挙が 0 行、(5) 結果の表に SKIP の状態が 0 で 7 つの状態 (仕様 §14) だけ、(6) 移動の生成物の一致の記録がある (一致しない物は `Sep-Changes:` の宣言とレビューの記録)、(7) 古い検査と古い CI が木に無く、基点のタグ `v3-pre-restructure` と、その SHA で全件が通った記録がある、(8) CI の所要と検査の数の前後の比較が [gate.md](../../design/tools/ci/gate.md) にある。加えて、`P4.md` の順の 1〜3 の検査が新しい CI に載り、main の関門が U29 に従って選んだ全件の成功を確かめる事。満たした SHA が main に在る。
