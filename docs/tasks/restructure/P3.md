# P3 — ソースの移動 (波。1 波 = 1 枝 = 1 コミット)

入口: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)。どの段も先に [RULES.md](RULES.md) を読む。

波の手順 (どの波も同じ。[SRC_MOVE](../../SRC_MOVE.md) §3 の上に、この票の関門を足した物):

1. 基点が main の先頭である事、動いている枝が無い事を確かめる ([RULES.md](RULES.md) の 5。`wip/snd-irq10-hwb` は止めたまま残す枝で、数えない)。
2. `move_map.json` からこの波の行だけを取り出し、`tools/move_files.py` で移す。置換しきれない一覧を手で直す。
3. `.mk` を直す: 置き場の変数 (`KERNEL_SRC_DIRS` ほか) と所有者集合。**リンクの順 (`build/sources/order.mk`) と `-I` の順は変えない。**
4. 所有の表・`tools/source_roots.py`・許可の一覧・基準の JSON・検査の `covers`・変異の目印のパスを直す (中身は変えない)。
5. 文書・スキル・`CLAUDE.md`・`AGENTS.md` の中のパスを直す (RULES.md の 9)。
6. 手元で回すのは: 触った像のビルド、`tools/include_resolve.py` の前後比較、P2-1 (この波だけ)、`src-owner`・`layers`・文書の検査。全体は push の後の CI (`wt/sep-rs-<波>` で sep・check・build)。
7. 読み手は、対応表のとおりに動いたか (`git diff -M --stat` の改名の率が 100% でない行)、`.mk` の差、置換の手直しの所だけを読む。
8. CI の全部の success → main → P0-8 の相手に知らせる → 次の波。

| 波 | 動かす物 (仮。P1-6 で確定) | 見込み | 気を付ける所 |
|---|---|---|---|
| W1 試しの波 | `net/` → `sys/net/` | 16 本 | 最小の波で手順・道具・CI の 3 本・知らせの経路を 1 周させる。所要と踏んだ事を記録して A3 |
| W2 | `fs/` → `sys/fs/`、`kapi/` → `sys/kapi/` | 95 本 | `kapi/` は生成物 (`kapi_generated.c`) の置き場と check_layers の読み替えの名前。[ABI] は変えない (`sdk/kapi.json` は動かさない) |
| W3 | `gfx/`・`sound/`・`input/` → `sys/<同名>/` | 116 本 | `sound/hal`・`input/hal` は D-4 が決まるまで親と一緒に動かすだけ |
| W4 | `arch/` → `sys/arch/` | 136 本 | 固定名 `arch_*.h` の `-I`、asm の include、PowerPC の `.mk` (`build/arch/`) |
| W5 | `platform/` → `sys/platform/` | 317 本 | `-Iplatform/$(PLATFORM)` と `<platform_*.h>` の引き方、起動の番地のヘッダ、`boot/` からの参照 |
| W6 | `drivers/`・`hwdev/` → `sys/dev/` | 421 本 | 部品 (`.mod`) ごとの `.mk` と出力先。GeForce を 1 か所に寄せるのは D-2 の決定の後で、この波では親ごと動かすだけにするか分けるかを P1-6 で決める |
| W7 | `kernel/`・`mm/`・`exec/`・`init/` → `sys/kern/` | 244 本 | リンクの順、`init/kernel_start.c` の入口、走査型の検査の根 |
| W8 | `kdebug/` | 160 本 | D-3 の決定のとおり。生成物 (`kdebug/generated`) |
| W9 | `include/` → `sys/include/` | 119 本 | 読む側が一番多い。`#include` は名前だけで引いているので `-I` の付け替えで済むはず — P0-5・P2-6 で確かめた形だけ。公開のヘッダ (`sdk/include`) と混ぜない |
| W10 | HAL の寄せ (`sys/hal/`)、`lib/` の分け (D-4・D-5) | P1-3 のとおり | 移すだけで済む物だけ。include の向きが変わる物は P8 |
| W11 | 最上位の片付け (`sample/`・`packages/`・`images/` ほか、D-7)、`sys/conf/` (D-6) | — | 生成物の置き場 (`images/`) と配備の道具のパス |

波を割る・合わせるのは P1-6 と W1 の実測で決めてよい (1 波は半日〜1 日、手直しが 50 か所を越えたら割る)。

P3 の終わり: 完了の基準 (2)、`src-owner` の基準ファイルが空、`layers` の違反 0 のまま、全部の波に一致の記録。実機と NP21/W には、最後の波の後に CI の成果物を 1 回入れて最小受入 (ROLES §4-2。[D2] と実機は個別の承認)。
