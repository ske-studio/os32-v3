# P3 — ソースの移動とビルドを通す (現状が正。U10)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

合格は 3 つ: **ビルドが通る** (x86 の `make all`、PowerPC の 6 像)、**生成物が基点と一致** (P2-1。一致しない所は理由を 1 件ずつ)、**起動する** (NP21/W と PowerPC の QEMU)。古い検査は回さない・中のパスも直さない。古い workflow (check・build・sep・selfhost-probe) は移動の変更で止め、代わりに P6-0 の最小の workflow (ビルドと一致) を入れる。

手順 (枝 `wt/rs-move`。ほかの枝は止める — RULES の 5):

1. 基点が P2-0 のタグである事、動いている枝が無い事を確かめる (`wip/snd-irq10-hwb` は止めたまま残す枝で、数えない)。
2. `data/move_map.json` を `tools/move_files.py` で移す。**1 回で全部を試み**、通らない時は置き場ごとに割る (割り方は詰まった所で決める。先に波の表は作らない)。
3. `.mk` を直す: 置き場の変数 (`KERNEL_SRC_DIRS` ほか) と所有者集合。**リンクの順 (`build/sources/order.mk`) と `-I` の順は変えない。**
4. ビルドを通す。直すのはパスと `.mk` だけ — ソースの中身を変えないと通らない所は止めて報告 (RULES の 1・7)。
5. P2-1 で基点と比べる。一致しない物は原因を読み、パスの文字列だけなら `Sep-Changes:` に書く。それ以外は直す。
6. 起動: PowerPC は QEMU で 6 像のうち起動する像、PC-98 は NP21/W ([D1]・[D2] の範囲、pc98emu に頼んでよい)。基点と同じ所まで進む事を画面とログで見る。
7. 文書・スキル・`CLAUDE.md`・`AGENTS.md` の中のパスは `move_files.py` の置換で直る分だけ。残りは P4 の 1 で文書の検査を載せた時に直す。
8. 読み手は、対応表のとおりに動いたか (`git diff -M --stat` の改名の率が 100% でない行)、`.mk` の差、置換の手直しの所、一致しなかった物の理由を読む。
9. **A3** (ユーザー: ビルド・一致・起動の結果) → main → P0-8 の相手 (ノート・pc98emu・os32powerpc) に知らせる。

気を付ける所 (P0 で分かっている物):

| 所 | 中身 |
|---|---|
| `include/` → `sys/include/` | **バイト一致にならない** — kdebug.elf と kselftest.o に文字列 `include/memmap.h` が入る (P0-5 の A)。差がこの文字列だけである事を P2-1 で確かめる。公開のヘッダ (`sdk/include`) と混ぜない |
| `arch/`・`platform/` | 固定名 `arch_*.h`・`<platform_*.h>` の `-I`、asm の include、PowerPC の `.mk` (`build/arch/`)、起動の番地のヘッダ、`boot/` からの参照 |
| `drivers/`・`hwdev/` → `sys/dev/` | 部品 (`.mod`) ごとの `.mk` と出力先。GeForce の寄せは D-2 のとおり |
| `kernel/`・`mm/`・`exec/`・`init/` → `sys/kern/` | リンクの順、`init/kernel_start.c` の入口 |
| `kapi/` | 生成物 (`kapi_generated.c`) の置き場。[ABI] は変えない (`sdk/kapi.json` は動かさない) |
| `kdebug/` | D-3 のとおり。生成物 (`kdebug/generated`) |
| HAL の寄せ (`sys/hal/`)・`lib/` の分け | `hal_map.tsv` の「移すだけ」の行だけ。include の向きが変わる物は P8 |
| 置換しきれない形 | P0-5 の `unresolved.tsv` 7,517 行のうち、ビルドが読む物 (`.mk`・生成の道具・配備の道具) だけ直す。古い検査の中の行は直さない |

P3 の終わり: 完了の基準 (2)・(6)、A3、main。実機には、その後に CI の成果物を 1 回入れて最小受入 (ROLES §4-2。[D2] と実機は個別の承認)。

**止めた枝への引き継ぎ (U4)**: 移動が main に入ったら、PM が `data/move_map.json` を枝 `wip/snd-irq10-hwb` に `tools/move_files.py` で掛けて新しい置き場に載せ直せる事を確かめ、結果を [DEFERRED_TESTS](../DEFERRED_TESTS.md) の `SND-IRQ10-RA266` の行に書く (入れるのは実装の再開の時)。対応表は P7 で消す前にこの確かめを済ませる。
