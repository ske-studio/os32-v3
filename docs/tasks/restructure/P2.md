# P2 — 移動の前に要る道具 (基点と生成物の一致だけ。U10)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

古い検査は移動に付き合わせない (U10) ので、移行の関門の道具は 2 本だけ。所有・層・登録漏れ・仕様 §15 の残りの検査は、移動の後に新しい検査として足す (`P4.md` の 1)。

| 段 | 書き手 / 読み手 | する事 | 受入 |
|---|---|---|---|
| P2-0 基点 | PM | 移動の直前の main にタグ `v3-pre-restructure` を打ち、その SHA で今の CI の全件 (変異込み) の success を確かめる (古い検査が言える最後の回)。その SHA の生成物 (x86 の出荷する物、PowerPC の 6 像の `.o` と像) を CI の成果物から取り、`~/os32-tmp/run/restructure/base/` に sha256 つきで置く。古い検査と古い CI はこのタグで読める | タグ・SHA・run の番号・生成物の sha256 の表が `P3.md` の末尾にある |
| P2-1 置き場が変わる時の生成物の一致 | astra / sol | **前提**: `userland/libos32gui.elf` に作業木の絶対パスと rustup の置き場が入る (P0_FINDINGS の P0-5 の B) — 比べる前に直す (`--remap-path-prefix` 等) か、比較から外す理由を書く (POLICY_CI G11)。`tools/build_compare.py`・`tools/ci/sep_identity.py` を、対応表 (`data/move_map.json`) を渡すと「旧いパスの `.o` と新しいパスの `.o`」を対にして比べる形にする。パスが生成物に入る所 (P0-5 の A: `include/memmap.h` の文字列ほか) は、差がパスの文字列だけである事を機械で確かめる (丸ごと比較から外さない)。道具の試験は `tools/restructure/` に置き、手元で回す (新しい CI が出来たら載せる) | 何も変えない木で一致。1 本だけ移した木で一致。移した上で 1 バイト変えた木で不一致が出る (POLICY_CI G12 の実演) |
