# P2 — 移動の前に要る道具 (基点と生成物の一致だけ。U10)

> 上位: [TASK_RESTRUCTURE.md](TASK_RESTRUCTURE.md)・[RULES.md](RULES.md) (入口と、どの段も先に読む決まり)

## P2-1 の記録

基点の一覧を入力にする入口と終了値は [sep_identity.md §6](../../design/tools/ci/sep_identity.md) に記載。受入の再実行は `MUTATE=1 make check-restructure-p2-1`。全像の基点採取と再採取は P2-0。

## P2-2 の記録

- Rust の release ビルドは Cargo の `trim-paths` でソース位置を正規化する。木内のターゲットクレートのシンボル識別子には、パッケージ名・版・ターゲット・有効な cfg を使う。Cargo のキャッシュ名は Cargo が決める。
- 2 木の全体比較で見つかった ar メンバーの時刻は GNU ar の決定的モードで固定する。インストール ISO は `SOURCE_DATE_EPOCH` (既定 946684800) を使い、 xorriso でボリュームとファイルの日時を固定する。
- 世代表のリンク入力は木内を相対パスで記録し、Rust メンバー名のうち Cargo のキャッシュ接尾辞を外す。リンク時の検証と個別の入力記録には完全なメンバー名を残す。
- `rust-build-paths` は製品の GUI ELF に作業木と sysroot のパスが残っていないこと、別々の木で組んだ事例のバイト一致、パスとシンボル識別子の各変異を検査する。
- 受入のログは作業領域 `~/os32-tmp/run/restructure/p2-2/tmp/` の `identity.log`。x86 の比較に追加の除外はない。

## P2-3 の記録

- GF の生成器が読む固定 C、来歴 JSON、直列化コードと抽出処理を運用側へ切り出した。PC-98 の受入媒体の生成器と変異表も `tools/` に置いた。
- 旧検査の 3 ディレクトリを除いた木で x86 ビルド、配布物の生成、GF 表の再現、MEMMAP の生成を確認。証拠は `~/os32-tmp/run/restructure/p2-3/tmp/`。
- PowerPC の core・link・sh・link-sh・shell・neg1 の 6 指定でビルド成功。現行の `sys/conf/images/ppc-flags.mk` では sh・shell が link-sh と同じ出力先になる。異なる ELF として採取できたのは 4 種類で、P2-0 の採取対象は、異なる 4 種類の ELF を必須にし、6 指定がどれに当たるかを一覧に書く (PM の判断 2026-11-26 — 6 つの別のファイルは求めない)。
