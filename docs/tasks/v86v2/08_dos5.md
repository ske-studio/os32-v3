**DOS は Ys と正反対のゲストだった。** Ys はハードを直接叩き `INT n` が 0/s
だったが、DOS はほぼ全部を BIOS コールで済ませる。
I/O トラップは 8 回しか出ない代わりに、**BIOS の正確さが全部効く**。

### 到達までに直したもの (§4)

1. ブートデバイス DA/UA を実機の値 (`0x80`) から `0x90` へ
2. `INT 1Bh` SENSE の戻り値と DA/UA 判定を実機に合わせた
3. `INT 1Bh` READ ID (AH=0Ah) を実装 — **DOS はこれでメディアを判定する**
4. `loop_dev` の FDI 経路で `sect==0` / 範囲外を弾いた
5. セクタ長の照合、端数セクタ、64KB 境界、トラック跨ぎを実機に合わせた
6. BIOS ワークエリアを「仮想マシンの構成」として作り直した

**DOS は Ys と正反対のゲストだった。** Ys はハードを直接叩き `INT n` が 0/s
だったが、DOS は逆にほぼ全部を BIOS コールで済ませる。
おかげで I/O トラップは 8 回しか出ない代わりに、**BIOS の正確さが全部効く**。

### BIOS HLE が V86 で成立することの確認

DOS を載せる前提として、NP21/W のホスト側 BIOS エミュレーションが
V86 のゲストに対しても働くかを先に確かめた。

- フックの発火条件は `!CPU_STAT_PM || CPU_STAT_VM86`
  (`i386c/ia32/interface.c:342`)。**V86 は明示的に対象**
- フック点は `0xF8000-0xFFFFF` の `NOP` 実行 (`_NOP()` → `ia32_bioscall()`)。
  ROM 帯を R/O + USER で直マップしてあるので踏める
- ゲストバッファへの読み書きは `MEMR_*` → `memr_read8/write8` が
  `CPU_STAT_PAGING` のとき `physicaladdr()` を通る (`i386c/cpumem.c:1755`)。
  **バッキング RAM にリマップしていても正しい場所に落ちる**
- 物理直アクセス (`mem[]`) は BDA (ページ 0) と TVRAM (`0xA0000`) だけで、
  どちらも実物理を直マップ済み ([04 §4-21](04_implementation_status.md))

## 2. 最初に止まっていた場所 — ブートデバイス DA/UA が実機のまま (`0x80` = SASI HDD)

> 修正前の症状: バナーの直後に「MSDOS.SYS 読み込み時にエラーが発生しました」
> と出て `0060:5BC2` の `jmp $` で停止した。

### 2.1 証拠の連鎖

**(1) DOS の IPL は DA/UA を `0000:0584` から読む。**

```
0094:  a0 84 05     mov  al, [0584]      ; ← MEMB_DISK_BOOT
0097:  24 f0        and  al, f0
00cc:  a8 80        test al, 80
00ce:  74 17        je   00e7
```

**(2) ゲストの `0x584` は `0x80` だった。**

```
emu_read_mem addr=0x580 len=16
  00000580  00 00 00 00 80 00 00 00  ...
                        ^^ MEMB_DISK_BOOT
```

`v86_bios_save_real()` が実機の BDA を丸ごと退避してゲストへ渡している。
OS32 は NHD (ハードディスク) から起動しているので、ここが `0x80` になる。

**(3) `0x80` は FDD ではなくハードディスクである。**

```c
/* np21w-src/src/bios/bios1b.c:1040 */
devtype = (CPU_AL & 0xf0);
switch (devtype) {
    case 0x90:            fdd_operate(3, 0, FALSE);   /* 2HD */
    case 0x30: case 0xb0: fdd_operate(3, 1, FALSE);   /* 2DD */
    case 0x00: case 0x80: sasibios_operate();         /* ← SASI HDD */
}
```

**(4) 実際、最後の 3 回の `INT 1Bh` は SASI 規約で来ている。**

`v86_disklog` 全 22 件のうち末尾:

```
#17 AX=8480 (SENSE)  … AL=80 → SASI
#18 AX=8400 (SENSE)  … AL=00 → SASI
#19 AX=0600 CX=0000 DH=0 DL=0 BX=256 dst=0010bc  → 成功(!) 256B 転送
#20 AX=0600 CX=0002 DH=0 DL=0 BX=256 dst=0010bc  → 成功(!)
#21 AX=0600 CX=0003 DH=0 DL=0 BX=256 dst=0010bc  → 成功(!)
```

FDD 規約で読むと「`CH=0` なので 128B セクタ、`DL=0` なのでセクタ 0」という
**存在し得ない要求**。SASI 規約なら `CX` = 16bit シリンダ (0/2/3)、
`DL` = 0 起算セクタ、256B/セクタ で辻褄が合う。
DOS のブロックデバイスドライバがハードディスクとして初期化を始めている。

**(5) そして OS32 はそれを「成功」として返している。**

`loop_dev_read_chs()` の FDI 経路 (`drivers/loop_dev.c:578`):

```c
offset = s->data_offset
    + (((u32)cyl * heads + head) * spt + (u32)(sect - 1)) * lba_sect_size;
```

`sect = 0` で `(u32)(sect - 1)` が `0xFFFFFFFF` になり、
`× 1024` で桁溢れして `offset` が **`0x00000C00` に回り込む**。
`offset + 1024 > data_offset + data_size` の境界チェックも当然通る。
結果、FAT 領域のゴミを「成功」として返していた。

### 2.2 なぜ前半は動いたのか

IPL と IO.SYS の前半は、DA/UA が `0x80` でも `0x90` でも
**同じ FDD 規約のレジスタで呼ぶ** (IPL の `test al,80` は 2HD でも真)。
今の HLE は `AL` を完全に無視するので、辻褄が合ってしまう。

**偶然動いていただけ**で、DOS のブロックデバイスドライバが
自分で装置種別を判定した瞬間に規約が分かれて破綻する。

> **実機の BDA を丸ごと引き継ぐのは、自分でデバイスを列挙しないゲスト
> (Ys) にだけ正しい。** DOS は BIOS ワークエリアを読んでマシン構成を
> 決めるので、**渡すべきは「実機の状態」ではなく「仮想マシンの構成」**。

## 3. 次に止まった場所 — READ ID (AH=0Ah) 未実装

DA/UA を `0x90` にすると `INT 1Bh` は全部 2HD FDD として来るようになり、
SASI 規約のゴミ読みは消えた。そして**同じ場所で別の理由で止まった**。

```
#16 AX=d690 CL=8 CH=3 DH=0 DL=1 BX=7168  → 成功 (IO.SYS/MSDOS.SYS のロード完了)
#17 AX=0790 (AH=07 RECALIBRATE)          → 成功
#18 AX=0490 (AH=04 SENSE)                → 成功
#19 AX=6a90 (AH=6a → cmd 0x0A = READ ID) → CF=1 / AH=0x86 …を 6 回
```

**MS-DOS はメディアの書式を READ ID で確かめる。**
RECALIBRATE → SENSE → READ ID の順に呼び、返ってきた `N` (セクタ長コード) と
`R` から 2HD (1024B×8) か 2DD (512B×8/9) かを決める。
「機能なし」で返していたので、そこで諦めて同じエラーを出していた。

実機の READ ID は「ヘッドの下を次に通るセクタの ID」を返し、呼ばれるたびに
トラック内を 1 つ進めて末尾で 0 に戻す (`fdc.crcn`)。
D88 はセクタごとに ID を持つので `fdd_readid_d88()` がトラックを走査し、
FDI のような一様な書式は `fdd_readid_common()` が `R = ++crcn` で合成する。

> **「未実装なら CF=1 で返せばゲストは代替手段に進める」は半分しか正しい。**
> 代替手段がある機能ならそうだが、**そこでしか答えが得られない問い合わせ**
> だと、ゲストは代替に進むのではなく諦める。

## 4. 実施した修正

### 4-1. BIOS ワークエリアを「仮想マシンの構成」として作り直す

`kernel/v86_bios.c` `v86_bios_setup()`。作る仮想マシンは
**2HD FDD 1 台 / HDD 無し / 拡張メモリ無し / コンベンショナル 512KB**。

| アドレス | 名前 | 前 (実機の値) | 後 |
|---|---|---|---|
| `0x0501` | `MEMB_BIOS_FLAG1` bit0-2 | 4 (= 640KB) | **3 (= 512KB)** |
| `0x0401` | `MEMB_EXPMMSZ` | 実機の拡張メモリ量 | **0** |
| `0x0584` | `MEMB_DISK_BOOT` | `0x80` (SASI HDD) | **`0x90` (2HD FDD#1)** |
| `0x055C` | `MEMW_DISK_EQUIP` | `0x0103` (2HD×2 + SASI) | **`0x0001`** |
| `0x0482` | `MEMB_DISK_EQUIPS` | 実機の値 | **0** |
| `0x0480` | `MEMB_SYS_TYPE` bit7 (IDE) | 立っている | **落とす** |
| `0x05AE` | `MEMB_F144_SUP` | `0x8F` を書いていた (誤り) | **0** |
| `0x0413` | (PC-98 には無い) | 書いていた (無意味) | **廃止** |

**メモリ量は切り下げること。** PC-98 は 128KB 単位でしか申告できず、
実際に張れるのは 572KB (`V86_REMAP_END = 0x8F000`) までなので 512KB と答える。
640KB と答えると DOS がコンベンショナルメモリ上端に COMMAND.COM を置き、
`0x8F000` 以降 (= OS32 のカーネルスタック帯、USER 無し) に触って `#PF` する。

**この 2 行が CONFIG.SYS 問題も同時に解いた。** §5-1 参照。

### 4-2. `INT 1Bh` を `bios1b.c` に合わせる

`kernel/v86_bios.c`。

| 項目 | 前 | 後 |
|---|---|---|
| `AL` (DA/UA) | 完全に無視。どの装置にも「レディ」と答える | 2HD ユニット 0 以外は `AH=0x60`。初期化 (03) だけは実機同様に素通し |
| SENSE (04) の戻り | 常に `0x00` | `0x01` (2HD) / `0x08` (1MB・640KB 両用) を組み立てる |
| **READ ID (0A)** | 未実装 | **実装**。D88 はトラック走査、FDI は物理位置から合成 |
| VERIFY (01) | 未実装 (定数も `0x02` と取り違え) | 転送しない READ として実装 |
| 診断リード (02) | 未実装 | READ と同じ扱い (実機も同じ `case`) |
| 端数セクタ | `while (count >= seclen)` で捨てて成功 | `min(count, seclen)` で最後まで転送 |
| 転送しきれない | 起こらない (捨てていた) | `AH=0xC0` / CF=1 |
| 64KB 境界跨ぎ | チェック無し | `AH=0x20` / CF=1 |
| トラック跨ぎ | ヘッドもシリンダも自由に繰り上げ | `AH bit7` かつ物理ヘッド 0 のときだけ裏面へ。**シリンダは跨がない** |
| セクタ長 (RAW/FDI) | ゲストの `N` を見ない | イメージの `bps` と一致しなければセクタ不在。**`secbuf` 溢れも同時に塞がる** |
| `BX=0` | パラメータ異常 | 何もせず成功 (実機と同じ) |

### 4-3. `loop_dev` の CHS 検証

`drivers/loop_dev.c` に `raw_chs_ok()` を追加し、FDI/HDI/RAW の
読み書き両方の入口で `sect==0` / 範囲外シリンダ・ヘッド・セクタを弾く。

READ ID 用に `loop_dev_track_id_d88()` を追加 (D88 の物理トラック上の
index 番目のセクタ ID を返す。`fdd_readid_d88()` と同じ走査)。

## 5. 残っている障害

### 5-1. CONFIG.SYS の HIMEM / EMM386 — **実害なしだった**

調査時は「原理的に載らない」と書いたが、**実際に走らせたら両方とも
自分で状況を検出して降りた**。

```
HIMEM: XMSドライバ Ver.2.60
  エラー: 使用可能な拡張メモリがありません.
          XMSドライバは使用できません

ＥＭＭ３８６ドライバ
  ＥＭＭ３８６は使用できません
  　プロテクトモードソフトウェアが既に動作しています

HMA が有効ではありません : 下位に DOS をロードします.
```

- HIMEM は拡張メモリ量 (`0x0401` = 0) を見て、プロテクトモードに
  入る前に諦める → §4-1 の「拡張メモリ無し」が効いている
- EMM386 は `SMSW` 等で**すでにプロテクトモードだと気づいて降りる**。
  V86 モニタの上で V86 モニタを動かそうとはしない
- DOS は HMA を諦めて下位にロードされる

つまり `DOS=HIGH,UMB` 付きの実ディスクをそのまま挿しても動く。
**「無理そうな構成」も実際に走らせるまで決めつけないこと。**

ただし A20 (`0xF2`) は依然として拒否ポートのままで、
XMS を本当に使うプログラムは動かない。

### 5-2. ゲスト RAM 512KB (実際に張れるのは 572KB)

`V86_REMAP_END = 0x8F000` の上は OS32 のカーネルスタック
(`0x90000-0x9FFFF`、USER 無し) なので渡せない。
128KB 単位の申告制約で切り下げるため、**実質 60KB を捨てている**。

`dir` の表示で空きは 158,720 バイト。DOS 5 を下位にロードした状態では
これで足りているが、大きなアプリを動かすならカーネルスタックを
1MB 以上へ退避して `0x00000-0x9FFFF` を丸ごと渡すのが筋
([04 §4-1](04_implementation_status.md) の不変条件は
「スタックが低位に居る限り」という前提付き)。

### 5-3. `INT 1Bh` WRITE / FORMAT / 密度設定が未実装

書き込み系が全部未実装なので、**ファイルを保存できない**。
`FORMAT.EXE` / `SYS.EXE` / `DISKCOPY.EXE` も当然動かない。
`loop_dev_write_chs()` は既にあるので、READ と同じ形で載せられる。

### 5-4. 脱出ホットキーが効かないことがある

実測 (DOS セッション):

| 操作 | 結果 |
|---|---|
| `CTRL+STOP` | **効かない** (2 回試行) |
| `CTRL+GRPH+DEL` | 効く |

Ys のセッションではどちらも効かず、5 分の `V86_TICK_LIMIT` で終了した
(`v86_boot_reason = 4`)。そのとき `v86_kbd_n_push=8 / n_read=0 / n_drop=8` で、
**ゲストが仮想 8251 を一度も読んでおらず FIFO が溢れていた**
(Ys は NP21/W のホスト側 BIOS が page 0 に書くキー入力状態テーブルを
見ているので、ポートを読む必要がない)。
`CTRL+STOP` は PC-98 では BIOS/エミュレータ側で特別扱いされる可能性があり、
**OS32 の ISR までスキャンコードが届いていないことが疑わしい**。要調査。

### 5-5. セッション 5 分上限 / PIT ch0 未仮想化

- `V86_TICK_LIMIT` = 5 分。対話シェルには上限そのものが邪魔
- ゲストが `OUT 71h` で設定する周期は破棄され、OS32 の 100Hz が見える。
  DOS の時計がずれる ([04 §7-2](04_implementation_status.md) の残項目 3b)

### 5-6. ドライブは 1 台だけ

`loop_dev` スロットは 1 つ、DA/UA も `0x90` 固定。B: ドライブは無い。
複数イメージを挿せるようにするなら、DA/UA → スロットの表が要る。

## 7. 再現手順

```bash
# ホスト側 (WSL)
cp /mnt/c/os32/dos5_1.fdi /mnt/c/os32/dos5.fdi   # emu_key はアンダースコアを打てない

# ゲスト側
v86 -b /host/dos5.fdi
# → バナー → HIMEM/EMM386 が自分で降りる → 日付/時刻 (ENTER で既定) → A>
# → CTRL+GRPH+DEL でシェルへ戻る (CTRL+STOP は効かないことがある: §5-4)

# ホストから (セッション中に読むこと。teardown で消える)
emu_read_mem addr=v86_disklog_w  len=4      # 呼び出し件数
emu_read_mem addr=v86_disklog    len=704    # 呼び出し列 (1 件 8 ワード)
emu_read_mem addr=v86_iolog_w    len=4
emu_read_mem addr=0x580          len=16     # MEMB_DISK_BOOT
emu_read_mem addr=0x500          len=8      # MEMB_BIOS_FLAG1 (メモリ量)
emu_read_mem addr=0x55c          len=8      # MEMW_DISK_EQUIP
```

イメージの中身を調べるとき:

```python
# FDI = 4096B ヘッダ + RAW。BPB は先頭セクタ
d = open('/mnt/c/os32/dos5_1.fdi','rb').read()[4096:]
# bps=1024 spc=1 rsv=1 nfat=2 nroot=192 tot=1232 media=0xfe spf=2 spt=8 heads=2
# データ領域 = (1 + 2*2 + 6) セクタ目から。クラスタ N のオフセット = (11+N-2)*1024
```

IO.SYS はクラスタ 2 (イメージ +0x2C00) から 64KB。
ゲストの `CS=0x0060` はこの先頭なので、**イメージから切り出して
`objdump -b binary -m i8086` にかければゲストの停止位置がそのまま読める**。
