## 進め方 (ソースの配置の整理と同じ形)

1. **調べ (sol、読み取りだけ)**: 設計書の節ごとに、どのソースファイルのことか (関数名・ファイル名・file:line の引用から) を対応付ける。ソースに当たらない節 (経緯・決裁・未決・受入の記録) も分類する。
2. **計画書 (PM)**: 節 → `docs/design/<ソースのパス>.md` の対応表。複数のファイルにまたがる取り決めは共通部分 (ヘッダ・共通の .c) の設計書へ、ほかはそこを参照。ソースに当たらない節は票か HISTORY へ。
3. **写す (terra)**: 中身は書き換えず節を切り出して写す。リンクの追従、文書の検査 (links・orphans・status・tree)。
4. **確かめ**: 元の文書の節が全部どこかに写ったこと (抜け落ち 0) を数で示す。元の文書はアーカイブへ (決裁の経緯の記録として残す)。

## D0 で決まった形 (D1 以降もこれで)

- 調べは sol と astra に同じ条件で出して比べ、行き先の和集合を採る (片方の見落としを拾う)。
- **計画の時制の文は設計書に入れない** (目標の行数・見込み・仮置き・未実測・「P? で〜する」・旧い所在・担当)。行番号つきで書き出し、元の票の記録の節へ (文は書き換えず行き先だけを変える)。
- 文は書き換えない。整理で動いたファイルのパスと、もう無いファイルへの参照だけ今の置き場に直す。食い違いは `> [要確認]` の 1 行と票。
- 設計書の頭は題・状態行 (出所)・ソースの 3 行。README はディレクトリの横断の決まりと下向きの索引だけ。個別の設計書から上向きのリンクは張らない (相互リンクを増やさない)。
- 写しはディレクトリごとに terra を並列 (1 担当 = 自分の設計書と自分の書き出しファイルだけ)、仕上げ (入口・票・参照・アーカイブ・確かめ) は 1 本。
