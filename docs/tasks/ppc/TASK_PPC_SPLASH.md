## 1. 題目 (設計の入力)

- **流れ**: 前半 = ユーザーの絵 (90 年代のデスクトップ風) → 「あれ？」= ビッグエンディアンにかけて画面のバイトが一斉に入れ替わり崩れる → 崩れた中から Open Firmware 風に、実際に読んだ device tree の名前が流れる (本物の起動情報) → 4 本の帯でロゴを描く (AltiVec の 4 レーンの見せ方だけ、描画は整数) → 銀のグラデーションに半透明の OS32 ロゴ (QuickSilver の素材感)。
- **時間**: 合計 5〜10 秒。演出は初期化の待ちに重ね、演出のためだけに待つのは最後のフェード 0.5〜1 秒程度。速すぎるときの最低表示時間は設定で。
- **守ること**: Apple のロゴ・Happy Mac・Chicago などの書体・Mac OS のメニューバーや Aqua の意匠・起動音を写さない (特定製品の見た目の再現にしない)。起動音を入れるなら OS32 独自の和音。
- **技術の注意**: 描く先は OF の FB (8bpp か 32bpp かは OF 次第、8bpp なら減色)。今の PPC の arch_copy は byte のループで、PCI の VRAM への全画面 1 枚に 0.2〜0.3 秒かかる見込み (概算)。書き換えをロゴの周りの dirty 矩形に絞るか、copy の幅の直し (A2: lhz/sth・lwz/stw、copy の中で byteswap しない、AltiVec はユーザー確認、G4 で測る) をスプラッシュの前に置くかを設計で決める。
- **絵の受け取りの仕様** (形式・解像度・色数・8bpp/32bpp への合わせ方・置き場とビルドへの組み込み) は設計で決め、本線の PM 経由でユーザーへ伝える。それまでの目安は 640×480 か 800×600、256 色の PNG (確定ではない)。1448×1086 はほぼ 4:3 で、どちらへ縮めても比率は崩れない。
