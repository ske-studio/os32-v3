## 1. 今の 480 ラインへの入り方 (`pegc_init`)

1. `09A8h` ← 31kHz
2. 両 GDC へ SYNC (8 バイト) — 値は `include/pegc.h` の `PEGC_GDC_MSYNC_480` / `SSYNC_480`
3. グラフィック GDC に SCROLL、START
4. `6Ah` ← 69h (800 ライン構成)、21h (拡張グラフィック)

**SYNC の値の出所は NP21/W の `bios/bios18.c`** (エミュレータが INT 18h AH=30h で流す値)。
実機の ROM と同じかは**一度も確かめていない**。uPD7220 の SYNC は書き込み専用で、BIOS ワーク
エリアにも写しが無いので、**読み戻して比べる手段が無い** (`include/pegc.h` の注記)。
NP21/W は同期のタイミングを模擬しないので、値が違っていてもエミュレータでは正しく映る。

## 2. 仮説 (確からしい順)

| # | 仮説 | 根拠 | 見分け方 |

| H1 | **SYNC の値が実機の ROM と違う** (水平の総幅・帰線区間 — P2〜P5 — がずれていると、液晶は別の画素クロックで取り込み、横にずれる) | 値はエミュレータ由来。pc98 (BIOS の作った同期のまま) は正しい | §3 段 1 で ROM の値を取れば決着 |

### 段 1 — 実機の ROM が流す値を記録する (`v86 -g`、新規)

> **実装済み (2026-09-26、KAPI v68 `v86_gdc_capture`、手元ビルドとホスト試験のみ)**。実体は `kernel/v86_gcap.c`
> (段取り・差し込み口・CUI の作り直し)、`kernel/v86_gcap_math.c` (記録・通すポート・打ち切る命令・並びの判定。
> `make check-v86-gcap-host` が実物のまま回す)、`kernel/v86_test16_gcap.asm` (ゲスト)、`userland/cmds/v86.c` (`-g` / `-g -t`)。
> 下の表の 4 つと引数の食い違いへの答え:
>
> - **記録**: 捕まえた OUT を畳まずに 512 件 (`seq` / ポート / 幅 / 値 / CS:IP / 実機へ通したか / フェーズ)。`seq` は IN も数える
>   通し番号 (飛び = その間の IN の数)。IN はポートごとの回数・最初と最後の値 (GDC の FIFO / VSYNC 待ちのポーリングで数が読めないため)。
>   溢れたら `V86G_ST_OVERFLOW` で列は出さない (実機へは通し続ける — ROM の切り替えを途中で崩さない)。
> - **通すポート**: 表の 09A8h・6Ah・68h・60h/62h・A0h/A2h・A4h/A6h に、**09A0h** (PEGC のモード読み戻し — 通さないと ROM が
>   0xFF の偽の値で分岐しうる)・**64h / 6Ch / 6Eh** (テキスト GDC 帯の残り)・**70h〜7Ah の偶数** (テキスト CRTC — H5 の手掛かり)
>   を足した。どれも通常の V86 で素通しにしているポートか 09A0h / 09A8h。それ以外で捕まえたポートは通常の仮想化のまま
>   記録だけする (`emu`)。ゲストの PIC は全部塞いで始める (実 IRQ を ROM のハンドラへ反射すると EOI 等が混ざる)。
>   **通常の V86 の許可リストで素通しのまま捕まえないポート — GRCG 7Ch・7Eh、EGC 4A0h〜4AFh、I/O ウェイト 5Fh、パレット
>   A8h〜AEh、FM 188h〜18Fh、37h、20h — は実機へ届くが記録には出ない** (ROM がここを触っても列に現れない)。
> - **幅**: 16 ビットの IN/OUT は `inpw` / `outpw` で通す。INS/OUTS (6Ch〜6Fh) と 66h 付きの IN/OUT EAX は #GP ハンドラの
>   入口で打ち切る (`V86G_ST_ABORT`、場所を記録)。66h 付きでも AL の IN/OUT は 8 ビットなので通す。
> - **開始・終了**: `v86_io.c` の方針が `v86_gcap_active()` を見て、開始で画面・音源を触らず、終了で 400 ライン・16 色へ
>   戻さない。① AH=31h (AL/BH に印 FFh) → ② 判定 → ③ AH=30h 480 → ④ AH=30h で ① のモード → ⑤ CUI の作り直し
>   (グラフィック GDC 停止・表示可・テキスト GDC 開始 — NP21/W の AH=30h はテキストの STOP を出す — ・テキスト VRAM 30 行を
>   採取前へ・カーソル形状)。480 ライン表示中 (PEGC の GUI・全画面アプリ) は `OS32_ERR_BUSY` で断る。
> - **④ を呼ぶか・戻し方** (代行レビュー P2-2 で直した): ③ が**最後まで走って AH≠05h** (ROM が引数を断った = 無変化) なら
>   ④ は呼ばず `restore = NONE`・`V86G_ST_REJECTED`。③ が 05h を返したか、③ が途中で終わった (打ち切り・暴走・時間切れ —
>   何を変えたか分からない) ときだけ ④ を呼ぶ。④ が最後まで走って 05h なら `ROM`、そうでなければ `FALLBACK` =
>   `pegc_restore_text_sync` で ① の周波数 (24kHz 固定にしない) の 400 ラインへ。判定は `v86g_need_restore` /
>   `v86g_restore_kind` (ホスト試験)。**FALLBACK が戻すのは同期だけ** — 09A8h・両 GDC の SYNC と SCROLL・6Ah (拡張モード
>   を抜ける / 400 ライン構成。PEGC の probe が通った機種だけ)・グラフィック GDC の STOP。**テキスト CRTC (70h〜7Ah) と
>   テキスト GDC の PITCH / CSRFORM は戻さない** (ROM が 480 用に変えたままなら文字の並びがずれうる。そのときはリセット)。
> - **時間の見切り** (代行レビュー P2-1 で直した): ROM の 1 呼び出しは 3 秒 (`GCAP_TICK_LIMIT` = 300 tick)。IOPL=3 では
>   ゲストの IF = 実 IF なので、IF を落としたまま ROM へ入るとタイマ IRQ が来ず、見切りも脱出ホットキー (CTRL+GRPH+DEL) も
>   効かなかった。いまは ROM の呼び出しを IF を立てて始め、ゲストの INT n でも IF を落とさない (`v86_gcap_keep_if`)。
>   ゲストの PIC は全部塞いであるので、実 IRQ は OS32 の ISR へ行くだけでゲストへは反射しない。**ROM が自分で CLI したまま
>   回ったときだけ**は見切りもホットキーも効かず、#GP の番犬 (5 万回) 頼み — I/O を伴わない待ちならリセットしかない。
>   自己試験 `st_hang` が「IF を立てて INT で入り、I/O も #GP も出さずに回るゲスト」を 0.3 秒で見切れることを確かめる。
>   **IF=1 の代償**: ROM の VSYNC エッジ待ちを OS32 の ISR が跨ぐと 1 フレーム遅れる。ROM が待ち回数に上限を持つ作りなら早期に諦めて AH≠05h を返しうる — その場合は `V86G_ST_REJECTED` で無変化 (④ を呼ばない)。
> - **引数の判定**: 予約 bit が 0・30 行は 480 だけ・480 は 31kHz だけ、を満たす並びが**ちょうど 1 つ**のときだけ決める。
>   **「今は 400 ライン」は決め手にしなかった** — NP21/W の AH=31h は解像度を 0000:0597h bit1-0 から返し、そこは AH=42h / 30h を
>   誰かが呼ぶまで 0 (200 LOWER) のままで、OS32 の起動では誰も呼ばない (実機の ROM も同じ作りかもしれない)。両方の並びで正しいのは
>   `AL=08h BH=00h` だけで、それは決めない (`V86G_ST_UNDECIDED`、30h を呼ばず値を出す)。印のままなら `V86G_ST_NO31`。
>   並びを取り違えても戻しの AH=30h は AH=31h の値をそのまま渡す (ROM 自身の並び) ので、元のモードへの戻りは判定に依らない。
>   **30 行を採った**: bit2 並びは `AL=0Ch BH=32h` (上の表の `31h` は 25 行 — OS32 の PEGC は 30 行で、`PEGC_GDC_MSYNC_480` は
>   NP21/W の「31-480:30」の値)、bit3 並びは表どおり `AL=08h BH=16h`。
> - **KAPI**: 増やした (v68、slot 239)。既存の v86 の入口 (`v86_selftest` / `v86_disktest` / `v86_boot` / `v86_boot2`) は
>   どれも引数の意味が決まっていて、記録を CPL=3 へ返す口も無い。既存スロットの意味を変えるのは ABI を壊すのと同じ
>   (スキル os32-kapi-add)。
> - **事前試験 (B4)**: `v86 -g -t` が決まった I/O 列の試験ゲストで列・順序・幅・IN の表・溢れ (513 回)・OUTSB と
>   66h EFh での打ち切りを確かめる (捕まえたポートは実機へ通さない)。NP21/W の ROM での `v86 -g` の件数は構成次第。

OS32 には V86 の監視部があり、INT 18h は HLE ではなく**起動時に保存した実機の割り込みベクタへ反射する**経路がある
(`kernel/v86_bios.c:246`、`kernel/v86.c:298`)。I/O 許可ビットマップでポートを選んで #GP で捕まえる仕組みもある
(`kernel/v86_io.c`)。これで**実機の ROM の INT 18h** を V86 で呼び、その間の OUT を記録する。ただし既存の部品のままでは
足りないところが 4 つある (Codex 1 回目 B2・B3・B5):

| 足りないもの | 今 | 段 1 で足すもの |
|---|---|---|
| 記録の形 | `iolog` は 64 件の循環で、直近 8 件に同じ port/value/CS:IP があれば**回数へ畳む** (`v86_io.c:43`)。SYNC のパラメータ列の順序が消える | **診断専用の畳まない OUT 列** (512 件、`seq / port / 幅 / 値 / CS:IP`)。溢れたら**採取失敗**として結果を出さない |
| 09A8h | 観測リストに無い (`v86_io.c:314`)。IN はダミー値、OUT は捨てる | 採取中だけ 09A8h・6Ah・68h・60h/62h・A0h/A2h・A4h/A6h を**実機へ通して記録** |
| 幅 | 中継は `size` に関係なく 8 ビットの `inp/outp` (`v86_io.c:390`) | 16 ビットの IN/OUT は 16 ビットで通す。**INS/OUTS は未対応 (`v86.c:323`)、66h 付きの 32 ビット IN/OUT も今は幅 2 で処理している (`v86.c:292`) ので、どちらも来たら採取を打ち切って失敗を出す** (黙って 16 ビットにしない) |
| 開始・終了 | 通常の V86 の開始は画面の状態を変え、終了は 400 ライン等へ戻す (`v86_io.c:350`)。今回の同期の状態は戻らない | **診断専用の開始・終了**。開始前に AH=31h で今のモードを読んで保存し、終わったら AH=30h でそのモードへ戻し、最後に OS32 の CUI の画面を作り直す (`pegc_shutdown` が起動時の 24/31kHz へ戻すのと同じ考え — **24kHz 固定では戻さない**、CUI のずれが再発する)。途中で失敗しても同じ戻し方を通る |

**AH=30h の引数は資料と実装で食い違っている** (Codex 1 回目 B1):

| 出典 | 640x480 / 31kHz | 640x400 / 24kHz |
|---|---|---|
| Bible 3-2 (ローカルのミラー) | AL の D3 = 31kHz、BH の D2D1 = 11 (480)、D4D3 = 行数 → `AL=08h, BH=16h` | `AL=00h, BH=0Ch` |
| NP21/W `bios/bios18.c:345` の検査 | `AL & F8h == 08h` が必須、AL の **bit2** = 31kHz、BH の **bit4-5 = 30h** で 480、bit0-1 = 行数 → `AL=0Ch, BH=31h` | `AL=08h, BH=21h` 前後 |

Bible の値は NP21/W では拒否される (`AH≠05h`)。どちらが実機の ROM に合うかは分からない — **NP21/W の値を実機の仕様とみなさない**。
段 1 では**まず AH=31h で実機の今のモードを読み**、その値の bit の並びから 30h の引数を決める (起動時の 400 ライン / 24kHz が
どう表されるかで、どちらの並びかが分かる)。AH=30h の戻り値 AH が 05h でなければ何も記録せずに戻す。

**事前試験** (Codex 1 回目 B4): NP21/W の AH=30h は SYNC を GDC の内部状態へ直接書く (`bios18.c:444`、09A8h も内部フラグ
`bios18.c:435`) ので、**エミュレータでは SYNC などの完全な列は採れない**。ただし BIOS の I/O エミュレーションが有効な構成では
PITCH (`bios18.c:464`) や 6Ah・62h (`bios18.c:505`) の OUT をゲストの OUT として実行する (`bios.c:901`) ので、**記録される件数は構成次第** — 0 件を正解にしない。記録器の試験は、決まった OUT 列を出す小さな
16 ビットの試験ゲスト (`kernel/v86_test16.asm` の流儀) で行い、列・順序・幅・溢れの扱いを確かめる。実機の ROM の採取とは分ける。

CPL0 で動く管理者用の診断 (`v86 -g`) として足す。KAPI を増やすかは実装時に決める (既存の v86 の入口で足りるなら増やさない)。
実機の回で `v86 -g` を 1 回走らせれば、H1・H2・H5 (PITCH・GDC クロック) が**数値で**決まる。

### 段 1 の NP21/W での記録 (2026-09-26、a173cb7)

`v86 -g` (NP21/W の BIOS、HLE と BIOS の I/O エミュレーションが出す分だけ):

```
R 31h      : AX=3108 BX=0100  layout=bit2 (NP21/W bios18.c order)
R 30h 480  : AX=300c BX=3200 -> AX=0500
R 30h back : AX=3008 BX=0100 -> AX=0500 (ROM)
O s480 00a2 0047 / 00a0 0050   ← グラフィック GDC の PITCH = 80
O s480 006a 0040 / 006a 0083   ← 6Ah 83h = GDC CLOCK-1 5MHz
O s480 0062 000c               ← テキスト GDC 0Ch
O back 006a 0068 / 00a2 0047 / 00a0 0028 / 006a 0040 / 006a 0082 / 0062 000c   ← PITCH 40、2.5MHz へ戻す
```

**H5 の裏付け**: BIOS は 480 ラインへ入るとき **PITCH を 80、GDC クロックを 5MHz** にする。OS32 の `pegc_init` はどちらも設定していない
(PITCH は既定 40 + クロック状態で実効 640 バイトという前提、`include/pegc.h:254`)。NP21/W は PITCH・クロックの違いでは画面がずれないので
表に出ないが、実機でずれる候補として最有力。SYNC の 8 バイトは NP21/W では内部状態へ直接書かれるので記録に出ない — 実機の記録で確かめる。

### 段 1 の実機での記録 (2026-09-29、44bd0fe、PC-9821Ra266)

```
v86 -g -t : OK
v86 -g    : R result : AH=31h value not recognized (status=2)
            R 31h    : AX=310d BX=0100 layout=-
            O 行 0 件 (30h まで進んでいない)
```

- **AL=0Dh は NP21/W の bit2 並び (bit3 常に 1、bit2 = 31kHz — NP21/W は AX=3108h) に bit0 が足された形**。BH=01h は
  NP21/W と同じ。`kernel/v86_gcap_math.c` の並びの判定が bit0 を予約 bit として弾いていた (`(al & FBh) == 08h`)。
  - 出典: [US] memsys.md 0000:0459h (990〜1007 行付近)「bit 3 — 対象 PC-98GS, PC-9821(ノーマル), PC-9801BA2･BS2･BX2 —
    ラスタスキャンモード (1 = ノンインターレース / 0 = インターレース)。**INT 18h - Function 30h,31h のモード設定情報
    bit 0。BIOS とは値の意味が逆転している**」。同 0459h bit0 (1030〜1045 行) は「CRT 解像度 480 ラインフラグ —
    INT 18h Function 30h で 640x480 に設定したとき 1」。
  - 直し (wt/pegc480-prep): 両方の並びで AL bit0 を許し、30h へ渡す AL に bit0 を保つ (ROM の値を勝手に落とさない)。
    戻しは従来どおり 31h の値そのまま。ホスト試験に実機の値 (AX=310Dh BX=0100h → 30h へ AL=0Dh BH=32h) と変異 5 本
    (`tools/tests/v86_gcap_tdd.md`)。KAPI は変えていない。**次の実機の回で `v86 -g` をやり直す**。
- **実機の CUI は起動時から 31kHz** — boot.log `[pegc] hsync=31k 09a8=81`、液晶の OSD は 720x400 H31.5kHz V70.2Hz、
  31h の AL bit2 = 1。NP21/W の CUI は 24kHz。`pegc_shutdown` / `pegc_restore_text_sync` は 2026-09-24 から起動時の
  09A8h (D0) へ戻す作りで、31kHz の 400 ラインの SYNC (`PEGC_GDC_MSYNC_400_31K` と起動時クロック別の `PEGC_GDC_SSYNC_400_31K_*` — これも NP21/W 由来) を使う。
  「CUI = 24kHz」を前提にしているのは起動時の 09A8h が読めなかったときの既定だけ (PEGC の probe が通った機種では来ない)。
- **09A8h の読みは 81h (bit7 = 1)**。[U] io_disp.md I/O 09A8h (1870〜1895 行): bit1,0 = 周波数 (01b = 31.47kHz、
  00b = 24.83kHz、10b/11b 設定禁止)、**bit7〜2 は「未使用 (常に 0 にする)」**、解説に「PC-9821Bp･Bs･Be･Bf･Xt･Xa･Xn･Xp･
  Xs･Xe, PC-9801BA2･BS2･BX2･BA3･BX3･BX4 ではプログラマブル PLL シンセサイザ (ドットクロック) のアクセスにもこの I/O
  09A8h を使うが、通常はマスクされているので設定できない」「周波数を切り替えたら GDC の SYNC コマンド等で同期信号を
  設定しなおさないと正常に表示が行われない」。Ra266 は機種表に無く、bit7 の意味は資料に無い。
  → **書くときは bit1,0 だけ (bit7〜2 は 0)、読み値は書き戻さない** (`include/pegc.h` §3、試験 `hsync_bits`)。
- **GDC クロック**: [B] 3-2 表3-2「84H = GDC 2.5MHz モード」「**83H と 85H = GDC 5MHz モード。5MHz にするには 83H と
  85H を両方出力する。周波数を変更したら SYNC コマンドの再設定が必要**」。[U] io_disp.md I/O 006Ah「1000001nb:
  GDC CLOCK-1 (82h/83h)」「1000010nb: GDC CLOCK-2 (84h/85h)」— 5MHz には両方、2.5MHz にはどちらか一方。
  [US] memsys.md 0000:054Dh bit2「640x480 / 31.47kHz / 拡張 → 5.0MHz 固定」、400 ラインは「054Dh bit5 (DIP SW 2-8)
  に従う」。NP21/W の記録に 83h しか無いのは、NP21/W の BIOS が CLOCK-2 を内部状態へ直接立てる (`gdc.clock |= 3`)
  から。→ OS32 は **83h と 85h を両方、SYNC の前に**出す。
- [U] io_disp.md 455〜470 行: 6Ah 68h/69h の VRAM 構成 (800 ライン構成が 480 ラインモードの既定)。同 106 行付近:
  INT 18h 30h の後は VSYNC 割り込みが止まるので 0064h へ書いて再開が要る (ROM の 30h を呼ぶ `v86 -g` の後始末の候補。
  今の `v86 -g` は OS32 の CUI を作り直すだけで 0064h は書かない — 未確認)。

### 段 2 の下準備 (2026-09-29、wt/pegc480-prep — 実機の記録を待たずに先に作った部分)

  クロックから [B] 2-7 の「通常」(両方 5MHz なら 80、それ以外 40) を選ぶ。probe が通っていない (記録が無い) ときは

#### 原因の結論 (事実として言えること)

- **H1 (SYNC の値) は否定**。480 の 2 組・31kHz 400 (2.5MHz) の 2 組の計 32 バイトが NP21/W 由来の OS32 の値と完全に一致した (表の 10・12・back)。
- **H5 のうち PITCH・GDC クロックは否定** (d5cd3a5 で既に 80 / 83h・85h を出していて、実機の値と同じ)。
- 残った違いは **順序 (H2) と、OS32 が出していなかったコマンド・値** — 実機の液晶で崩れた原因はこのどれか (どれかは実機でしか分からない):
  1. **グラフィック CSRFORM L/R** (表 13): OS32 は書かず、起動時の BIOS の値に頼っていた。ROM は 480 へ入るとき必ず L/R = 0 を入れる。
     back で ROM が 68h 09h (200 ライン扱い) を戻すことから、Ra266 の BIOS は起動時にグラフィックを 200 ライン扱いにしている —
     そのとき L/R = 1 なら 1 ライン目ごとに 2 ラスタ = 行が崩れる。**NP21/W の 256 色表示は L/R を見ない**
     (vram/makegrex.c) ので、エミュレータでは出ない。
  2. **SCROLL の LEN** (表 16): OS32 は LEN = 0、ROM は 3FFh。NP21/W は LEN = 0 を「無制限」に読むので出ない。uPD7220 の実機が
     LEN = 0 をどう扱うかは資料に無い。
  3. **RESET / MASTER・SLAVE を出さずに SYNC だけを書き換えていた** (表 9・14)、**表示を止めずに切り替えていた** (表 4)、
     **テキスト GDC の PITCH・SCROLL・CRTC・6Eh を 480 用に入れ直していなかった** (表 11・17・22・23)。
  4. **09A8h を毎回書いていた** (表 5): 起動時の読み 81h の bit7 を 0 にする。bit7 の意味は資料に無い
     ([U] 09A8h「bit7〜2 未使用 (常に 0)」、PLL を持つ機種の注記に Ra266 は無い)。ROM は 31kHz のままなら書かない。
     以前の CUI の桁ずれ (TASK_FDC_REALHW §9-1) も 09A8h を書いていた経路で出て、書かなくして消えた。
- 6Ah 41h (表 2) は [U] が「拡張グラフィックスモードでは必ずプラズマディスプレイモード」と書くので、出さなくても同じはず。
  ROM に合わせて出す。

| VSYNC 待ち | ROM は群の間で 60h を 1500〜5800 回 (約 1 フレーム) 読み、最後の読みは VSYNC が落ちた値 (45h) → 「VSYNC が来て明けるまで」と読んだ (ROM は逆アセンブルしていない — 推定)。OS32 は同じ 7 か所で待ち、1 辺 50ms で打ち切って `pegc_vsync_timeouts` を数える |
| 記録の無い組 | 起動時 24kHz (資料 [B] 表2-27)・起動時 5MHz の戻り (NP21/W 31-M、IM は [B] 2-7)・PEGC の probe が通らない機種 (6Ah・6Eh・クロックに触らない — 6Eh は古い 9801 では周波数切換) |

#### (A) が比較する区間

ホスト試験 `rom_s480` / `rom_back` が ROM の記録と 1 行ずつ比べるのは次の区間の OUT 全部 (5Fh だけは除き、6Eh の直後にあることを別に見る):

- **入る**: `pegc_enter_480_ports()` の頭から終わりまで (= `pegc_init` のポート操作。この後の MMIO (E0100h・E0102h)・リニア窓・VRAM
  クリア・パレット (A8h〜AEh) は比べない — ROM の AH=30h はパレットに触らず、記録器は A8h〜AEh を捕まえない)。
- **戻る**: `pegc_text_sync_400()` の頭から終わりまで (= `pegc_shutdown` のポート操作)。CUI なら末尾のカーソル復帰 (console.c の実物) を含む。
  v86 -g の FALLBACK の口 `pegc_restore_text_sync()` は、先頭の 09A0h 0Ah の選択と読み (拡張モードか) を除いて同じ列。
- **比べないもの**: 起動時の記録 (`pegc_boot_sync_record` — 09A8h の読み、09A0h 09h の選択と読み)、診断 (`pegc_diag_take` —
  480 へ入った直後と戻った後の 09A0h 02h/03h/05h/09h/0Ah/0Dh の選択と読み、09A8h の読み)。どれも 09A0h への選択の書き込みと
  読みだけで、表示の状態は変えない ([U] io_disp.md I/O 09A0h)。

## 4. 段 1 と独立にできる小さな修正 — `gdc_send` が FIFO を待つ

> **実装済み (2026-09-29、wt/pegc480-prep)**: コマンドの前は FIFO EMPTY (bit2)、パラメータの前は FIFO FULL (bit1) で
> ないことをステータス (60h / A0h) で見てから書く。満たなければ `cpu_delay_us(2)` を挟んで読み直し、5000 回
> (1 バイトあたり 10ms) で諦めて書き、`pegc_gdc_fifo_timeouts` (kernel.map から読めるグローバル) を数える。
> START / STOP も同じ口を通す。値は `include/pegc.h` §12。NP21/W はステータスを読むと FIFO を処理するので 1〜2 回で抜ける。

`gfx/backend_pegc.c` の `gdc_send` はコマンドとパラメータを待たずに流している。
uPD7220 のステータス (60h / A0h の READ) の FIFO FULL が落ちるのを待ってから 1 バイトずつ
書く形にする (上限つき、上限を超えたら数えて先へ)。NP21/W では常に空なので回帰はしない。
これ単独で直るかは実機でしか分からないが、害は無い。**段 0 と同じ実機の回に入れる**候補。
