## 0. なぜやるか

**従来の FD は PC-98 標準の 2HD 1232KB (1024B/セクタ) だけだった。**
これは現代の PC では書けない。実機へ運ぶ手段として 1.44MB が欲しい
(ユーザー指示、2026-09-18)。

**既存の 1232KB を置き換えるのではなく、両方を持つ。** 既定は 2HD のまま。

## 1. 資料が言っていること (読んだ記述のみ)

| 事実 | 出典 |
|---|---|
| DA/UA **`30H〜33H`** = 1.44MB 対応両用インタフェースのアクセスモード (`90H〜93H` が従来の 1MB I/F) | `docs/hw/PC9800Bible/2-9_ディスク.md` 表 2-34 (ローカルミラー、git 管理外) |
| INT 1Bh の主要機能 (01H〜10H) は 1.44MB でも ○ | 同 §INT 1Bh 機能一覧 |
| `0000:0584h DISK_BOOT` (起動したディスクの DA/UA) に **`30〜33h` = 1.44MB メディア**が載る → **BIOS の想定内** | `../../hw/undocumented/memsys.md` |
| **`I/O 04BEh` = 3モードFD I/F 制御** (Undocumented)。WRITE: bit6,5=ドライブ / bit4=1 でモード変更有効 / bit0=1 で 1.44MB。READ: bit4=1.44MB 可 / bit0=現在のモード | `../../hw/undocumented/io_fdd.md` |
| 1.44MB アクセスは **1MB I/F モードのときだけ**可能 | 同 |
| **リードの前に必ずライトしてドライブを指定する** | 同 (解説) |
| **読んだ値が FFh かどうかで搭載を判断できない** — I/O 00BEh のデコードイメージが 04BEh に出る機種がある | 同 (解説) |

**どの機種から 1.44MB 起動に対応したかは資料に無い。** 「1.44MB FDD 搭載機種」
「1.44MB FD I/F サポート機」という表現だけで、機種名の明示が無い。
転送レートや回転数の明記も無い (grep 済み)。

## 3. 決めたこと

| 決裁 | 内容 |
|---|---|
| 形式 | **生イメージ (`.img`) にする。** D88 はやらない (§5 の残件) |
| 既定 | **2HD 1232KB のまま。** `-g 144` / `-DFD144` / `make fd144` で明示的に選ぶ |
| ルートエントリ数 | **標準の 224 ではなく 192** (§4-1) |
| ソースの持ち方 | **1 本を 2 通りに組む。** 別ファイルへ写さない — 写すと片方だけ直って静かにずれる |
| `04BEh` | **入れる。** ただし**触るのは 1.44MB を選ぶときだけ** (§4-3) |

## 4. 実装

### 4-1. ルートエントリを 192 にした理由 (踏みかけた罠)

IPL はルートディレクトリを `0x6000` へ**一括で**読む。標準の 224 エントリだと
**14 セクタ × 512B = 7168B で終端が `0x7C00` = SP にちょうど当たり、
スタックと衝突する。** 192 なら 12 セクタ = 6144B で 2HD と同じ余裕が残る。

エントリ数は BPB で宣言するので、ホスト側のマウントには影響しない。

### 4-2. ジオメトリ

| | 2hd (既定) | 144 |
|---|---|---|
| バイト/セクタ | 1024 | **512** |
| セクタ/トラック | 8 | **18** |
| シリンダ | 77 | **80** |
| 総セクタ | 1232 | **2880** |
| メディアバイト | 0xFE | **0xF0** |
| FAT セクタ数 | 2 | **9** |
| ルート開始 LBA / セクタ数 | 5 / 6 | **19 / 12** |
| データ開始 LBA | 11 | **31** |
| DA/UA | 0x90 | **0x30** |
| INT 1Bh セクタ長コード | 3 | **2** |
| イメージサイズ | 1,261,568 | **1,474,560** |

**値の正典は `tools/mkfat12.py` の `GEOMETRIES`。** アセンブラ側 (`boot/boot_fat.asm`
と `boot/loader_fat_new.asm` の `%ifdef FD144`) は同じ値を持つので、
**片方だけ直さないこと。**

### 4-3. 触ったファイル

| ファイル | 変更 |
|---|---|
| `tools/mkfat12.py` | `GEOMETRIES` と `select_geometry()`、`-g/--geometry`。FAT の容量とルートDir のセクタ境界を検査して fail closed。`-d` (D88) は 144 で**拒否**する (理由つき) |
| `boot/boot_fat.asm` | `%ifdef FD144` でジオメトリ切替。**`read_sector` を `div` に統一** (§4-4)。FAT を `FAT_SECTS` セクタ読むループ化。パディングを `SECT_SZ - 2` に (溢れたら nasm が止める) |
| `boot/loader_fat_new.asm` | 同じ形。`DA_UA` がカーネルへ渡る `boot_drive` になる |
| `build/boot.mk` | `boot_fat144.bin` / `loader_fat144.bin` を `-DFD144` で組む |
| `build/image.mk` | ファイル一覧を `define FDD_IMAGE_ARGS` で 1 か所に。`images/os32_boot144.img` と `make fd144`。**1,474,560 でなければエラーで止める** |
| `drivers/fdc.h` / `fdc.c` | `fdc_geom_144`、ドライブごとの現在ジオメトリ (`fdc_get_geom` / `fdc_set_media` / `fdc_set_media_by_daua`)、`fdc_set_3mode` (04BEh) |
| `fs/fatfs/diskio.c` | LBA→CHS と `GET_SECTOR_COUNT/SIZE` を**ジオメトリ駆動**に (マクロ直読みをやめた) |
| `drivers/dev.c` | `dev_init()` が記述子を現在のジオメトリで書き直す |
| `kernel/kernel.c` | `boot_drive` の DA/UA でメディアを選ぶ。**`dev_init()` より前。** 3モードの状態を画面へ (`144M` / 赤い `144?`) |

### 4-4. `read_sector` を `div` に統一した理由

spt=18 は 2 の冪ではないので、従来のシフト演算 (`and al,07h` / `shr ax,3`) が使えない。
**2HD 側も同じ `div` に寄せた** — 分岐を残すと片方だけ直して静かにずれる。
2HD の IPL には 641 バイトの余裕があるので、数バイトの増加は問題にならない。

結果として**実コードは両方 381 バイト**で、サイズは中立だった。

### 4-5. `04BEh` に触る範囲を絞った

`fdc_set_media()` が触るのは **1.44MB を選ぶときと、自分で入れたものを戻すときだけ**
(`s_3mode_on[]` で記録)。2HD しか無い機種で `04BEh` を書くと、00BEh のデコード
イメージが出る機種では **1MB/640KB I/F の切替に化ける恐れ**があるため。

呼ぶのは「1.44MB の I/F が居ると分かっているとき」だけ — 起動した DA/UA が
0x30 系なら BIOS がその I/F を使った証拠になる。

**失敗しても起動は止めない。** BIOS が起動時に既に正しいモードへ入れている
場合があり、しかも 04BEh の読みは嘘をつく機種がある。画面に印を残して進む ([V4])。

### 5-1. ホスト機能への依存 (F11 の内訳)

**起動経路はホスト機能を一切必要としない。** 致命的なのはルートマウントだけで、
それはフロッピー自身。

| 機能 | 無いときの挙動 | 根拠 |
|---|---|---|
| HostDrv (`/host`) | **静かに飛ばす**。`hostdrvfs_detect()` が I/O ポートを見て 0 を返し、`kernel.c` が `if (hostdrvfs_detect())` で囲っているのでマウントを試みない | `fs/hostdrvfs.c`、`kernel/kernel.c` |
| サブマウント (hd0 / cd0 / lo*) | **失敗を無視**。ext2 → iso9660 → fat と試して全部落ちてもループが続く | `kernel/kernel.c` |
| SerialFS | 明示的な `serial` コマンドのときだけ。失敗は `SerialFS mount skipped (%d)` | `userland/shell/rshell.c` |
| Host Services | アプリが呼んだときに `-100` (`HOST_ELINK`)。起動経路は呼ばない | F11 の実測 |

**HostDrv を実際に外した試験は未実施** — ini の `HOSTDRV0` を消す必要があり [D2] の承認対象。

### 5-2. `FONT..NG` は退行ではない

`/sys/font/default.kcgfont` が最小 FDD イメージに入っていないだけ
(`build/image.mk` の一覧に無い)。**2HD 版でも同じ。** 空きは 427KB あるので
入れたければ足せる。

> **2026-09-24 追記**: FD の中身を CD の MINIMAL と同じ集合にし、既定フォントを
> 8.3 の `/sys/font/default.kcg` として入れた (カーネルは長い名前が無ければそれを読む)。
> 入れた後の空きは 2HD 55KB / 1.44MB 267KB。[08_build.md の「起動 FD と MINIMAL」](../../08_build.md#起動-fd-と-minimal)
>
> **2026-09-25 追記**: カーネルが約 4KB 増えて 2HD の FD が作れなくなったので、MINIMAL を
> 「レスキュー兼インストーラ」に絞り、既定フォントと一般コマンドを NORMAL へ移した。
> **FD 起動ではまた `FONT..NG` が出る** (退行ではない。文字は本体のフォント ROM)。空きは
> 2HD 359KB / 1.44MB 568KB。
