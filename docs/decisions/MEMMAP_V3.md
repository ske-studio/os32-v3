## 4. SQLite・FEP・モジュール・ブート順

### 4-5. ブート順とローダの区間表 (D18)

**承認済みのEARLY計画はユーザー決定2026-10-18で作らない。** VK32の複数entryの製品利用、bootinfo 212B新形式、U19 (PG/台帳をroot前へ)、同梱域1MiB/所有移譲と対応するローダASM・hsync_bootold新対応を取り消す。VK32の形式上限4 entryは既存のまま。T4後のcore 1本の像を全媒体で共用し、FATとHostDrvはcoreに残す。

1. ローダは現行の圧縮像を集積→CRC検査→coreへ展開する。集積上限は508KiBを維持する。T6b-1/2は凍結。圧縮像が508KiBの8割の406.4KiB (≈416kB) に近づいたら起票する。

## 5. Unicode 表・フォント・FEP・バックバッファ

### 5-4. フォント — OpenType (D14: `.kcgfont` 廃止)

> **注記 (ユーザー決定 2026-09-30)**: 上の数字は JIS X 0208 サブセット (`ipaexg_subset.ttf`、3.2MB) の実測で、**サブセット化は廃止した**。**日本語 OpenType はリポジトリに含めない** — ビルド時に `tools/fetch_fonts.py` が IPA の公式配布から**同意つきでダウンロード**する (同日追記: v3 の OpenType 層はそれを配布物に入れる — 同意した人がビルドした物。移植先の欧文フォントは T7b)。**CUI は内蔵フォント (KCG ROM) だけで描く**。内蔵フォントの無い移植先の GUI 基本フォントは**寛容ライセンスの欧文 OpenType** (候補: Go fonts = 3-clause BSD、DejaVu = Bitstream Vera License。選定は T7b)。参考: 無改変の原本 `ipaexg.ttf` (6,099,900B) は 12,239 グリフ、`glyf` 5,593,490B (平均 457B、最大 1,224B、複合 0)、`loca` 48,960B、`cmap` 245,775B、`hmtx` 48,914B (fontTools 実測 2026-09-30) — 作業域の上限は同梱する欧文フォントで T7b が測り直す。

| **KCG ROM fallback (予備、D14 で決定)** | **残す (モジュール 4KB)** — フォントファイルが読めない構成 (FD 起動・`/sys` 破損) でも GUI の文字が出る唯一の手段で、コストは 4KB と JIS 表 (どのみち残る) と読み出しキャッシュ 64KB (§4-3 に計上) |

## 9. しないこと

- カーネルの仮想アドレス化 (高位カーネル) — v4 以降 (D20)。v3 では P2V / V2P の集約まで。
- アプリ私有サーフェス + WM 合成 ((c))、Video HAL / VESA2 的層 / SDL (P9)、音・入力の層 (P8) — 別の柱 (D19)。
- 互換層・旧バイナリの救済 (D7)。
- FEP の任意省略 (D21。MINIMAL 以外は常に読み込む)。
