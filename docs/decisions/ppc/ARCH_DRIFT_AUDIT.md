# PC-98／PowerMac 実装差分の監査

対象は `origin/main` の `cc1260bd2be7ef25c5722229fb4699aea3f958a5`。x86 は PC-98 製品像、PPC は既定の `kboot-link` と `kboot-core / kboot-shell / kboot-sh / kboot-link-sh`。ソース・選択式・試験コードを読み、製品を変更せず、ビルド・実機・ゲスト試験は省略した。規模は x86 のサービス契約へ寄せる概算の変更行数とファイル数。分類間で同じファイルを触る場合があるため、規模の合算には使わない。来歴の短縮 SHA は各側の先頭根拠行の `git blame origin/main`。実装全体の導入時点と異なる場合があり、分岐の導入が特定できた箇所は下に補記した。

比較基準は PACK の 2026-11-20 指示。対象 SHA の `docs/decisions/ARCH_COMPAT_CONTRACT.md` は §8 から確定記録へ続き、§9 の表を含まない。`docs/POLICY_DEV.md` 以下の §10 にも「x86 に揃える」行が見当たらない。表の「既にある」は PACK に掲げられた8項目への対応を意味する。現行 §10 の「root は RAM の読み取り専用の像」は維持して読んだ。root の統合対象は mount 手続きで、互換のために ISO RAM root 自体を HDD へ置き換える見積もりは含めていない。

## 比較基準の訂正と来歴

- 起動実体は `kboot-link` の診断、`kboot-shell` の常駐 CLI、`kboot-sh` と `kboot-link-sh` の USER シェルの三形態。二つの USER シェルは同じ `userland/shell/*.c` を使用する。既知の「KAPI の不在」は像全体の不在と、EXEC 像内のスロット別不在に分ける。 `sys/conf/images/kboot-link.mk`、`sys/conf/images/kboot-shell.mk`、`sys/conf/images/kboot-sh.mk`、`sys/conf/images/kboot-link-sh.mk`、`build/ppc-user.mk`、`sdk/gen_kapi.py`
- `sys_switch_shell` の差を CPU マクロによる権限判定とする記述は訂正が必要。i386 分岐は ShellService のサイズ検査、x86 の切替許可は実体の owner 判定、PPC の未提供判定は生成側の provider group。 `sys/kern/exec/shell_service.h`、`sys/kern/gui.c`、`sdk/kapi_target_ppc.py`
- PPC の exec boot は B30/B31 の `900d4674d`、USER sh の常駐 loop は S-C P04 の `9543775ee`、描画の owner と世代の門は 5b-A3/A4 の `73192b894`。link-sh の SFS 提供と LAN wrapper は P5/P5b の `2964a2003`、cwd/終了値の追従は `2f4ed7d73`。 `sys/platform/powermac/exec_boot.c`、`sys/platform/powermac/shell_boot.c`、`sys/platform/powermac/display_provider.c`、`userland/shell/rshell_lan.c`
- PC-98 の NIC は製品 LAN モジュールの i82557 系と、起動時 legacy 候補の NE2000 系を区別する。tick budget は x86 の TSC/PIT と PPC の TB で内部単位が異なり、共通側は同じ provider の `elapsed` と `cnt` を比較する。 `sys/conf/features/lan.mk`、`sys/conf/features/pc98-devices.mk`、`sys/platform/pc98/tick_budget.c`、`sys/platform/powermac/tick_budget.c`、`sys/kern/irq/tick_budget.c`

### 像・共通コードの条件分岐

| 条件 | 影響・根拠 |
|---|---|
| 5 像の機能表と legacy | `sys/conf/images/pc98.mk`、`sys/conf/images/kboot-core.mk`、`sys/conf/images/kboot-link.mk`、`sys/conf/images/kboot-shell.mk`、`sys/conf/images/kboot-sh.mk`、`sys/conf/images/kboot-link-sh.mk`。PPC flags と名前の検査は `sys/conf/images/ppc-flags.mk`。 |
| static SQLite と特別ビルド | `sys/kern/sqlite_outer.c`、`build/targets/ppc-powermac.mk`。hard-float 専用 group、stack/restore、生成 KAPI と ROM/RAM root の依存を target が追加。x86 側は `build/targets/x86-pc98.mk` と `sys/conf/features/sqlite.mk`。 |
| pending の機能フック | `build/sources/hooks.mk`。gfx/surface/font lease は EXEC、DB は PC98_PENDING または SQLITE、他は PC98_PENDING が既定。absent provider がプレースホルダーを供給。 `sys/kern/exec/exec_hooks.h`、`sys/kern/exec/absent/exec_gui.c` |
| SDK 生成のターゲット枝 | PPC の typed invocation、sys_halt wait、tvram_clear、機能なし／loop／DB と link SFS の選択。 `sdk/gen_kapi.py`、`sdk/gen_kapi.py`、`sdk/gen_kapi.py` |
| 共通部の CPU マクロ | 自前 C/H の顕著な直接分岐は cdecl・サイズ assert・memstat の試験分岐。vendor SQLite のコンパイラ別最適化も存在。 `sys/include/callconv.h`、`sys/kern/exec/shell_service.h`、`userland/diag/mem_stat_test.c`、`lib/sqlite3/sqlite3.c` |
| 共通シェルの profile | PPC の `SHELL_AS_APP`、`SH_LAUNCH_SYNC`、最小 base/sys、コマンド選択、path/home、link のリモート SFS。機能枝は main、cmd_base/dir/env/file/hdprep/mnt/pci/peek/script/sys/tri、rshell/rshell_lan、serial_watchdog、ui に及ぶ。 `userland/ppc/sh/profile.h`、`userland/ppc/sh/link_profile.h`、`userland/shell/main.c`、`userland/shell/cmd_sys.c`、`userland/shell/rshell_lan.c` |
| 同名ファイルの扱い | `boot.c` は PC-98 の boot phase 登録と PPC の OF 用入口で役目が異なる。PPC 製品像の入口は kernel_boot。PPC の boot_capture と ime_display、旧 shell_putchar は platform 選択リストに現れず、有効な provider 同士の比較から除外。 `sys/platform/pc98/boot.c`、`sys/platform/powermac/boot.c`、`build/arch/ppc-sources.mk`、`build/platform/powermac.mk` |
