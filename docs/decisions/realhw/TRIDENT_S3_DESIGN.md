## 3. 部品の境目

以下は内部契約案。公開KAPI/SDKの変更ではない。rc=0成功、負値失敗、段階番号と最初のrcを保持する。

```c
/* trident.h: module側の常駐状態。構造体はゼロ初期化。 */
struct trident_saved { u8 value[852]; u16 vga_base; bool valid; };
struct trident_resources { /* kernel所有、moduleへ貸与 */
    volatile u8 *regs, *lfb; u8 *client;
    u32 owner, bar0_rid, bar1_rid, decode_bytes, mapped_bytes;
    u32 display_sid, client_sid, client_bytes;
};
struct trident_device {
    const struct trident_resources *res;
    struct trident_saved saved;
    u32 declared_bytes, verified_bytes, step;
    int last_rc, restore_rc, disable_rc;
    bool init_done, first_init_done, active, returning, armed, leave_done, closed;
};
int trident_screen_init(struct trident_device *d); /* 初回のみSave/Init/実測 */
int trident_enter(struct trident_device *d); /* ModeInit/Enableのみ */
int trident_leave(struct trident_device *d); /* Restore/lock/Disable */
int trident_close(struct trident_device *d); /* Disable/Restore/lock */
int trident_restore98(void *opaque);        /* close経路、IF=0可 */
/* 新設 gfx/gfx_emergency.h: ownerは表示を取得したexec owner */
int gfx_arm_emergency(int (*restore)(void *), void *opaque, u32 owner);
int gfx_return_emergency(u32 owner, int reason); /* kernel fatalはownerを問わない */
/* trident_module.h: kernelが貸す。復帰入口はmodule text所属を検証 */
struct TridentModuleContext {
    GfxBackend *backend; GfxCounters *counters;
    const struct trident_resources *resources;
    int (*arm)(int (*restore)(void *), void *, u32 owner);
    int *height, *flip, *page;
};
```

- resources.cはcore側。`gfx_boot_reserve()` (gfx/gfx_core_surface.inc:149) → `trident_boot_reserve()` を `init/kernel.c:203` の準備境界で呼ぶ。master CR3/live AS=0を満たす。
- PCI bindとactiveは分離。ID/SR09/BAR型/Command memory-enableを検証、decode幅の根拠とRAM・PEGC・82557等との全区間非重複を確認する。
- BARには書かない（BARLEN_DESIGN.md:31）。同:25の基準Ra266の既知の上限BAR0=4MiB、BAR1=64KiBを予約・写像の根拠にし、VRAM実容量とは区別する。Trident BAR0/BAR1 と他装置の既知の全範囲の非重複だけを確認し、82557 CSR の隣接配置や未計測・台帳未登録 memory BAR の存在を起動条件にしない。長さ不明の BAR は基点だけを見る（先頭 1 ページとの照合）。基点が Trident 範囲内なら重複として拒否する。pci_aperture.cは作らない。
- 既存APIの戻り規約が異なるのでresources.cで負rcへ正規化する。`ledger_resource_add`/`ledger_reserve_set`/`ledger_surface_create`は真成功、`paging_map_phys`は0成功。

```c
/* resources.c: 実API接続の要部。rid/owner/spansは検証済み、VAはmemmap定数 */
if (!ledger_reserve_set(owner, spans, n)) return TRI_E_RESOURCE;
if (paging_map_phys(reg_va, reg_pa, reg_pages, PTE_RW | PTE_PCD))
    return TRI_E_MAP; /* 外側のtransactionが既成功mapを戻す。予約は保持 */
if (!ledger_surface_create(&display, &display_sid)) return TRI_E_SURFACE;
if (!ledger_surface_create(&client, &client_sid)) return TRI_E_SURFACE;
/* module側: resources/pinを確認してからarm。index選択を含む最初の表示レジスタ書込前 */
rc = ctx->arm(trident_restore98, &device, display_owner);
if (rc) return rc;
rc = trident_screen_init(&device);
if (rc) { device.last_rc = rc; device.restore_rc = trident_restore98(&device); }
```

- 起動予約段階はPCI/configだけ。SR09等のindexed読みも装置書込みを伴うので、module pin/arm後のidentifyへ分ける。§2順0のSR観測はこの後半で行う。
- BAR0は確認用範囲を含むdecode内だけsupervisor/PCD、BAR1は使用する0..83C8hを覆う9ページ（不足apertureなら拒否）。全aliasのcache属性を統一。
- RAM CLIENT=307200B=75ページ、DISPLAY=BAR0先頭75ページ。clientはBOOT所有WB、displayはDEVICE所有UC。2MiB全体やMMIOをUSERへ公開しない。
- 私有leaseは既存SURFACE経由、通常GUIはCLIENTのみ。DISPLAYは明示全画面leaseに限定。revoke→TLB→参照減の既存寿命を守り、master PTのUSER昇格なし。
- arm前失敗はSURFACE/CLIENT/既成功mapを巻戻す。DEVICE decode予約は他用途へ転用せず保持。arm後はコード・saved・全復帰写像・module登録参照をshutdown後も保持。
- module接続はcirrus_module.c:22–80のload/start/exports/policy照合とgeforce_module.c:95のprepare検証に倣い、専用trident loaderがprepareとrestoreもtext範囲検証してpinし、検証後にcandidateを公開。arm後detach/abortはBUSY。
- `GfxBackend`はname/probe/init/query/shutdown/present_rect/set_palette/enter/leave/prepareを実装、fill_rect/blitはNULL、modeは640×480 packed8一つ。page_flip/vsync等はNULLでNOSYS。
- prepareは記述子確認のみ（include/gfx_hal.h:85–95）、Initを走らせない。void init/enter/leave/shutdownは§2の内部関数のrcをlast_rcへ保存、failed時probe=0/query=そのrc、coreはログと復帰結果を確認してPC98へfallback。
- presentは矩形clip→RAM pitch/sizeとLFB終端を確認→行ごとCPUコピー。paletteはfirst/countを検証してDACへ6bit RGB。通常転送にVRAM readbackを追加しない。
- leave/shutdownは§2の別経路。returningで再帰を防ぎ、rcと完了段階を保持する。初回失敗を再initで隠さず、復帰失敗後は自動再入場しない。保存値はmodule常駐期間中保持する。
- leaveはRestore失敗でもDisable、closeはDisable失敗でも有効なSaveのRestoreを試み、両rcを保持。復帰rcにかかわらず呼出元はTVRAMへ必ずfaultを描画する。復帰処理自身は割当・ログ描画・tick・GE待ちをしない。
- 一般例外/#PFではアプリfault分類後、TVRAM出力前に呼ぶ。表示所有者終了/CTRL+STOP/初期化失敗も同じ口。子アプリfaultは表示ownerが異なれば復帰しない。
- `GFX_PREF_TRIDENT`はV:137の既存決定どおり内部値を追加し強制指定だけ。gfx_core.c:107–109,195–199、boot予約、init/kernel.c:254相当、設定解釈、gfxmode一覧を一緒に更新。auto探索には追加しない。

## 4. VRAMの容量の判定

SPR解釈はD:2919–2975を全行転記する（単位KiB、9682のmask=0F、古いチップの07は対象外）。

| SPR & 0F | 01 | 02 | 03 | 04 | 06 | 07 | 08 | 0A | 0C | 0F | その他 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 申告KiB | 512 | 6144 | 1024 | 8192 | 10240 | 2048 | 12288 | 14336 | 16384 | 4096 | 1024＋不明フラグ |

0EはCR C1 & 11が00/01/10/11で20480/24576/28672/32768KiB。全表は解釈用でありRa266のアクセス許可範囲ではない。

- `declared_bytes`、`decode_bytes`、`verified_bytes`を別記録。採用するのは書いて読み戻した連続容量。SPR=7F/FFの4MiB申告と2MiB実測の差は診断付き成功、黙って2MiB定数へ丸めない。
- 実測はHAL公開前、Enable後、PCD写像で実行。保存scratchはRAMを使い、検証中にclient/displayのleaseを許可しない。
- decode内をページ単位に保存→位置由来の異値→読取→反転→読取→元値復元する。ページ内全語を検査し、ページ境界の識別語を同時保持してページ間aliasも検査する。4MiB decodeで境界語1024個×4B＋1ページ保存=8KiB scratch。別値が残るうちに独立性を判定し、元値は全点を逆順復元する。
- 不応答・穴・aliasの最初の位置までの連続して読み戻せた範囲をverified_bytesとする。上位aliasで下位が変わっても元値復元後に下位の連続域を再確認し、上位への書込みを止める。上位独立なら4MiBまで採用可能、2MiB定数への丸めも拒否も行わない。
- **verified_bytes >= 640×480 = 307200なら成功**。上位2MiBのミラー・独立・未確認は成否条件にしない。SPR申告/実測連続範囲/ミラーあり・なし・未確認を1行だけ記録する。
- 必要量未満はCAP_TOO_SMALL。必要表示域のアクセス不能・復元不一致はACCESS/RESTORE、復元未完了を成功にせず復帰へ。不要な上位の不応答は連続域の終端として扱う。decode外にはアクセスせず、探索対象は既知の4MiBまで（資源境界）。
- H:411–431の4点printは実測の手本であり全域保証ではない。上記の全語・ページ間確認と連続容量判定を追加する。host期待値を実装結果から生成しない。
- 待ち無しの同期アクセスが基本。将来待ちを導入する場合だけ操作開始時の新しい期限を使い、根拠のある装置条件・失敗rcを設計へ追加する。共有deadline/固定試行数は禁止。
