## 2. .osri v2 の形式

```c
/* little endian。配置説明用。構造体castで読まない。 */
struct OsriHeader {                         /* 64B、既存配置 */
    u8 magic[4];                            /* "OSRI" */
    u16 version, header_bytes, width, height;/* 2,64,640,400 */
    u8 bpp, color_format;                   /* 4,1 */
    u16 flags;                             /* 0 */
    u32 file_bytes, palette_off;            /* 128096+8*n,64 */
    u32 pixels_off, pixels_bytes;           /* 96,128000 */
    u32 events_off, event_count;            /* 128096,0..1197 */
    u16 event_bytes, reserved_profile;      /* 8,0 */
    u16 band_lines, reserved0;              /* 1既定（2/4も可）,0 */
    u32 file_crc32, reserved[3];            /* offset48, reserved=0 */
};
struct OsriEvent {                          /* 8B、変更後の最終色 */
    u16 line; u8 index, reserved0;          /* 1..399,0..15,0 */
    u16 rgb444, reserved1;                  /* 0x0RGB,0 */
};
/* RAM専用。公開GFX_RasterPalTableへ変換しない。 */
struct OsriImage {
    u16 pal[16], count, band, version;
    struct OsriEvent event[1197];
};
```

| 約束 | v2／互換動作 |
|---|---|
| 初期色／画素 | offset64に16×u16、行0の色。offset96からB/R/G/I各32000B、行80B、左がbit7、索引bit0/1/2/3。 |
| 行・順番 | 行0差分は初期色へ畳む。line昇順、同一行index昇順、重複・同値設定拒否。line%band=0。隣接するイベント行の差1を許す。 |
| 容量 | 変更番号数m、成分数cなら費用c+max(m−1,0)。各番号最低1成分なので2m−1≤N。N=5/6ともm≤3、399×3=1197件。 |
| 予算 | 形式は行内≤3件。実行側で前状態から各行の費用を再計算しN以下を確認。3件でもRGB全変更なら11 OUTなので拒否。 |
| 保存しない値 | N、周波数、CPU、成分マスクを予約欄へ入れない。Nはホストの引数と再生器の採用予算。変更成分は前状態と最終rgb444から復元。 |
| v1 | version=1、n≤200、空ならband=4等の既存形式検査を保持。v2の行内3件／N制限をv1読込へ流用せず、読込後のpl_prepareで再生費用超過ならロゴへ戻る。公開tableの200件／2行制限も維持。v2を旧版は拒否しロゴへ戻る。 |
| 検査 | 既存の固定値・予約0・範囲・正確な長さ・短読・末尾余剰・CRC検査を維持。版別上限を先に検査してから128096+8*nを計算。 |
| CRC | offset48..51を0として全体IEEE CRC32。Python zlib／既存crc32_coreを使用。 |

## 3. 再生器

- 画像所有・転送は`platform/pc98/splash_image.c`、走査・成分列の準備と再生は新`splash_raster_image.c`、モード状態の所有は既存`splash_raster.c`。可変の辺状態は画像呼出しのcontextに閉じる。
- 再生側の内部予算はN=5。診断ビルドの同じ予算項目を明示的に6へ替えて試す。形式からN6を自動採用せず、通常版を変更するのは実列の受入後。
- 全イベントをcommit前に一度走査し、各行のOUT列を作る。行内で色を複数回試した履歴は保存しない。前行パレットとの差分だけを最終順にする。

```c
/* splash_raster_image.h: RAM専用。portはA8/AA/AC/AEの下位8bit。 */
struct PlRow { u8 first, count, port[6], value[6]; }; /* 14B */
struct PlPlan { struct PlRow row[400]; };            /* row[0].count=0 */
int pl_prepare(const struct OsriImage *, u8 N, struct PlPlan *);
int pl_frame(struct SplashRaster *, const struct OsriImage *,
             const struct PlPlan *, u64 deadline_us); /* OK/drop/NO_SYNC/期限 */
/* platform側: 期限はboot入口から引継ぐ。 */
if (osri_load(path, borrowed_fb, image) != OK) goto logo;
if (pl_prepare(image, adopted_N, plan) != OK) goto logo; /* commit前 */
set_all_palette_black();
gfx_add_dirty_rect(0, 0, GFX_WIDTH, GFX_HEIGHT);
gfx_present_nosync();                    /* 黒で128000B、画像転送はこの1回 */
while (frame_and_exit_fit(deadline_us)) {
    switch (pl_frame(state, image, plan, deadline_us)) {
    case OK: break;                       /* 次フレーム、残時間を再検査 */
    case DROP: break;                     /* IF復元・PIT精算済み、次VBLANKから */
    case NO_SYNC: goto logo;              /* 転送済みでも画像を解放してロゴ */
    case DEADLINE: goto common_exit;
    }
}
goto common_exit;                         /* 残時間不足も共通終了 */
/* logo: 画像解放→同じ期限の既存ロゴ経路（残時間不足なら共通終了）。
 * common_exit: 画像解放→bootの共通終了。再転送・期限再起算なし。 */
```

| 順序 | 手順と境界 |
|---|---|
| 1. 起動判定 | 09A8h D0で24/31k、8周期±1%・bit5高期間でVS型／非表示全体型を判別。active0=25/34又は0。公称H=100000/2483又は100000/3147µsを維持。 |
| 2. 初期16色 | 毎フレーム新VBLANKに16色全部（64 OUT）。VBLANKはVFP/VS/VBPを含む。非表示全体型はFより前に完了する。VS型は短いbit5高期間内だけへ押し込まず、F捕捉後VBPで完了できる予算を使う。 |
| 3. 原点 | A0hの同じINでbit5/6を読む。新しいV立下りF、その後のlow→highをk=1とする既決規約。開始時highを数えない。初回は古いbeginのFを流用しない。 |
| 4. 可視前 | VS型は初期色中に未観測のHをD:345の番号付き区間Aと共通low区間Gで再確定し、可視直前でCLI。非表示全体型は初期色・IRQ0処理後、予測Fの直前でCLIし、新Fを実際に捕捉して連続計数する。CLIから可視開始まで≤2H、F前に保護できなければdrop。 |
| 5. 行y−1の表示中 | 行yの先頭indexだけA8hへ先行OUT（count>0の場合）。RGBは触らない。列と分岐先の選択はH立上り前に済ませる。 |
| 6. E(y) | lowを確認した後の新highを1回数え、k=active0+yで準備済みcount個を直ちにOUT。先頭番号は列に含めず、2色目以降のA8hは列に含む。成分はG→R→B順のうち変わるものだけ。 |
| 7. 次行 | lowで再武装して次行の先行番号を出す。空の行もHを数え、OUTは0。行399まで同じ処理。行400の可視終端まで保護後、PIT精算して保存IFを復元。 |

```c
/* 概念上の内側。実際にはcount別の最大6 OUT列を展開し費用を測る。 */
status = in8(0xA0);                  /* 内側で時計を読まない */
if (edge_upper_limit_reached()) goto drop; /* low待ちも含む上限 */
if (!(status & 0x40)) armed = 1;
else if (armed) {
    if (!edge_lower_limit_met()) goto drop; /* 新辺だけ下限検査、OUTより先 */
    armed = 0; ++k;
    if (k == target_k) emit_prepared_outs(row); /* 0..N、探索・色展開なし */
}
/* 行間の準備中もサンプル間隔Qの上限を守る。IF方針は画像側だけが持つ。 */
```

- burst問題の解決: 1H未満でarmedを毎回捨てる観測を再生へ流用しない。可視中は連続観測し、辺ごとの有限反復上限だけを更新する。IRQ開放を跨いだ前値で偽の辺を作らず、次フレームはF/Gから取り直す。
- プローブも同じ連続検出を使い、既定の64周期を連続採取（31k約2.03ms、24k約2.58ms＋入口）。時計は前後だけ、RAM集計後にIF復元・シリアル出力。旧「2Hから時計費用を引いて標本数を決めるburst」で64完成周期を求めない。
- 辺ごとに前の成功INから次の成功INまでを測る反復窓を固定する。列count・先行OUT・分岐ごとの既知費用を含め、正常辺の最遅観測をTnormal、1本欠落時の次辺の最早観測をTmissとし、上限Kの最短／最長経過tmin(K),tmax(K)が`Tnormal<tmin(K)≤tmax(K)<Tmiss`を満たすことを採用条件にする。通常TnormalはH_max＋Q＋E、Tmissは2H_min−Q−Eで評価する。
- 下限もH_min−Q−Eより早い辺を拒否するよう費用別に認定し、上限到達／早すぎる辺はk加算と次RGB OUTより前にdrop。low待ちも同じ窓に含め、下限は新辺の成立時だけ検査する。初回はF/Gから一意に定まる次辺の区間で窓を初期化する。正常Hを待つ窓と欠落Hの次辺を排除する窓が両立しなければ採用しない。固定1000000回や内側の時計読取は使わない。
| 時間予算 | 判定 |
|---|---|
| H内 | `Q + D + W_N + E < B_min`。Q=実サンプル間隔上限、D=成功IN帰還→列の開始、W_N=列全体（番号・各OUT・列内処理）、E=観測誤差。二重計上しない。 |
| 概算31k | 1.15+0.78×5=5.05µs（5.9との差0.85）、N6=5.83µs（差0.07）。分岐等未算入、5.9も保証下限ではない。実列の計測でB_minと比較する。 |
| 次行準備 | 先行番号・行進行・再武装込みで高/lowを丸ごと飛ばさないQを測る。`Q<min(B_min,H_min−B_max)`、準備はlow区間内に完了。 |
| 可視保護 | 400H≈12.71/16.11ms。VS型は可視前入口、非表示全体型はF前のCLIから計上し、入口≤2H＋出口Cexit込みで`402H_max+Cexit<20ms`。VBLANKの初期色・IRQ0処理をCLI前に終える。 |
| 3秒 | boot入口の期限。読込・判定・黒での転送・再試行を全て含む。次フレーム＋終了処理の上限が残時間に入らなければ即共通終了。VS待ちは100msと共通期限の早い方。 |
- 初期色の最終許容時刻Linitは、非表示全体型ではFの最早時刻からCLI・F捕捉準備の上限を引き、VS型では一意に再確定できる最後のA/G入口から再確定費用上限を引いて定める。最早可視時刻と共通期限−フレーム残処理−Cexitも上限に取る。
- 初期色開始前に時計で`now+C64_max+E≤Linit`を検査する。各初期色OUTの前にも残列費用上限込みで同じ検査を行い、64 OUT直後に完了時刻≤Linitを検査。超過なら残りOUTを止めdrop（既出色は取消不能）。C64_maxは分岐・時計・許すIRQ遅延込みで測る。
- CLI直前に時計で最終入口時刻と残予算を検査し、CLI後は費用を認定した有限反復でF/Gを取得する。可視ループの最初のRGB OUT前にも原点一意・入口経過≤2H・最初の辺の窓を検査し、遅れはdrop。内側で時計を読まず、入口・辺の反復費用をQ/DとIF上限へ算入する。
- PIT補正は旧候補§3を継承する必要機能。各保護（非表示全体型はF前から）の入口/出口で残数c0/c1とpending p0/p1を採取し、H経過範囲から`d=w*reload+c0−c1`のwを一意に決める。IF=0で`tick_count += w+p0−p1`を一度だけ反映し、保留IRQの1回と二重計数しない。
- 算数は`time_splash_math.c`、採取・反映は`ktime.c`。ラッチ競合の再採取、次PIT境界までの出口余裕、異常出口の経過範囲も旧候補どおり検査。補正不能なら推測を足さずIF復元・共通終了。補正前の時計で期限を延ばさない。失ったtick_dispatchをまとめて呼ばない。
- 間に合わない行: 起点不明・入口遅れ・H欠落・初期色超過では同フレームの残りを止め、dropは1回、未完了予定件をlate/unappliedへ各1回。翌行へ差分を移すと以後の成分の前状態が壊れるため繰り越さない。次VBLANKに16色から回復。既出の色は取り消せない。
- 事前のN/物理予算不成立はcommit前に拒否。実行中の一過性dropと同期喪失によるNO_SYNCを分ける。n=0は静止色提示後IF開放。入口IF=0で動的再生せず、勝手にSTIしない。
- 既決の縮退順は1行→実測で成立する2行→静止ロゴ。2行像は原画から再変換して配置し、実行時間引きはしない。2行でも1本のH内はN以下で、2Nをまとめない。H内の列自体が収まらない問題は2行化では解けない。

- 2行縮退は旧候補§2(b)/(c)の採用条件を継承。準備不足なら全行計数・連続保護のまま偶数行だけ更新。長い保護／PIT補正が不成立ならD:345のG/Sで各偶数行の番号を一意にし、各保護≤2H・開放≥1H・IRQ0処理完了が成立する短区間だけを採る。この場合は長い保護用の補正を呼ばない。成立しない場合は静止ロゴ。

| 評価 | ディザ前の等重みRGB二乗誤差`L=SSE(y)+0.5*SSE(y+1)`。最終行は当行のみ。当行だけの誤差増加も合計改善なら許す。旧variance重みをPL-Bへ混ぜない。 |
| 採択 | 試算:85を規範にする。slot内は重複除去した混成RGB辞書順から改善量/max(1,追加OUT)最大の最初だけを選ぶ（np.argmax、同点はRGB順）。その代表間のみscore→改善量→総費用小→slot小→RGB辞書順で比較。改善量≤1e−7なら除外、反復≤2N、候補なしで停止。最適解保証なし。 |
| 費用 | 探索開始時の前行パレットとの差を毎回再計算。途中の変更は同じslotの最終値へ統合し、最終列のc+max(m−1,0)≤Nを守る。 |
| 画素／書出し | 全履歴確定後、整数FS（右7、左下3、下5、右下1／16、負は0方向除算、縦持越し）で物理索引へ割当てる。最近色同点はindex順。B/R/G/Iを詰め、最終差分をline/index順に8Bで書く。 |
| 全体上限 | PL-Bに旧100件・1件/行・固定色8個の既定を適用しない。1197件は容量上限で埋める目標ではない。N6ファイルをN5再生器が受けたら実費用で検査し、超過行があれば拒否。 |
| 2行縮退 | 2行共有のパレットを原画から作り、現在2行＋次2行の半分を評価。境界は偶数行だけ、各H内N以下、最大597件。bandはヘッダーで識別し疎な差分から推定しない。 |
