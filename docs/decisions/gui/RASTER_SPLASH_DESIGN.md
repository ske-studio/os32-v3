## 2. 段0: 計測の設計

| 根拠 | 採用する情報・限界 |
|---|---|
| PC9800Bible `docs/hw/PC9800Bible/2-7_グラフィック.md:230` | 0A8h=番号、0AAh=G、0ACh=R、0AEh=B。既存の4 OUT順を保つ。 |
| UNDOCUMENTED `docs/hw/undocumented/io_disp.md:24,765` | 0060h/00A0h の bit5=VSYNC、bit6=HORIZONTAL BLANK。水平同期信号そのものとの同一視はしない。 |
| `include/pegc.h:95,106,115,247` | 09A8hは `PEGC_HSYNC_PORT` / `PEGC_HSYNC_READ_HF` でD0だけ読む。書込用MASKは使わない。054Ch bit5は既存BIOS定数と `v86_bios_real_lowmem()` の起動時の写しで診断記録だけ（ページ0は未写像、fix0依頼で訂正）。 |
| 周期・位相の正典 | `include/pegc.h:325-335` の400行SYNCと `docs/hw/undocumented/io_disp.md:1875` の公称周波数を組にする。周期のµs比は31k=`100000/3147`、24k=`100000/2483`、4行は約127.1/161.1µs。 |
| NEC Technical Databook Hardware (1993) | 手元の `docs/hw/` に該当資料を確認できず、未照合。メーカー資料のタイミング表を実装前のHW3資料ゲートでPMが補う。 |
| BSD参照 | [FreeBSD releng/10.4 sys/pc98/cbus/gdc.c](https://github.com/freebsd/freebsd-src/blob/releng/10.4/sys/pc98/cbus/gdc.c#L655):655,685 はVSYNCの抜け→入り、831は16色パレット設定。冒頭はBSD 3条項。同期・I/Oの参考に限り、描画コマンドは採らない。 |

- 観測口は診断ビルド専用 `platform/pc98/splash_probe.c`。通常起動と同じ begin 後に呼び、診断終了後は共通終了処理へ戻す。新規KAPI・常駐IRQハンドラは作らない。
- 時計は既存 `sys_time_now()`（`kernel/time/ktime.c:56`、PIT補間µs）。読出費用・1µs量子化・逆行補正回数を測る。ラスタの待ちに `cpu_delay_us()` は使わず、絶対時刻とステータスを照合する。
- 全画面CLIは禁止。IF=0は目標の1行前から対象HBLANKの同一行更新終了まで、最長2行周期（31k約64µs/24k約81µs）。各保護区間後はIF=1を1行周期以上確保する（入口IF=0では動的再生しない）。立下り捕捉は§5の1行以内だけを保護する。最大値と1フレーム合計を記録する。

| 測るもの | 手順・記録 |
|---|---|
| 起動条件 | SHA・媒体CRC・機種・09A8h生値/D0・054Ch bit5・表示高・flip・PIT分周・シリアル速度。begin前後の値を比較する (054Ch は起動時の写しなので前後は同値、begin による変化は 09A8h で見る)。 |

| 行周期/HBLANK幅 | bit6の0→1→0を高速ポーリング。32/64周期の総時間を整数比で求め、幅は単発測定の観測誤差込みで下限を出す。IRQを含む長い区間は欠落候補として別集計。 |
| パレットI/O | 同じ値で単一OUTを8/16回、色1件の4 OUTを1/4/8組実施。空ループ・時計費用を別測定し、組数に対する傾きと単発上限を記録。長い組は分割しIRQ窓を設ける。 |
| 初期16色 | VSYNC入りで16件を設定し、終了時刻・bit5・次の可視開始までの余裕を記録。16色全体をCLIで囲まない。 |
| IRQによるずれ | 無負荷/シリアル受信負荷の予定→開始/終了差、late件数/率、遅延行数、最大IF=0・フレーム合計、tick差、OE/FE/PE/ring overflow差と番号付き受信列の欠番を採る。 |
| 現行120µsとの比較 | flip有無、dirty初回/継続を分け、同じ像で初回と後続の所要・最終帯位置を比較。120を127や161へ置換する試験とは分ける。 |

- 計測像: 左端に固定白の16行ごとの目盛、中央にパレット1だけの広い縦長矩形、右端に固定16色タイル。画面上下は太い固定枠にする。
- 中央の赤/緑を4行または1行ごとに変え、カメラ用に32行帯と上/中/下の太い印も置く。副尺は固定色の8行縞を9列へ−4〜+4行ずらして並べ、動的帯と揃う列を選ぶ（周期8で両端は同位相なので粗い枠で区別）。
- VSYNC立下りから最初の帯までを1行ずつ掃引する。beginでbit5の高期間を測り、総行数−400（31k=49、24k=40行）に近ければ `active0_lines=0`、VS幅（31k=2、24k=8行）に近ければ `active0_lines=P8>>2`（VBP:31k=34、24k=25）とする。8周期の高期間平均を行周期へ換算し±1行以内を「近い」とし、どちらにも合わなければdynamic_ok=0。NP21/Wの非表示全体型では立下りが可視行0になる。実機は選んだ位相を副尺・HBLANK番号で確かめる。立上りを原点に表示するログには実測VSYNC幅を加える。
- カメラは表示有無・大崩れ・帯の大まかな位置だけを判定する（`docs/decisions/realhw/RA266.md:94`）。1行位置・色差・細い水平乱れをカメラ合格だけで保証しない。
- プローブはRAMへ固定長記録し、測定区間終了後にシリアルへ出す。走査中のprintf・ファイル読み込み・カメラ要求は禁止。溢れた記録は失敗扱い。
- 記録例: `SPLR phase=... frame=... y=... target_us=... begin_us=... end_us=... stat=... late=...`。集計はn、min、median、p99、max、欠落候補数、時計エラー数を残す。
- PMはノートのセッションへ31kHz診断起動・受信負荷を依頼し、ログとカメラ画像名を対応させる。実機24/31kHzの物理切替と復帰はユーザーの立会い時だけ。PMのソフト操作では切り替えない。
- NP21/Wは24kHzの周期判定・bit6によるHBLANK待ち・ポート順・両VSYNC辺・timeout・復帰・planar配置・初回/継続を先行確認する。bit6模擬は `~/np21w-src/src/io/gdc.c:761`。実機I/O予算の証拠にはしない。
- 段0成果物は31kHzの位相補正・hblank_min_us・誤差E・1件上限W・IRQ遅延J・許容件数・late率・IF=0最大/合計。周期num/denは定数で、実測値をそのまま周期にしない。24kHzはSYNC由来の既定値をNP21/Wで確認する。
- 採用ゲート: `m*W + E + 判定費用 < hblank_min_us`、初期16色は可視開始前に完了。31kHzは実測で採用、24kHzは初版4行1件をNP21/Wで確認して採用し実機予算は未確認と明記。複数件は各モードの確認済み上限まで。

## 3. `.osri` 形式 v1

- カーネル内部形式。静止画1枚、非圧縮、little endian。下記は配置の説明でありファイルを構造体へ直接castしない。サイズとoffsetofを静的検査する。
```c
struct OsriHeader {                    /* 64 bytes */
    u8 magic[4];                      /* "OSRI" */
    u16 version, header_bytes;        /* 1, 64 */
    u16 width, height;                /* 640, 400 */
    u8 bpp, color_format;             /* 4, 1 = RGB444 */
    u16 flags;                        /* 0 */
    u32 file_bytes, palette_off;      /* 128096 + 8*n, 64 */
    u32 pixels_off, pixels_bytes;     /* 96, 128000 */
    u32 events_off, event_count;      /* 128096, 0..200 */
    u16 event_bytes, reserved_profile; /* 8, 0; mode is not in file */
    u16 band_lines, reserved0;        /* 1/2/4, 0 */
    u32 file_crc32;                   /* offset 48 */
    u32 reserved[3];                  /* all zero */
};
struct OsriEvent {                    /* 8 bytes */
    u16 line;                        /* 1..399; visible line */
    u8 index, reserved0;              /* 0..15, 0 */
    u16 rgb444, reserved1;            /* 0x0RGB, 0 */
};
```
- 初期パレットは16個のu16（0x0RGB、上位4bit=0）。画素はB/R/G/Iの順に各32,000B、各行80B、左端がbit7。色番号のbit0/1/2/3を各プレーンへ入れる。
- 初期パレットが可視行0の値。イベントはその行の開始前に完了すべき差分で、同じ行はindex昇順、同じ(line,index)の重複を拒否する。lineはband_linesの倍数。
- 行0の変更は初期パレットへ畳む。段2の0,4,…,396の比較列は「初期の1色＋99差分」になる。毎フレームの初期16色は別負荷として必ず数える。
- reserved_profileは常に0。n=0ならband=4、n>0でも走査モードを格納しない。同じファイルを24/31kHzで使い、行/フレームの件数上限は起動時に選んだカーネルの予算で検査する。
- 整合性: loaderでmagic/version/固定値/予約0、正確な全長と固定offset、n<=200、範囲・整列・重複・同値再設定を検査。画像制御側で行/フレーム予算をcommit前に検査する。異なるイベント行の間隔は2行以上とし、1行間隔を予算違反で拒否する（band=1自体は形式上許すが、間隔の緩和は段4の実測後だけ）。同一行の複数件は一つの保護区間の予算で検査する。未知フラグは拒否しファイルの走査モード照合は設けない。
- nを上限検査してから `128096+8*n` を計算し、短い読み・途中EOF・末尾余分も拒否。検査済みになるまでVRAMへ提示しない。暗号署名や複雑な回復形式は追加しない。
- CRCはヘッダー48..51を0としてファイル全体をIEEE CRC-32。Pythonは `zlib.crc32`、Cは `lib/crc32_core.inc:13` のinit/update/finalを再利用し、finalは最後の1回だけ。
- `lib/crc32.c:14` の一括版と同値であることを既知ベクトル・分割読みで照合する。CRCの新実装やゲストへのzlib追加は不要。
- SDKの `GFX_RasterPalEntry` はr/g/b別バイト・pad2のRAM形式（上記`:623`）。`.osri` の8Bと同サイズでもバイナリ互換にせず、SDKヘッダー・世代・KAPIを変更しない。
- 既存MGXは画像用、VBZはパス描画用でイベント列を持たない（`tools/img2mgx.py:51,528`、`tools/img2vbz.py:1160`）。枠を流用せずPIL・struct・CRCの既存手段を使う。

## 4. ホスト変換

- 置き場は `tools/img2osri.py` 1本。PillowでPNG等を読み、RGBへ合成、縦横比維持の縮小＋黒余白で640×400にする。透明部分は黒へ合成する。
- CLI案: `input.png -o splash.osri --mode fixed|A|B|C --budget <json> --events 100 --per-line 1 --band 4 --fixed-colors 8 --dither fs --alloc median|variance --preview preview.png`。budgetは変換の件数上限だけでファイルにモードを埋めない。
- fixedは全画面16色、n=0。初版動的出力は4行・1件/境界・100件以下（格納上限200と区別）。両モードに配る像は両者の採用予算の小さい方を使い、実測前の出力は診断用として扱う。
- RGB888→444は各成分 `(v*15+127)/255` の整数丸め。PILの量子化色も444へ丸め同色を統合。パレット履歴を確定後、各行で有効な16色へ整数Floyd–Steinberg誤差拡散（右7・左下3・下5・右下1、分母16、左→右）して画素を決める。符号付き誤差は0方向へ除算、画像外は捨て、行間は持ち越し、最近色の同点はindex順とする。

| 最適化 | 初版の具体的な処理 |
|---|---|
| A:16色全可変 | 初期行/帯をPILで最大16色へ量子化。次の帯は前パレットを維持し、量子化候補色への1スロット置換を全候補で評価、二乗誤差を最も減らす変更を予算まで採る。 |
| B:共通色＋可変 | 全画面量子化で得た色を使用数降順・同数はRGB順でk色固定し、残り16-kだけAの置換対象にする。kはCLI指定、初版既定8。 |
| C:帯で共有 | A/Bの評価範囲を4行の帯へ広げ、同じパレットで全画素を再割当て。初版既定はB＋C（4行・最大1件/境界）。2/1行は段4で有効化。 |

- `--alloc median`（既定）は従来のPillow MEDIANCUTと等重み距離。試用の `--alloc variance` は全画面をRGB444に丸めた画素数重み付きRGB分散を整数の重みにし、全画面と各帯の箱を箱内分散×全画面重みが最大のチャンネルで重み付き中央値分割する。同一レベル間では分割せず、代表色を444に丸め同色を統合する。帯の置換評価と誤差拡散の最近色にも同じ重みを使う。全成分の分散がゼロなら等重み。
- CLIの `--mode B` は固定色＋4行帯、`--mode C` は固定色なし＋4行帯（`A` も現実装では同じ帯方式）。上表のCは最適化の分類であり、CLIのB+Cを `--mode C` と取り違えない。

- 変更は誤差が改善する時だけ採り、同値設定を出さない。indexの選択は誤差→index→RGBの順で同点処理する。探索は貪欲法で、最適解を保証しない。
- 更新予算に達したら現在のパレットで残りを量子化する。完成画像からイベントだけを削る処理は禁止。パレット履歴と誤差拡散後の画素を一組で出力する。
- プレビューは出力済み`.osri`を読み直し、各行のパレットでディザ込み画素を復号する。同じリサイズ済み原画をPillowで256色に減色・ディザした像と横に並べ、ラベル付きPNGを1枚出す。厳密な走査時刻・実機色の模擬はしない。
- 初版に色誤差レポート・比較専用ツールは作らない。変換完了時は件数・最大同一行件数・予算・CRC・Pillow版とオプションだけを記録する。画質目標は256色版と見比べて遜色ない程度で、数値閾値は置かない。

## 5. OS32再生と部品の境目

| 部品 | 責任・状態の所有 |
|---|---|
| `init/boot_splash.c` | 全体の開始/終了、3秒期限、内蔵ロゴ。begin後に画像経路を試し、失敗時はロゴを描き直す。装置・プレーンの詳細を持ち込まない。 |
| `platform/pc98/splash_image.c`（新規） | 借用BBと共通再生状態を使い、画像記述だけを所有。読み込み→実行予算検査→commit→再生を制御し、戻る時にFD・画像記述を解放。共通状態はロゴへのfallbackまで保持。 |
| `gfx/gfx_osri.c`（新規） | VFS読み込み・形式/CRC検査。受け取ったBBへ分割読み込み。ポートI/O・表示・時間待ちは行わない。 |
| `drivers/video/pc98/splash_raster.c`（新規） | 24/31kHz判定・有理数周期・VSYNC/HBLANK待ち・パレット再生を画像と既存ロゴで共有。FS/VRAM転送は知らず、共通再生状態も本部品が所有する。各gfx_initで未判定に戻し、最初の利用時に8周期・位相を判定してそのgfx_initの寿命中保持、gfx_shutdownで失効する。splash外の公開gfx_present_rasterも同じ状態を使う。 |
| `gfx/gfx_vram.c`（既存） | 画像はnosyncの初回転送だけ。既存gfx_present_rasterのflip/dirty処理も転送→共通再生へ分離し、RASTER_LINE_US・相対delay・無期限VSYNC待ちを除去。公開KAPIの型/番号は維持。 |
| `platform/pc98/splash.c`（既存） | begin成功後にsplash_rasterの非公開accessorから共通再生状態を借り、初回の8周期判定を済ませる。clear_pagesは共通状態の寿命を変えない。BBは既存gfx_kernel_framebufferで借りる。 |

```c
/* 非公開ヘッダー。呼出し契約を先に固定する。 */
struct OsriImage { u16 pal[16], count, band;
                   struct OsriEvent event[200]; };
struct SplashRaster { u32 frame, late, mode, dynamic_ok; int last_result;
                      u32 line_num_us, line_den, active0_lines; };
int osri_load(const char *path, struct gfx_kernel_fb *dst,
              struct OsriImage *image); /* 成功0、失敗<0、必ずclose */
int pc98_splash_raster_begin(struct SplashRaster *s); /* accessorの初回利用時に8周期・位相判定 */
int pc98_splash_raster_frame(struct SplashRaster *s,
                            const struct OsriImage *image);
int platform_splash_try_image(const char *path, u32 end_tick);
/* begin/frame/tableは0またはNO_SYNCをlast_resultにも記録。try_imageはDONE/FALLBACK/NO_SYNC。 */
int pc98_splash_raster_table(struct SplashRaster *s, const GFX_RasterPalTable *t);
struct SplashRaster *pc98_splash_raster_state(void); /* 再生器所有、初回遅延判定、gfx_init〜gfx_shutdown */
void pc98_splash_raster_reset(void); /* gfx_initで未判定化、gfx_shutdownで失効させる内部フック */
```
- 初回のopenは現行boot_splash内、begin後・root mount/IRQ有効化後。パスは `SYS_SPLASH_IMAGE` の `/boot/splash.osri`。その前に共通再生器で8周期を判定し、結果を画像/ロゴで共有する。Host Serviceや遅延mountを待たない。
- begin後はパレットを黒へ揃える。`osri_load` は64Bヘッダー→32Bパレット→4プレーン→イベントを順に読み、4KiB以下の単位で既存BBへ直接格納しCRCを逐次更新する。
- 短い正のreadは残量を読み足す。失敗なら全BBをロゴで上書きしてから提示。BBのpitch×高さが32,000Bで4プレーンが連続していることを確認してから読み込む。プレーン容量はモード選択時のgfx_mode_fitsの台帳検査を前提とする。`OsriImage`だけ小容量確保し、大きなスタック配列・128KBの一括ヒープ確保は避ける。
- 全検査完了後に全画面dirtyを1回登録し `gfx_present_nosync()` を1回呼ぶ。準備中は黒、最初の正常VSYNCで初期色を出す。flip後の表示ページを固定し、以後present/flipを呼ばない。
- prev_dirtyは次回presentのための既存状態として残るが、画像再生中は参照されない。終了/ロゴ再描画を含め両ページを確認する。継続フレームのVRAM書込量は0。
- 起動判定: D0が選ぶ周期と8周期平均/総行数を±1%で照合する。SYNCの総行数は31k=449（約14.27ms）、24k=440（約17.72ms）。照合は64bit整数の交差積で行い、不一致はdynamic_ok=0としn=0画像のみ使用、動的画像/ロゴは静止ロゴへ。bit5高期間からのactive0選択は§2に従い、どちらの幅にも合わない場合もdynamic_ok=0。beginがBIOSのSYNCを保つ前提も段0で検証する。
- 各フレームで新しいVSYNC入りに初期16色を設定し、抜け時刻t_endを捕捉。起動判定の周期・高期間と直近のVSYNC入りから立下りを予測し、その1行前までIF=1、予測した立下りの1行前から立下り捕捉までだけIF=0とする。捕捉窓は最大1行、窓内に捕捉できなければIFを戻して当該フレームを捨てる。立下り捕捉が予測から半行以上遅れたフレームも、以降のイベントを適用せず捨てて数え、次の新しいVSYNCから回復する。行yの可視開始は `t_end + floor((active0_lines+y)*line_num_us/line_den)`、更新はその直前HBLANK。64bit整数で絶対位置を計算し、イベント間隔も行差から導く。
- 入口IF=0では動的再生せず、静止提示して入口IFを維持する。目標の1行前までIF=1で待ち、irq_save後に対象HBLANKの新しい辺を待つ。同一行の全4 OUT群まで保護してIF=1へ戻す。1区間は2行周期以内、立下り捕捉を含む各保護区間の後にIF=1を連続1行周期以上確保し、VRAM転送はこの区間へ入れない。初期16色はIF=1のまま設定し、立下り捕捉前に完了する予算で検査する（IRQ側からパレットを書かない前提を確認する）。画像と公開tableの予算検査は異なるイベント行の間隔2行未満を拒否する。遅れや繰越で窓が確保できない時は窓を優先し、後続を繰り越す。間隔の緩和は段4の実測後に限る。
- IRQ等で目標を逃したらlateを数え、IF=1の窓を確保した次のHBLANKへ順序を保って適用する。残余に収まらない分も繰越し、後続と重なった同一indexは最新の予定値へ畳む（未適用件数も記録）。絶対目標はずらさず、次フレームの初期色で回復する。
- HBLANK待ちが2行以内に完了しなければIFを戻してlateとして数え、IF=1を1行以上確保した次の窓へ繰越す。可視区間を越えた未適用分は数えて捨て次フレームへ。lateだけでは再生停止しない。同期待ちはVSYNCの100msタイムアウトでNO_SYNC、時計異常時は有限ポーリング上限で終了する。
- 固定画像（n=0）は初期色を1回設定した後、終了期限までIRQを有効にして待つ。画像経路の全再試行を含め3秒の共通期限を延ばさない。
- NORMALだけに画像を配り固定パスにあれば使用する（PM決定）。欠落・破損・予算超過・動的判定不可は理由を1行だけログして内蔵ロゴへ。FD/MINIMALは画像を含めない。begin自体の失敗は従来どおりCUIへ。
- 再生中はVSYNCタイムアウトで画像経路を終了しNO_SYNC静止ロゴへ。late率は試験の採否基準に用い、通常再生中の停止条件にはしない。故障時も3秒の共通期限を延長しない。
- 共通再生器の結果を非公開の状態照会でboot_splashへ返す。NO_SYNC/dynamic_ok=0ならロゴをnosync提示して有限期限で終了する。時計も使えなければ共通終了へ直行。公開gfx_present_rasterのvoid署名は変更しない。
- 既存ロゴ移行L0: gfx_present_rasterは全dirty転送（non-flipも一括）とflipを先に完了し、次のVSYNCから共通table再生へ。SDKのline=0は初期色、以後はline順の絶対目標。ロゴの100件/4行・形・色順・フレームごとのoffsetは維持し、初回だけ長い経路を解消する。位置の基準は旧120µs再生の見た目ではなくテーブルの意図とし、行yの色をエントリ⌊y/4⌋に合わせて400行全体へ広げる。splash外もgfx_initごとに判定した共通状態で再生し、判定不可/NO_SYNC/予算違反は転送済み像を静止提示してvoidで戻る。3秒間のcommitsを移行前後で数え、スクロール速度の差を±10%以内に保つ。
- 共通終了は成功/失敗とも一箇所: 画像記述解放→両ページ消去→`gfx_shutdown()`（共通再生状態失効）→`palette_init()`→`tvram_clear()`。保存したIFとGUI希望値を維持し、画像用状態を次回GUIへ残さない。

### 2. §2 置換案 — 根拠・予算・番号の原点

H は水平周期、B は安全にパレットを更新できる水平非表示幅、Q は連続 IN の実サンプル間隔上限、W は 4 OUT 完了までの上限。
Q は IN 命令だけでなくループ・分岐・計数の費用を含む。C は時計読出し、E は位相/量子化等の余裕とし、すべて整数比で管理する。
HBLANK は `GDC_GFX_STAT`（00A0h）の `GDC_STAT_HBLANK`（bit6）、V は同じ IN の bit5 を採る。
根拠は `M/include/pc98.h:186,187,288`、`M/docs/hw/undocumented/io_disp.md:765`。水平同期パルス HS 自体とは区別する。
メーカー資料は `~/os32-tmp/refs/pc98-databook/NOTES.md:4`、NEC Technical Databook Hardware (1993) p.350–351。
BSD 参照は [FreeBSD gdc.c](https://github.com/freebsd/freebsd-src/blob/releng/10.4/sys/pc98/cbus/gdc.c#L655) の :655,685,831（BSD 3 条項）。同期待ち・パレットポートの参照に限り、描画処理を移植しない。

| モード | H、総行数、VS/VBP | B の根拠と採用限界 |
|---|---|---|
| 24k | 100000/2483µs、440、8/25 | メーカー HFP+HS+HBP=3.04+3.04+3.8=9.88µs。bit6 と実画面の対応は実機で確認。 |
| 31k | 100000/3147µs、449、2/34 | `M/include/pegc.h:335` の CR=78+2=80、HS=7+1=8、HFP=3+1=4、HBP=7+1=8 より H×20/100≈6.355µs。 |

31k の B は SYNC の導出値であり、メーカーの測定値ではない。実機の bit6 幅・極性・可視開始との関係が一致して初めて採用する。
24k の同じ導出は H×26/106≈9.878µs。水平各値の符号化は `M/docs/hw/PC9800Bible/2-6_テキスト.md:219,270` と既存 SYNC 定義を参照。
NP21/W は `gdc.c:438` の式のままだと高幅が24k約30.4µs/31k約25.4µsになる。実機用の B と取り違えない。
bit5 の非表示全体型は同ファイル `:439,440` と `~/np21w-src/src/pccore.c:1084,1105,1113` に対応する。
この差はエミュレータ波形の別検証項目とし、本改訂で NP21/W を編集したり極性を自動反転したりしない。

begin の8周期±1%と bit5 高幅±1行の分類は残す。非表示全体型なら active0=0、VS 型なら active0=VBP。
ただし周期一致だけで dynamic_ok=1 にしない。H 波形・Q/W/B・再同期誤差・有限待ち予算も通った場合だけ動的再生を許す。
同一行 m 件の更新条件は **Q + 分岐費用 + m×W + E < B_min**、辺の連続検出条件は **Q < min(B_min, H−B_max)**。
ここで Q と分岐費用の二重計上を避け、前者はサンプル間、後者は成功 IN の戻りから最初の OUT までとする。
たとえば W=4µs なら Q=1µs は31kでも余裕を検証できるが、Q=5µs は31kを通らず、Q=8µs は24kも通らない。
さらに Q=8µs は31kの高パルスを丸ごと跨げる。時計を除去しても全位相・全型 drop=0 は保証できない（§7 の PM 決定 U1）。
時間予算不成立は画像 commit 前の拒否/静止 fallback。実行中の一過性超過は G2 の drop とし、両者を混同しない。

番号の定義: 可視行 y の直前の H 立上りを E(y) と呼ぶ。初期16色が行0を作り、差分は E(y) で出す。
bit5 立下り F が行境界に一致し、その境界の直前 H が既に終了する位相なら、F 後の最初の新しい H 立上りを k=1 とする。
この規約では E(y) の番号は **k=active0+y**。非表示全体型の E(0) は F より前なので初期色で処理する。
VS 型の最初の E(0) は k=25/34、最初の差分 y=4 は k=29/38。非表示全体型の y=4 は k=4。
F と H の位相関係は bit5 高幅だけでは決まらない。診断で同一 IN の V/H 列と副尺を照合し、この番号規約を確定する。
F と H が同じサンプルで変わる場合の前後関係が不明なら採用しない。定数を±1して見た目だけ合わせない。
起点は V の high→low を観測した後、H の low→high を初めて観測して立てる。開始時 high を新しい辺として数えない。
内側は `IN→bit比較→0→1なら++k→kが対象なら4 OUT`。high の連続読出しで二重計数せず、次の low で再武装する。
V/H の読む順序差を作らず、一つのステータス値を使う。時計・printf・探索・CRC・VRAM 転送をこのループへ入れない。

### 3. §5 置換案 — IF 窓と番号を失わない再開

400行を連続 IF=0 で数える案は採らない。可視部だけで31k約12.71ms/24k約16.11ms、VBP 込みならさらに長い。
採るのは **番号が一意な短い観測区間をつなぐ方式**。IF=1 中に観測しなかった辺は「実測した本数」に加算しない。
時計による粗待ちは許すが、「数行前なら誤差を吸収する」だけでは不十分。H 波形には行番号が無く、1行のずれは数え直しても消えない。
したがって各再開前に、次に観測する辺の番号がただ一つと証明できるガード区間を設ける。曖昧なら OUT 前に drop。

1. 起点捕捉は、前フレームで確定した立下り区間 F_prev と、8周期観測から安全側に求めた実測フレーム周期 [T_min,T_max] の和 F_next=F_prev+[T_min,T_max] を覆う窓で行う。IF=1 で読んだ V 立上り時刻は粗い確認だけに使い、F の予測基準にしない。最初のフレームの入口では、begin と同じ観測方法で、同一 IN の V が最後に high だった時刻と最初に low だった時刻の区間から F_prev を必ず取り直す（時計・IN の遅延と途中の IRQ を含める）。begin から n フレーム空いた古い区間を最初の基準に流用せず、n×(T_max−T_min) の不確かさを持ち込まない。その幅で次の F→最初の H の保護が≤2Hにならなければ有限期限内で再取得し、取得できなければ動的不採用。捕捉失敗フレームは drop し、古い基準から経過フレーム数ぶん周期区間を足す。幅が許容を超えたら再取得し、IRQ 後の遅れた立上りで基準を上書きしない。
2. その窓から最初の H 辺までの保護を≤2Hに収める。旧「F 捕捉≤1H」はこの V/H 起点取得≤2Hへ置換する。
3. 真の番号付き辺 k の時刻区間 A=[a−,a+] を保つ。時計は窓の前と OUT 後に読み、C/Q/W の上下限で辺を挟む。
4. OUT 後の時計は診断/次の粗待ち期限のためであり、検出済み H 内へ書くかどうかの判断には使わない。
5. 次の番号 j の辺の区間を I(j)=A+(j−k)×[H_min,H_max] とする。公称値を中心に周期照合で得た誤差境界を使う。
6. 共通 low 区間 G(j)=(upper(I(j−1))+B_max, lower(I(j))) に入ったことを確認してから数え始める。
7. IF=1 で G(j) 付近まで待ち、irq_save の前に IF=1 のまま時計で入口の事前検査を行う。G(j) の安全な入口期限を過ぎていれば irq_save せず、保護区間を作らず手順8へ進む。まだ手前なら IF=1 で待つ。事前検査が通った場合だけ irq_save し、直後に一度だけ時計で期限を再検査する。時計・分岐・最初の IN の上限まで含め G(j) 内なら開始。事前検査から再検査までの時計費用 C を含む競りの幅は S_j の内側への丸めに算入し、IRQ がその余裕を超えて遅延させた場合は開始せず復元する。
8. IF=1 の事前検査で G(j) を逃した場合は、保護区間を作らず G(j+1) を再評価する。まだ手前なら IF=1 のまま待ち、G(j+1) についても手順7の事前検査と irq_save 後の再検査を行う。既に入っていれば、その検査費用も含め G(j+1) 内と証明できる場合だけ開始する。両方の入口期限を逃した場合は OUT 前に drop。irq_save 後の再検査に失敗した場合は別途保護区間として計上し、復元後1Hを確保しても S_(j+1) が残る場合だけ再試行する。低状態だけで番号を決めず、IRQ で1行以上飛んだ場合も番号を丸めない。
9. y の1本前 j=k(E(y))−1 から入れたら二つの新しい立上りを数え、二つ目で直ちに更新する。G(j+1) から入った場合は最初の新しい立上りが E(y) なので1本だけ数えて直ちに更新する。いずれも開始時 high を辺に数えない。
10. 終了時計を取って irq_restore、次の保護開始まで少なくとも1Hの割込み処理機会を確保する。次の A で誤差を更新する。

割込み許容値はイベントごとに式で固定する。i=j,j+1 について、入口処理を始めてよい安全な時刻区間を S_i=[L_i,U_i] とする。
G(i) の開区間端を内側へ丸め、IF=1 の事前時計検査・時計誤差・irq_save・直後の時計再検査（費用 C）・期限判定・最初の IN の最悪費用を差し引く。事前検査後の競りに備える内側の余裕もここへ算入する。さらに前の保護終了から1H以上、当該保護≤2H、終了から次の保護開始まで1H以上になる範囲へ絞る。空の S_i は使わない。
通常経路の予定入口 r=L_j に対し、IF=1 の事前検査での超過判定から再待ち・次の入口検査までの追加の非IRQ費用上限を D とする（初回入口費用は S_i に算入済み）。irq_save 後の再検査失敗も再試行する場合は復元等の追加費用を D に含め、別途1Hの開放条件を満たす場合だけその経路を使う。J は r へ向かう粗待ちの末尾から入口確定までに IRQ により増えた累積遅延で、連続・複数 IRQ と復帰遅延を含む。単一 ISR の最長時間とは区別する。
両方の S_i が使える4行経路では **J_max(y)=U_(j+1)−r−D** とし、**0≤J≤J_max(y)** なら S_j で開始するか、間の空白を IF=1 で待って S_(j+1) で開始できることを事前検査する。再試行を含む実際の入口がこの上限に収まる待機・判定費用を D に含める。S_j だけなら J_max(y)=U_j−r、1辺だけの経路ならその S の U−r を使い、負の予算は不採用。
フレーム全体の **J_max=min(全イベント・中継の J_max(y), F捕捉入口の余裕, 初期16色完了期限の余裕)** とする。各余裕は同じく時計・実行費用・IF契約を差し引いた値。LC-A は J の測定範囲・負荷・最大値と各 J_max を µs の整数比で記録し、未測定の数十µsという推測を採用値にしない。実機の観測最大は測定負荷での証拠であり、任意の IRQ に対する絶対上限とはしない。
irq_save 後に失敗した入口再検査も保護区間として最大・合計へ加え、復元したら次の保護まで1Hを確保する。この制約で S_(j+1) が消える場合は1辺経路を使えず、S_j だけの J_max へ縮める。IF=1 の事前検査で G(j) を過ぎたと判定した経路は保護区間を作らず、この失敗検査由来の1H待ちを加えない。合計200Hという評価を失敗検査の費用なしで流用しない。

これは粗い時刻で番号の候補を絞り、実際の更新を辺で決める方式。各イベントの OUT を F からの経過µsで発火させる旧方式とは異なる。
H_min/H_max は±1%の採否条件とは別に安全側で計算する。400行ぶん公称±1%を放置すると±4行となり G は消える。
長いイベント空白にはパレットを書かない中継の観測区間を置く。空区間もIF上限・合計・最低開放時間に含める。
G が空、時計誤差が1行以上、区間の上限を保証できない場合は動的不採用。起点が確かでないまま k を丸めて再開しない。
数える間の上限は校正された最小/最大ループ費用に基づく反復数。停止 H/時計でも必ず irq_restore する。
通常の必要辺を待てる回数かつ最悪実行時間≤2Hとなる回数上限を両立できなければ不採用。POLL_LIMIT=1000000の流用は禁止。
区間外では100msのVS期限と全体3秒期限を残し、期限確認までの遅れも最大2H以内に抑える。

異なるイベント行の間隔2行未満の拒否は維持。段2は1行1件の既存制限も維持し、同一行複数件の拡張は後段のままとする。
2行間隔は1辺だけを捕捉する短区間で IF=1≥1H を満たす場合にだけ採用し、満たせなければ予算違反として全表を拒否する。
4行間隔でも「最大2Hなら常に可」とはしない。A/G/C/W から区間の終了上限と次の開始下限の差≥1Hを事前検査する。
N=99 の差分＋起点1区間なら保守的合計≤200H、31k約6.36ms/24k約8.05ms。中継M区間があればさらに≤2MH。
実際は `Σ(粗待ち終了→辺待ち→OUT→終了時計→復元)` を記録し、最大は31k約63.55µs/24k約80.55µs以内。
「IF=1窓」は再生器が保持してCLIしない区間を指す。IRQ自身と sys_time_now 内の短いCLI（`M/kernel/time/ktime.c:70`）は別集計する。
実機で物理的に連続した IF=1 を要求する解釈では現行時計も違反するため、IRQ受付可能時間・PIT tick・受信欠落で契約を検証する。

### 4. 取り逃がし・初期色・late/drop

区間ごとに開始番号・観測辺数・終了の時刻区間を照合し、経過時間から許される行数集合が観測数と一致することを検査する。
例えば本来2Hの区間で1本を落とし3H掛かった場合は、区間期限/数の不一致で drop。検出後は同フレームの残りを出さない。
フレーム境界では実測VS周期、モード総行数440/449、番号の進みを照合する。観測数と、Gで一意に確定した未観測区間を別々に記録する。
IF=1区間の推定本数を足して「全440/449本を観測した」と報告しない。VS周期だけでは単独のH取り逃がしは検出できない。
過去に出した色はフレーム末尾の検査では取り消せない。OUT前のQ/Bと番号一意性が主保証、末尾検査は事後検出である。
前提を破るHパルス欠落・NMI等は既出の色が乱れ得る。dropはフレームの取消表示を意味せず、残りを中止して次回初期色で回復する。

画像は毎回16色、公開表の行0はその指定色を復元する。いずれもIF=1で、IRQ側が同じパレットを触らない前提を確認する。
非表示全体型は新しいV立上りで16色を書き、起点捕捉の最早開始までに終える。VS型はF捕捉後のVBPで書ける予算を検査する。
31k VS幅は約63.55µsで、1 OUT=1µsなら64 OUTだけで超える。VS内に16色が収まるという条件を置かない。
VS型の初期色の間も未観測Hを区別し、完了後 G で番号を再確定する。行0開始前の完了と最初の差分窓の両方を満たす。
静的予算は事前検査、IRQによる実行中の初期色超過は droppedを1増やしOKで戻る。dynamic_okを消さず次の新しいVで再試行（G2）。
lateは予定行に完了しなかった差分件数、各件1回。drop後の未適用分もlate/unappliedへ一度ずつ加算し、初期16色は別診断件数。
droppedはそのフレームを1回だけ数える。理由は起点不明・再開番号不明・H欠落・初期色超過・実行予算超過に分ける。
lateの次行への繰越・同index畳込は廃止する。行ごとの色一致を失う時点でdropし、lateだけを理由に画像経路全体を停止しない。
VS喪失/時計異常はNO_SYNC、通常のdropはOK。n=0の静止色、入口IF=0の静止提示、3秒期限、共通終了は従来契約を維持する。

### 5. 模型の試験計画

模型を単調な独立走査時計で動かし、`in_us`、`clock_cost_us`、`out_us`、分岐費用、IRQ継続時間を別パラメータにする。
IN のサンプル位置と返却時刻を別にし、OUTは開始でなく実効時刻/完了時刻を記録。行末までの全可視期間も検査する。
24k/31k×VS/非表示全体の4型×各300フレーム、起点位相を掃引。初期16色＋4行99件の全400行×16色を独立期待値と照合。
旧模型の「4 OUTを最後にまとめて反映」だけでなく、G/R/B各OUTによる可視途中の色破れ、1行早い適用も検出する。
IN費用1/5/8µs、時計費用1/5/8µsを直交させる。旧poll=5の反例はまずIN=0/時計=5/OUT=1/幅8をそのまま再現する。
`R/play_r3_row_mismatch.log:1` の24k非表示全体・行4開始178977µs、OUT178979〜178982µsが旧版でREDになることを確認する。
新模型ではINにも非ゼロ費用を課し、H幅を実機由来へ替えた試験を追加する。旧再現と現実条件の試験を一つに混ぜない。
Q+分岐費用+mW+E<B、番号/IF予算、J≤J_maxを満たす組合せでは行色一致かつlate=unapplied=drop=0、両版DIAG有無で同じ結果を要求する。
満たさない組合せでは動的不採用をGREENとする。とくにIN=8/31kをdrop=0の動的成功にする偽のH幅拡大は禁止（U1）。
IRQ注入は §3 の累積遅延 J を µs 単位で 0 から J_max+2H まで掃引し、J_max−ε/J_max/J_max+ε（εは模型の最小時間刻み）も必ず含める。モード・位相ごとの J_max の数値、J、入口経路をログへ出し、J≤J_max で全300フレーム drop=0 を要求する。
J>J_max は保証域外なので、単に上限を超えただけで失敗を強制しない。G(j) だけを逃す注入では、IF=1 の事前検査が超過を検出して irq_save を呼ばず、S_(j+1) が空にならず G(j+1) の1辺経路で行色一致・drop=0となることを要求する。事前検査を除く旧経路の変異で余計な保護区間と1H待ちによりこのケースが RED、修正版で GREEN になることを確認する。irq_save 後の再検査との競りも別注入し、失敗した保護区間の計上・復元後1H・OUT前のdropを検査する。両方の入口期限を逃す注入または初期色期限を超える注入では OUT 中止・drop一回、その次の正常負荷フレームで初期色から回復を要求する。連続IRQも注入し、単一ISR長だけで J を小さく見積もる変異をREDにする。
V立上り直前のIRQを別に注入し、F_prev＋周期による窓がずれないこと、初回 F_prev の区間が広がった場合に採用しないことを検査する。begin から最初のフレームまで n フレーム空けるケースも加え、最初の入口で新しい同一 IN の high→low 区間を必ず再取得することを検査する。古い begin の区間を流用する変異を RED にし、再取得の幅が許容内なら開始、期限内に許容幅を取得できなければ動的不採用とする。
NP21/W 型の H 高幅（24k H×80/106、31k H×80/100、約8割）とその位相も独立の波形ケースに追加する。番号・周期・極性の対応と不適合時の拒否を検査し、このケースの成功を実機幅での可視行色一致の合格に代用しない。
Hパルス1本消失、倍幅、V停止、時計停止/逆行、期限ぴったり、行399、2行間隔、同一行拒否、入口IF=0も検査する。
変異は辺の二重計数、k±1、時計挿入、予算無視、G検査削除、drop二重加算、G2をNO_SYNC化、IF復元/有限上限削除を実行時REDにする。
無時間INの模型では新ループが停止するため、INごとの時刻進行と独立の呼出回数上限を先に実装する。結果未取得をGREENと書かない。

### 6. 実機・変更ファイル・段

Ra266の31kでQ/C/W、累積割込み遅延JとJ_max、bit6幅と位相、8周期、高幅分類、番号、IF最大/合計、drop理由をRAMへ記録し、走査後にシリアルへ出す。
固定16色＋4行帯＋8行縞の−4〜+4行副尺を撮影し、上中下・帯の向き・400行下端・初期色回復・3秒後CUIを確認する。
300フレームの無負荷/受信負荷でJ≤J_maxを確認したうえでdrop=0、未適用0、受信欠番/OE/FE/PE/overflow増加0を要求し、旧ロゴ速度±10%も残す。J超過は通常負荷の合格とせず、期限超過時のdropと次フレーム回復を別記する。
カメラで1行精度を断定しない。副尺で判別不能な位相は未確認、Q/W/Bゲート未達なら動的採用しない。
24kは既存 `SPLASH-24K-RH` の立会い試験で同項目を測る。物理切替/復帰はユーザー、ソフトはノート経由でPMが依頼する。
