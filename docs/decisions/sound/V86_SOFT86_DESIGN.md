# PCM 専用機の V86 ゲストに提供する PC-9801-86 互換音源

状態は **草案**。対象は PC-98 の DOS ゲスト一セッション。着手時期は未定。[ROADMAP](../../ROADMAP.md) の将来項目と ユーザー決定 U32 に基づく。[AV 設計 §9](AV_HAL_DESIGN.md) のセッション・発音経路にボード PCM の再生を追加する。

## 起動時の選択

| 起動時に得た証拠 | V86 セッションの動作 |
|---|---|
| 0188h 系と 0288h 系がともに ABSENT、CS4231 の snd2 再生 backend が利用可能 | ソフト 86 の候補。begin で前景所有と stream を取得してから bitmap を切替。競合は BUSY として戻す。 |
| 実 86 または 26K | 搭載機のゲスト I/O と IRQ 配送を維持。26K を 86 として広告しない。 |
| 118 | 実 FM を素通しにし、118 の実 PCM を使える構成を保つ。実 FM と PCM の物理線共有は IRQ 設計の後段。両者の併用を実機受入に含める。 |
| probe 不明、出力なし、未対応機種 | 自動選択を見送り理由を記録。従来の V86 経路を使う。 |

IRQ 設計 S1 の保存判定を参照し、begin で再 probe しない。S2/S3 が物理線を所有する。双方 ABSENT でも BIOS の WSS INT5・DMA #1 と backend の open 成功を別々に確認する。probe 復元失敗時は物理 IRQ12 を抑止する。118 の初段で IRQ10 の PCM を使えるのは、実 FM の線と分離できる場合に限る。後段は実配線を照合し、同線なら物理 IRQ12 を共有する。実 FM の bitmap 捕捉後も等価な実 I/O を一回だけ転送する。別線なら各線の所有者へ返す。

起動時に機種能力を固定し、各 begin では利用権だけを取り直す。CS4231 の物理線の到着回数は機種判定に使わない。

## FM を鳴らす版の実装判断

1. **合成後の PCM は既存の snd2 stream 一本に渡す。** 前景の V86 アプリが drain した時刻付きレジスタ列をソフト OPNA に適用し、通常文脈で sndl_pump を呼ぶ。L3 が開いた CS4231 stream に S16LE・左右交互・44,100 Hz（4 byte/frame）で供給する。snd2_stream_write の長さと正の戻り値は byte。短い成功では受理済み分だけ進め、0 なら残りを次の pump へ持ち越す。未送信標本を再合成しない。負値は再生失敗として回収する。初段は一人の書き手で足り、出力用の新 KAPI、共有メモリ、別の再生タスクは不要。後述の PCM 一括転送は **ゲストが A46Ch に書くボード PCM を monitor からアプリへ取り出す** 後段だけに使う。[既存の出力契約](../../../sys/hal/sound/snd2_stream.c)
2. **V0 は期限起床を製品へ結線する前の測定にする。** 共通 PIC・Q1・偽時計 V1 の既存検査、I/O 捕捉、同期読み、アプリの合成・出力は先行できる。V0 の診断対でゲストが I/O を出さない間にも実期限から VM を抜けられること、同時 PI が再生を進めることを測る。合格した起床源だけを V4 と run の復帰点に結線してから、タイマ駆動の DOS 曲を製品で受ける。測定不成立時の順は下記 IRQ12 節に従う。
3. **実 FM が IRQ10 なら、同じ線への PCM open は資源設定前に拒否する。** 実 FM の所有と配送を保ち、WSS の 0F40h・DMA・PIC を変えない。つなぎの 0x1A は FM と IRQ10 の分離を確認でき、S3 が資源を取得した場合に限る。線不明の併走も有効にしない。両ベース ABSENT の Ra266 は WSS 単独の IRQ12 なので、この版のために IRQ10 の共有 dispatcher を作る理由がない。衝突時の拒否と設定不変はホストで試す。
4. **118 の実 FM と PCM の IRQ12 共有は型番・設定別の実測で解禁する。** ID 8、FM 応答、独立した WSS 検出を入口とし、86 FIFO は触らない。FM 単独と PI 単独で物理線・ack 後の解除を記録し、同線駆動可能な配線、他の割込み源の抑止、併走時の非無音 PCM・曲速・PI 単独のゲスト反射ゼロ・終了時の復元が揃った設定だけを製品表に入れる。ID だけでは線は判らない。未確認なら実 FM を維持し、PCM は前項の別線条件で扱う。118 の有効化を Ra266 の FM 聴取の前提にしない。[配線と受入手順](../../design/kernel/irq/irq.md)

## ゲスト I/O と時間の所有

PC-98 の V86 monitor が SOFT セッションに限り TSS I/O bitmap の 0188h–018Fh、A460h–A46Eh を禁止側に設定する。#GP の IN/OUT では既存の観測・実ポート転送より先に対象を消費する。A462h/A464h は GS/73 用 DSP で、SOFT 86 は未搭載として FFh／書き捨てとする。発音の時刻、タイマ満了、FIFO 消費を同じ単調時刻で比較し、同時刻では期限を反映してから命令を処理する。

| 対象 | monitor が答える操作 |
|---|---|
| 0188h/018Ah、018Ch/018Eh | 各 bank の index を保持。data 書込みは時刻と通番を付ける。status とタイマは monitor で即答し、合成器に依存する data 読みは AV §9 の IOREAD で同じ命令に返す。奇数は FFh／書き捨て。 |
| A460h | AV §9 の ID と拡張許可を返す。許可解除時は bank 1 を隠す。 |
| A466h、A468h | FIFO 状態／音量、運転・停止・リセット・レート・割込み許可と要求を管理。 |
| A46Ah、A46Ch | 制御状態に応じて形式・左右の指定または割込み閾値を設定し、再生データを byte 順に受ける。 |
| 範囲内の未定義番地と A46Eh | 初版案は FFh／書き捨て。実測・資料で機能が判明した番地だけ仕様化する。 |

現行の v86_gp_emulate.inc は INS/OUTS 未対応で、a0_weak.c のセッション口は NOSYS。AV §9 の run/drain、幅 2/4 と同期読みは実装予定である。SOFT は幅 1/2/4 の IN/OUT・INS/OUTS を低位 byte から扱う。物理ポートを一つでも含む混在要素はアクセス前に未対応 fault とする。文字列は REP の有無、DF の両方向、16/32 bit のアドレスサイズに従い、一要素ずつ転送先／元の全 byte のメモリ権限とキュー容量を先に検査する。例外では完了要素だけ index・残数に反映する。

同期読みは通常の IN 一命令に限る。AV §9-2 の sid と直前の IOREAD に対する reply を検査し、次の run で同じ IN を再実行して応答を一度消費する。保留中は EIP と宛先レジスタを進めない。FM の INS は要素の読出し前に影を検査し、必要な影が無効ならその要素の副作用・書き戻し前に未対応 fault とする。FIFO の REP OUTS は確定要素だけ index・残数を進め、満杯では EIP を保持して未発行要素から再開する。end/fault/kill では期限を解除し、起床印と保留 IN・応答を消去して次の VM 進入前に bitmap を復元する。stream と前景所有は通常文脈で一回回収し、begin 途中失敗も取得済み資源を戻す。

## FIFO から CS4231 まで

仮想 FIFO は 32 KiB の byte リングとし、空／満、再生位置、閾値要求は monitor が所有する。経過時間×選択レートの整数剰余を保持し、完全な入力フレーム単位で消費する。停止中は進めず、形式やレート変更の直前に旧設定でその時刻まで進める。空なら無音とし残量を負にしない。満杯への書込み、閾値ちょうど、要求解除後の再発火、端数 byte の扱いは実 86 の短い I/O 列を基準に固定する。

monitor は消費した PCM と時刻付き FM イベントを順序付きでアプリに渡す。転送用キューとゲスト可視 FIFO は別に持ち、drain の頻度でゲストの残量を変えない。転送枠の不足は run の命令境界でアプリへ戻して解消する。既存 v86s_fm_drain のイベントに PCM byte を一個ずつ詰めると syscall とキューを圧迫するため、PCM は時刻・形式・長さを持つ一括転送を提案する。FM は 512 件（6 KiB）、PCM 転送列はまず一塊（ステレオ i16 で最大 1 KiB）で測る。公開 ABI の表現と採番は実装前レビュー事項。

V86 アプリが lib/os32_opna の整数合成、PCM の整数レート変換、libos32snd の加算・飽和、L3 pump を順に行い、一本の snd2 stream から CS4231 に出す。PC-98 のポート知識は monitor に置く。新規の合成・転送は通常文脈で行う。既存 HAL の DMA 補充コピーには AV §3-4 の上限を適用する。[合成器設計](SYNTH_OPNA_DESIGN.md)

run の返却境界は FM と PCM で一つとする。begin 時刻を起点に、前回境界の直後から今回境界までを渡す。境界は時刻と同時刻内の通番で表し、begin 時刻の最初の操作も含める。期限の CSM・FIFO 消費を同時刻のゲスト書込みより先に確定する。PCM payload は先頭標本時刻・形式・レートを持ち、次の制御イベント・閾値・リング端または 256 入力 frames で区切る。満杯なら両列で格納できた連続部分の末尾だけ返し、未確定の期限・端数・byte を次に引き継ぐ。未処理イベントのない時間は空列でも境界を進められる。ゲストが止まっている間にアプリは両列をそこまで取り切り、標本時刻と通番順に合成する。

期限処理の入口でゲスト時計を一度採り、その時刻を今回の目標に固定する。一回に最大一区間進め、転送満杯で戻っても目標と消化位置を保持する。到達後は後続の経過分を次回に回し、保留 IN の完了または PIC 判定を経て VM に再入する。次の期限処理までにゲストの一命令を完了できるよう、期限が既に過ぎた場合も再入前の追い直しを繰り返さない。連続する二つの pump 窓（各 768 出力 frames）で未処理時間が各窓の開始時より増え続けたら、過負荷でセッションを終了する。周期数の計算とコピーは IRQ/IF=0 の外。遅着時は内部状態だけ進める。FIFO 空の無音・遅着・出力 underrun の別計数と欠落 frames の記録は kdebug 対部品で行う。正常受入は欠落ゼロ。

## IRQ12 の成立と配送

タイマ A/B の満了フラグと対応出力許可、FIFO の閾値要求と許可を個別に保持し、論理和で一つの仮想線を作る。ゲストの音源 ack は対応要因だけを消す。CS4231 の物理 PI は既存 handler が ack して snd2 を進める。PI 単独でゲスト pending を立てると、再生 period のたびに DOS の演奏が進むため、この組合せを負の試験にする。

AV §9-4/V0 に従い次期限に I20/I21 を arm する。PI と TI の同時 ack・再設定が再生と共存できなければ PIT one-shot の既存時計との共存を測る。両方失敗なら 100 Hz 制限をユーザー判断に戻す。TI または期限用 PIT の handler は起床印を立てる。同時 PI は同じ dispatch で ack・再生補充を済ませる。物理 EOI 完了後、割込みスタブの IRET 直前に保存 EFLAGS.VM と起床印を調べる。VM なら命令境界の文脈を保存し、既存の v86_longjmp_out で run に SLICE を返す。通常 tick の slice 判定を待たない。非 VM なら印を保持し、次の run の VM 進入前に通常文脈で引き取る。run 間の pump・IOREAD 待ちではゲスト時計を進め、前景停止では停止時刻まで確定して時計を凍結、再開時に期限を張り直す。満了ごとに予定時刻の CSM を同じ通番列へ積み、同時刻の OUT より先に処理する。満杯では未処理期限を保ち CSM を合流させない。27h の A/B フラグ許可・個別クリア、29h の出力許可を独立に試す。

実 FM 反射と SOFT は要求記録→候補選択→注入確定を共用する。ゲストの IRQ フレームと完了済み #GP 命令の復帰で候補を選ぶ。IOPL=3 の STI は CPU が実行し、ハードウェア IRQ の受理か、STI の次の捕捉命令が完了した時点で配送する。線の立上りを IRR にラッチし、音源 ack による入力解除でも未配送 IRR を保持する。SOFT の確定後は両側の EOI が揃い、なお線が active なら一回再要求する。実音源は同じ未解除要求を再反射せず、源別に解除を確認してから次を採る。片側 EOI では重複させない。ICW2 変更後は slave の現ベース＋4 を使う。非 VM 時も IRR に保持する。VM 復帰で仮想 IF・STI shadow・両 IMR・優先順位・ISR を検査する。スタックとベクタの検査、フレーム更新の成功後にだけ IRR を消費し slave IR4 と master IR7 を in-service にする。既定ベクタは INT 14h。一復帰につき一件、同時の IRQ0 を先に通す。仮想 EOI とマスク解除で残存要求を再評価する。物理 EOI は既存 dispatch complete に一任する。[IRQ 設計「後段の実音源共有と仮想 PIC」](../../design/kernel/irq/irq.md)

固定優先順位、ISR と EOI の根拠は Intel 8259A の Fully Nested Mode と End of Interrupt（p.15）。比較実装は FreeBSD bhyve の要求選択と受理処理。PC-98 のカスケードはマスタ IR7 に接続する。[Intel 8259A](https://pdos.csail.mit.edu/6.828/2005/readings/hardware/8259A.pdf)・[FreeBSD vatpic.c](https://github.com/freebsd/freebsd-src/blob/main/sys/amd64/vmm/io/vatpic.c)

## Ra266 の受入窓

この窓の採時・計数は kdebug on の対部品で行い、外部収録と照合する。初回の目標は整数 FM 6 声＋SSG 3 声＋ステレオ FIFO 一本を出力 44.1 kHz、period 256、lead 3 で 60 秒。これは未測定の目標。一区間は 5.80 ms、3 区間は 17.41 ms。17.41 ms は pump 間隔の上限、snd2 の cap 1024 frames は 23.22 ms。OUT 時刻、FIFO 消費、slice/drain、変換完了、staging 供給、played を同じ窓で採る。実データに孤立クリックを入れ、OUT 時の外部マーカーとライン出力を同時収録して計算値と照合する。PCM の OUT→出力には先行 FIFO の待ちが入り、消費→出力と分ける。暫定合格は後者と FM 書込み→出力が 1 pump 窓＋cap（40.63 ms）以内、前者はこれに先行 frames／入力レートを加えた値以内。22.05 kHz では同じフレーム数で各時間枠は倍になる。

タイマ周期 T ごとに予定→検出、検出→注入可能な VM 復帰、復帰→注入を別記し、IF/IMR 保留も計数する。暫定予算は検出最大 min(T/4, 1 ms)、配送可能時の検出→注入最大 T/2。短周期で超過したらその周期を対応外として報告する。60 秒窓の演奏速度誤差は暫定 1% 以内、CSM の欠落ゼロ。ゲスト側の意図的保留は配送予算の集計から分ける。

PII 266 MHz で声数 1→3→6、SSG、FIFO、リズムを順に加え、各 period の trap・合成・pump cycles と各最大値、staging の供給時刻が HAL の補充期限に間に合ったかを記録する。欠音・期限超過ゼロ、pump 最大 768 frames、IRQ0 最大 200 µs、対象 HAL の IF=0 最大 1450 µs を要求する。既知波形で 8/16 bit の符号・byte 順、左右単独／両側、レート変更境界の位相継続を照合し、広い整数の加算後に一度だけ飽和した標本と一致させる。44.1 kHz 未達ならゲスト速度を保って 22.05 kHz で再測する。

## 最初の DOS 聴取の実装と受入

1. NP21/W は req86 の**窓 2**（FM なし、WSS 単独、ini の表記は `SNDboard=60`）を選ぶ。PM は窓 2 の ini の写しを今回の試験名 `soft86-w2.ini` として明示的に `/isoft86-w2.ini` で起動し、実際の ini 名・値、像 SHA と媒体 CRC を収録に添える。保存済み 0188h・0288h の双方 ABSENT、WSS の BIOS INT5、実 stream open 成功、IRQ12・DMA #1 と played 増加を同じ起動で記録してから聴取する。0x64 は実 86 素通しの回帰窓。窓 2 の既存記録は wave の再生までで、冷間初回には underrun が一度ある。初回と再起動後の結果を別記する。[冷間起動の記録](../../tasks/DEFERRED_TESTS.md)
2. 実装する DOS 試験は `tests/sound/soft86_tone.asm`（NASM flat binary の COM）。DOS 起動媒体の写しに FMTONE.COM を入れ、AUTOEXEC.BAT で実行する。OS32 シェルから `v86 -b fmtone.fdi` でこの媒体を起動する。通常の -b は FM_SOFT を指定して begin を試す。カーネルは保存 probe を読み、実音源・UNKNOWN・対象出力なしは資源取得前に NOSYS を返す。この戻りだけ従来の boot2 に進む。両 ABSENT の候補で begin が成功したら、アプリは最初の run より前に L3 のソフト OPNA と stream を開く。begin の BUSY や候補選択後の open 失敗はエラー終了し、取得済みの sid は end する。snd2 のユーザー設定値を probe の代用にしない。ゲストは sndl_test.c の左単音（algorithm 7、block 4、F-number 0269h）を基本 bank の byte OUT で設定する。28h=10h の後、仮想 IRQ0 の経過 tick をメモリで待ち、2 秒後に 28h=00h。待ちループ自体は I/O を行わない。消音を 1 秒保持して終了する。DOS 起動・終了、キーボードの既存経路を保つ。
3. v86_io.c の bitmap と実 OUT 入口で対象ポートを物理転送より先に消費し、index/data を Q1 に順番に渡す。v86.c は通常 tick 一回で VM の汎用・セグメントレジスタ、復帰 CS:EIP、SS:ESP、EFLAGS を保存して SLICE を返す。v86_session.c で同じ命令境界から再入し、終了・fault・取得途中失敗で bitmap と所有を戻す。kapi_v86s.c と v86_call.c は既存四口を dispatch。アプリは空の drain でも返却境界まで合成して既存 L3 を pump する。44.1 kHz、period 256、lead 3 を先に満たし、無 I/O 中も通常 tick（100 Hz で 10 ms）から次の供給完了までを含む供給間隔が 768 frames（17.41 ms）未満、underrun と未送信標本の欠落ゼロを実測する。SLICE 復帰時刻、drain の空振り・未処理数、供給時刻は kdebug 対部品で採る。V0 の採時・計数も同じ扱いとする。
4. ホスト登録検査は保存 probe の両 ABSENT／実 86／UNKNOWN を入力し、自動選択と bitmap を照合する。SOFT の実 I/O 入口→run/drain→pump で音色列・key-on/off の通番、物理転送ゼロ、無 I/O の連続 SLICE 後の文脈と音の継続、正常終了・fault の各直後の bitmap 復元と stream 再取得を検証する。物理 OUT への落下、key-off 脱落、bitmap 復元漏れ、stream 解放漏れを各々変異にする。NP21/W は同一媒体を二回起動し、左単音約 2 秒→release 後の無音→再起動で再発音をライン収録と聴取で確認する。COM が DOS プロンプトへ戻り無音を収録したら CTRL+STOP で VM を抜ける。終了境界まで残るイベントを drain・合成してから stream を drain close し、end で sid を返して同じコマンドを再実行する。ホストでは -b の分岐、BUSY／open 失敗で boot2 を呼ばないこと、各 SLICE の前後で PCM の物理 IRQ12 が有効なことも調べる。

Q1 と一括転送は u32 の at_us（約 71.6 分）・seq（毎秒 1 万件で約 4.97 日）の一周をまたぐ入力を使い、内部の広い時刻と列順で同時刻の標本順を保つ。sid は毎秒 1 セッションでも約 136 年で一周し、直前の保留一件との一致だけを調べる。

各段で失敗入力を先に登録し、条件反転・早すぎる注入確定・期限取り違えなど対応する変異を通す。AV §9 の構文は将来契約であり、合成ライブラリの存在だけでは run/drain の受入は成立しない。

## ユーザー確認

対象 DOS ソフトごとに再生専用で足りるか、入力→発音の許容 ms、必要な最短タイマ周期と許容誤差を確認する。V0 の両起床源が成立しない場合の 100 Hz 制限、Ra266 未達時のレート・声数も判断を求める。118 の実 PCM 利用は既定要件である。

## 資料から決める値と実機で決める値

手元の PC9800Bible「2-13 FM音源」冒頭と §2-13-3 は従来 OPN の範囲を明記し、基本 index/data、24h・25h の 10 bit Timer A、26h の 8 bit Timer B、27h の始動・フラグ制御を説明する。これを基本バンクの試験入力にする。OPNA 拡張と CSM の標本は既存ソフト OPNA と固定 fmgen の一致を回帰基準にし、物理割込み到着と DOS の許容遅延は別に測る。[合成器と参照標本](SYNTH_OPNA_DESIGN.md)

UNDOCUMENTED io_sound.md の A466h は満杯 32 KiB・空、A468h は bit 5 で要求許可・bit 4 に 0 で ack、A46Ah は許可中の書込み値 ×128 byte を残量閾値、禁止中は幅・左右の設定、A46Ch は byte 入出力とする。この列を FIFO 段の通常試験に使う。閾値を飛び越す消費や ack 直後の再発火は同じ短い列を実 86 で測って決める。DOS ソフトごとの許容値は資料にも合成標本にも含まれない。タイマ駆動の曲を受ける段で上記 Ra266 の 60 秒窓を採り、最短周期、注入遅れ、曲速、発音までの外部収録をユーザーの聴取と突き合わせて決める。40.63 ms は実測前の設計予算である。

製品にはゲスト時計・転送の進捗と二窓の過負荷判定を残し、受入用の採時と欠落・無音・遅着の内訳は kdebug 対部品と外部収録に移す。


## ユーザー決定 (2026-11-28) — DOS の中のソフトの OPNA の合成の場所

ユーザー「Aだが、予算しだいで処理の内容の確認をします。」— **A を採る**: ソフトの音源のセッションだけ DOS を区切って走らせ、各区切りで呼び出し元の状態に戻して既存のユーザー側の OPNA → snd2 の合成を回す (相談役 sol の推奨、~/os32-tmp/run/rev-sound/CONSULT.md)。B (IRQ の中で合成) と C (v86_call の中のカーネルの合成、固定の領域 +326 KiB) は採らない。
**予算の確かめ**: 切り替えの手間 (区切りごとの状態の戻し) と IRQ0 の最悪 ≤200 µs・IF=0 の最長 ≤1,450 µs・最大の供給の間隔 <17.41 ms を kdebug の側で測る。足りない時は POLICY_DEV §10「予算が足りない時の棚卸し」に従い、処理の内容をユーザーが確かめる (ユーザーの言葉「予算しだいで処理の内容の確認をします」)。
