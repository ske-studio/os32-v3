# PCM 専用機の V86 ゲストに提供する PC-9801-86 互換音源

状態は **草案**。対象は PC-98 の DOS ゲスト一セッション。着手時期は未定。[ROADMAP](../../ROADMAP.md) の将来項目と [U32](../../tasks/restructure/DECISIONS.md) に基づく。[AV 設計 §9](AV_HAL_DESIGN.md) のセッション・発音経路にボード PCM の再生を追加する。

## 起動時の選択

| 起動時に得た証拠 | V86 セッションの動作 |
|---|---|
| 0188h 系と 0288h 系がともに ABSENT、CS4231 の snd2 再生 backend が利用可能 | ソフト 86 の候補。begin で前景所有と stream を取得してから bitmap を切替。競合は BUSY として戻す。 |
| 実 86 または 26K | 搭載機のゲスト I/O と IRQ 配送を維持。26K を 86 として広告しない。 |
| 118 | 実 FM を素通しにし、118 の実 PCM を使える構成を保つ。実 FM と PCM の物理線共有は IRQ 設計の後段。両者の併用を実機受入に含める。 |
| probe 不明、出力なし、未対応機種 | 自動選択を見送り理由を記録。従来の V86 経路を使う。 |

起動時に機種能力を固定し、各 begin では利用権だけを取り直す。CS4231 の物理線の到着回数は機種判定に使わない。

## ゲスト I/O と時間の所有

PC-98 の V86 monitor が SOFT セッションに限り TSS I/O bitmap の 0188h–018Fh、A460h、A466h–A46Eh を禁止側に設定する。#GP の IN/OUT では既存の観測・実ポート転送より先に対象を消費する。A462h/A464h は既存ポリシーに従う。発音の時刻、タイマ満了、FIFO 消費を同じ単調時刻で比較し、同時刻では期限を反映してから命令を処理する。

| 対象 | monitor が答える操作 |
|---|---|
| 0188h/018Ah、018Ch/018Eh | 各 bank の index を保持。data 書込みは時刻と通番を付ける。status とタイマは monitor で即答し、合成器に依存する data 読みは AV §9 の IOREAD で同じ命令に返す。奇数は FFh／書き捨て。 |
| A460h | AV §9 の ID と拡張許可を返す。許可解除時は bank 1 を隠す。 |
| A466h、A468h | FIFO 状態／音量、運転・停止・リセット・レート・割込み許可と要求を管理。 |
| A46Ah、A46Ch | 制御状態に応じて形式・左右の指定または割込み閾値を設定し、再生データを byte 順に受ける。 |
| 範囲内の未定義番地と A46Eh | 初版案は FFh／書き捨て。実測・資料で機能が判明した番地だけ仕様化する。 |

幅 2/4 は AV §9 の連続 byte 順。範囲をまたぐ命令は全 byte の担当とキュー空きを先に確認する。REP OUTS は一要素ごとに確定し、停止時点の残数と index から再開する。同期読みや転送待ちで確定前の EIP を進めない。正常終了・fault・kill・begin の途中失敗を同じ解放経路へ集め、期限を無効化し、bitmap、前景所有、stream を回収する。古い世代の応答を次のゲストに渡さない。

## FIFO から CS4231 まで

仮想 FIFO は 32 KiB の byte リングとし、空／満、再生位置、閾値要求は monitor が所有する。経過時間×選択レートの整数剰余を保持し、完全な入力フレーム単位で消費する。停止中は進めず、形式やレート変更の直前に旧設定でその時刻まで進める。空なら無音とし残量を負にしない。満杯への書込み、閾値ちょうど、要求解除後の再発火、端数 byte の扱いは実 86 の短い I/O 列を基準に固定する。

monitor は消費した PCM と時刻付き FM イベントを順序付きでアプリに渡す。転送用キューとゲスト可視 FIFO は別に持ち、drain の頻度でゲストの残量を変えない。転送枠の不足は run の命令境界でアプリへ戻して解消し、音声の欠落を計数する。既存 v86s_fm_drain のイベントに PCM byte を一個ずつ詰めると syscall とキューを圧迫するため、PCM は時刻・形式・長さを持つ一括転送を提案する。公開 ABI の表現と採番は実装前レビュー事項。

V86 アプリが lib/os32_opna の整数合成、PCM の整数レート変換、libos32snd の加算・飽和、L3 pump を順に行い、一本の snd2 stream から CS4231 に出す。PC-98 のポート知識は monitor に置く。描画・合成・コピーを IRQ スタックに載せない。[合成器設計](SYNTH_OPNA_DESIGN.md)

## IRQ12 の成立と配送

タイマ A/B の満了フラグと対応出力許可、FIFO の閾値要求と許可を個別に保持し、論理和で一つの仮想線を作る。ゲストの音源 ack は対応要因だけを消す。CS4231 の物理 PI は既存 handler が ack して snd2 を進める。PI 単独でゲスト pending を立てると、再生 period のたびに DOS の演奏が進むため、この組合せを負の試験にする。

1 kHz の期限照合と I/O 復帰点で満了を記録し、非 VM 時は IRR に保持する。VM 復帰で仮想 IF・STI shadow・両 IMR・優先順位・ISR を検査する。スタックとベクタの検査、フレーム更新の成功後にだけ IRR を消費し slave IR4 と master IR7 を in-service にする。既定ベクタは INT 14h。一復帰につき一件、同時の IRQ0 を先に通す。仮想 EOI とマスク解除で残存要求を再評価する。物理 EOI は既存 dispatch complete に一任する。[IRQ 設計「後段の実音源共有と仮想 PIC」](../../design/kernel/irq/irq.md)

## Ra266 の受入窓

初回の目標は整数 FM 6 声＋SSG 3 声＋ステレオ FIFO 一本を出力 44.1 kHz、period 256、lead 3 で 60 秒。これは未測定の目標。一区間は 5.80 ms、3 区間は 17.41 ms。実際の遅延は guest OUT から出力位置までのフレーム差で測る。タイマ予定時刻と注入時刻の差を別に記録し、IF/IMR によるゲスト側保留を除いた最大・分位を示す。1 ms 照合より短い周期では status の経過計算と IRQ の合流回数を記録する。

PII 266 MHz 上で FM 1→3→6 声、SSG、FIFO、リズムの順に負荷を加え、各窓の合成・pump・I/O trap の cycles、CPU 比率、最大 pump 間隔、underrun、DOS 演奏時間を採る。合格は欠音 0、pump 間隔 ≤768 frames、IRQ0 最大 ≤200 µs、対象 HAL の IF=0 最大 ≤1450 µs。44.1 kHz で失敗した組合せは出力 22.05 kHz の整数変換案を別窓で測り、ゲスト FIFO レートとタイマ速度を保つ。製品上限は合格した声数・レートの組で記載する。

## 実装の分割と先に失敗させる検査

各行は半日〜一日の受入単位の案。行数は製品側の概算。既存 IRQ12 S4 と L3 実機 pump の測定を基準窓にする。

| 段 | 概算 | 先に赤にする入力と期待結果 |
|---|---:|---|
| V8/V2 選択・捕捉 | 150–250 行 | 118・26K・実86・UNKNOWN は bitmap 差分ゼロ。PCM 専用だけ対象 OUT の実ポート回数ゼロ。fault 後に元の bitmap。 |
| V1/V4 タイマと PIC | 200–350 行 | PI 単独で注入ゼロ、A/B と FIFO 同時で一件。IF=0、マスク、壊れた stack で IRR を保存。EOI 後に残存要因を再評価。 |
| ボード FIFO | 200–350 行 | 偽時計で閾値の前後・満杯・折返し・途中停止・速度変更を検査。異なる drain 間隔で同じ残量・IRQ 列。 |
| Q1/V3/V5 転送と寿命 | 各 150–300 行に分割 | キュー満杯、REP の途中 yield、応答再試行、kill 後の再開で重複・漏れゼロ。旧 sid を拒否。 |
| V6 発音と受入 | 200–350 行＋実機窓 | 左右の既知 PCM と FM 同時発音の整数出力を比較。NP21/W で DOS のタイマ演奏・FIFO 補充、Ra266 で上記負荷、実音源搭載機で素通しを対照測定。 |

各段は製品入口を通る登録検査と、機種条件反転・物理 PI 誤注入・FIFO 二重消費など対応する変異を同梱する。実機の音量・発音遅延・118 の同時利用はホスト試験と別に記録する。

## 実装前に確認する範囲

ユーザー判断は初版を再生専用とするか（録音、外部入力の要否）、受入対象の DOS ソフト、Ra266 が目標未達の場合に許容する出力レート・声数。整数演算を前提とし、浮動小数点を必要とする変更は事前に相談する。実機の IRQ 線、FIFO の境界挙動、負荷上限は測定で決める。
