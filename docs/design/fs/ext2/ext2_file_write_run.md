# fs/ext2/ext2_file_write_run.inc — 予約済みデータの範囲書込み

> 状態: **現行 (2026-11-01)**

`ext2_write_run_window` は [同期書込みの窓](ext2_file_write_batch.md) の
最大64件を先に予約し、その窓内だけで全1KiBのデータを最大32本にまとめて発行する。
stream/create/全置換は同じ発行口を使う。次窓の予約は、現在の窓のmetadataを
commitした後に開始する。作業領域の寿命・公開順序・後始末はbatch側が所有する。

## 区間の切出し

予約成功分の論理順に、物理番号が+1で、呼出元buf上も連続する全ブロックを
`ext2_write_data_blocks(ctx, first, 1..32, src)` へ渡す。既存と新規を区別して
区切らず、物理的な隙間・端数・窓末尾・32本で区切る。表境界自体は区切りに
しないが、新しい表の割当がデータの物理配置に隙間を作ればそこで分割する。
64本の新規連続データは32本ずつの2要求、33本は32本と1本の2要求になる。

全ブロックは呼出元bufを直接使い、大きなdataコピーや新しい保持配列を作らない。
端数だけ既存の`ext2_g_dat`を使う。新規ブロックは全0から、既存ブロックは
`ext2_read_data_block`で読んだ内容から要求範囲だけを更新して1本で書く。

## 完了と失敗

要求全体が成功した後だけ`ext2_write_data_done(ctx, blocks)`を進め、完了byte数と
inodeサイズを更新する。要求途中・最終完了の失敗はいずれも要求全体を未完了とし、
後続data要求を発行しない。旧サイズ内の既存dataが部分的に変わることは許容する。

予約/NOSPCでは既に予約できたprefixを発行できる。予約中のmetadata読取り失敗は
fs_errorに従いdataも発行しない。data失敗時はbatchが未完了予約をRAMでtrimし、
成功prefixをdata→bitmap→下位表→上位表→inodeの順で公開する。
create/全置換では当窓全体を取り消し、保持をabortして既存の未公開inodeの後始末へ渡す。
metadata失敗後の逆書込み・解放や、失敗要求内の成功セクタ数の推定は行わない。

## 検証と落とし穴

`tools/tests/test_ext2_write_run.py` は製品ext2とRAM Device模型で、新規/既存の
1/2/32/33/64本、非連続、表割当の隙間、端数RMWとゼロ埋め、65ブロックに触れる
非整列64KiBの窓境界を検証する。D1を温めた書込み後の再read/statも確認する。
各Device要求の前後と全512B境界に一過性/持続故障を注入し、失敗run全体の未計上・
後続停止・参照取消・返却prefixを照合する。成功像は`e2fsck -fn`無修正、停止像は
媒体の参照先bit・重複所有・無関係ファイルを検査し、許容された漏れ/孤児/集計差/EOF外参照の
修復後に再度`e2fsck -fn`が通ることを要求する。
完了済み512Bが保持される模型であり、電源断時の装置内キャッシュの並替えやセクタ破断は対象外。
EOFや窓の最後の端数を全ブロックのrunへ混ぜると、呼出元bufの範囲外を読むので注意する。
