# iso9660_dir_read.inc — ディレクトリのまとめ読み

> 状態: **現行 (2026-10-31)**

検索と一覧は `iso_dir_sector` を使う。走査ごとの `IsoDirScan` は先読み可否と
前回利用した窓の終端だけを持つ。永続メモリは増やさず、既存の 32KiB 窓と
4 本のセクタ LRU を共用する。ctx と媒体の契約は `iso9660`。

1. LRU を先に調べ、hit の時刻・件数を更新する。
2. miss なら共用窓を調べる。窓の補充は必要 LBA から最大 `ISO_RA_SECTORS` 本、
   ディレクトリの切上げセクタ数と volume の残量まで。サイズ 0 は読まない。
3. 要求されたセクタだけ LRU に写す。先読みした全セクタを登録しない。
   窓のコピーは `ra_hits`、成功した補充は `ra_fills` に数える。
   `scache_fills` は物理単セクタ読みだけに数える。

LRU の探索・victim 選択・登録は、ファイル端の `iso_get_sector` と共通。
`iso_fill_sector` は成功時だけ valid を立てる。

## 落とし穴

- callback が窓を置換し、前の窓の範囲内で窓 miss になったら、その走査の残りは
  単セクタ LRU 経路にする。16 セクタ走査は最大 16 コマンド・31 セクタ転送
  （callback 自身の I/O を除く）。窓を毎セクタ補充しない。
- 補充前に窓を無効化し、失敗したらその走査の先読みを止めて必要セクタだけ
  読み直す。部分的なデータを公開せず、無関係な LRU・パスは残す。
- 世代確認を補充や再読の前後へ増設しない。既存の入口・結果確認に任せる。

冷状態・再入なしの全走査は 32KiB で READ(10) 16→1、64KiB で 32→2。
先頭セクタで発見する検索は最大 30KiB 余分に読むため、実機で別に測る。
試験は [cd_read_host_dir](../../tools/tests/cd_read_host_dir.md)。
