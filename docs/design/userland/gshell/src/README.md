# userland/gshell/src/ — 設計
> 状態: **現行 (2026-10-31)** — 出所: API_CONTRACTS・DESIGN (D1 で移した)
ソース: `userland/gshell/src/`

体制: WM = gshell 内 (Rust)、クライアント = 共有ライブラリ帯域 (Rust, no_std)、
カーネル側は `gui_call` 1 本と syscall 境界ポンプのフックだけ (C)。

---

### T8. WM の実行文脈 — 2026-09-05 追加 (誰がいつ描き、いつ待つか)

WM (gshell) はシェル帯に常駐する CPL=0 のコードで、アプリ実行中は**アプリの syscall の
中でしか走らない**。走る文脈は 4 つで、それぞれ許される操作を固定する。

- [X1 ハンドラ・X2 COMMIT・X3 WAIT (handler.rs)](handler.md)
- [X4 ポンプ](#pump)

- **WM 所有 UI の進行は X3**: アプリは下記の park 条件で WM へ制御を返す。
  X4 は入力の退避・カーソル更新を行うが、メニュー等の状態機械は進めない。
  KAPI を呼ばない USER ループの停止と STOP の既知の限界は T6 を参照する。

---

### visible

- **可視領域** (2026-09-05): WM はウィンドウごとに「クライアント矩形 − 上にあるウィンドウの
  矩形」を**互いに素な矩形の集合** (最大 16) として持つ。`Paint` は「損傷 ∩ 可視領域」の
  各矩形につき 1 件で、**`Paint` の矩形は常に可視領域の内側**。したがって背面ウィンドウが
  描いても前面を上書きしない (クライアント側は G2 の基底クリップで守る)。矩形が 16 を
  超えたら WM は残りを次の周に回す (落とさない)。

- **露出の再描画**: 移動・非表示・破棄・Z 順変更で露出した領域は、WM が可視領域を計算し直し、
  下になっていたウィンドウ (とデスクトップ) に露出分の `Paint` を発行する。順序の管理は
  要らない (矩形が互いに素なので、どの順で描いても結果は同じ)。

| 項目 | 値 |
|---|---|
| 可視領域 | 互いに素な矩形 16 / ウィンドウ。超過分は次の周 |

### lib

- [起動時システムパレット設定 (wm.rs)](wm.md#システムパレット)

- アプリが走っていないとき (gshell 単独) は、gshell 自身のループが X3 と同じ周期を回す。

WM は再開直前にもキーボード入力と STOP を
処理する (exec_start が同じ周の最初の X3 より後に戻る場合にも先に消費)。

- gshell の「CUI へ」= `gfx_shutdown` (`leave`) + `sys_switch_shell("/sys/shell.bin")` + exit。

- WM 自身のウィンドウ (デスクトップ・フォルダ・ターミナル) は gshell 内で同じ API を使う
  (経路が直接呼び出しになるだけ)。

### fullscreen

- [フルスクリーン前後のパレット退避・復元 (wm.rs)](wm.md#パレットの退避復元)

- 全 16 色とラスタ効果 (走査線ごとのパレット切替) が要るゲームは**フルスクリーン占有**
  (ROADMAP) を使う。

### chrome

- リース中、16 色バックエンドの WM は**クロームを 2 色 + パターンで描く**: 文字と枠は
  `TEXT`、面は `WINDOW`、影と無効面は `DITHER50`、フォーカスは `DOTTED`、アクティブ
  タイトルは黒地に白文字、非アクティブは白地に黒文字、デスクトップは市松。Windows 1.x/2.x
  のモノクロ表示と同じ骨格で、`Style.flags` の 4 つはこのために用意してある。

- 枠・タイトルバー・閉じるボタンは WM が描く。アプリが触れるのはクライアント面だけ。

- [マウスカーソルのスプライト移動 (cursor.rs)](../../../../../userland/gshell/src/cursor.rs)

### modal

#### U4. モーダル (状態機械)

WM が入力の宛先をそのダイアログに限定する。親は `Paint` を
  受け続ける (再描画は止まらない)。
  **例外 (2026-09-10 追記)**: 限定されるのは**モーダルが開いてから始まった入力**である。

- 完了は `Modal{dialog, result}` イベント。**入れ子ループは存在しない**。
- 標準ダイアログ (メッセージ / ファイル選択 = 既存 libos32filer 相当) は WM 側に置く。

| 採用 | 解く欠点 | 386 でのコスト |
|---|---|---|
| **モーダルは状態機械** (WM が入力宛先を限定、完了はイベント) | 入れ子ループと再入 | なし |

### timer

#### U5. タイマ

PIT 10ms 粒度。

上限 8 / アプリ。`Timer` イベントで届く。`OP_WAIT` は次のタイマまでで起きる。

- [set_timer / kill_timer (timer.rs)](../../../../../userland/rust/libos32gui/src/timer.rs)

| 項目 | 値 |
|---|---|
| タイマ | 10ms 粒度、8 本 / アプリ |

### slot

測定条件: WM は入力を取り込んだ tick を `serial` ごとに直近 64 件、スロットの予備領域
(T2 の約 5KB のうち 256B) に記録する (デバッグ用だが契約の一部)。
