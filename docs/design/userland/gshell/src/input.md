# userland/gshell/src/input.rs — ウィンドウ入力配送

> 状態: **現行 (2026-10-31)**

マウスとキーを WM およびアプリへ配送する。

## 落とし穴

- **ボタンエッジの所有**: syscall 境界のポンプが先に `prev_buttons` を進めると、WM がドラッグ終了や閉じる操作を見逃す。
  `userland/gshell/src/input.rs:690` は WM が扱うエッジを据え置き、次の WM 処理へ渡す。
  `wm_owns_edge` (`:796`) の判定順を WM 側と揃え、ドラッグ・背面窓・閉じる操作とクライアントへの配送を確認する。

## 設計 (D1 で移した)

> 出所: API_CONTRACTS・DESIGN

- 順序は FIFO。入力イベントには `serial: u16` が付く (Wayland の serial。押下と解放、
  フォーカス変更の突き合わせに使う)。

- **保持できる件数と溢れ** (2026-09-05 再改訂。「欠落しない」保証は取り下げ): アプリが
  `OP_POLL` を呼ばない間に保持できる待ち行列型は **リング 128 件** + その先のカーネルの
  キー待ち行列 **32 打鍵** (`KBD_BUF_SIZE`。満杯時は新しい打鍵を黙って捨てる。印字可能な
  打鍵は `Key` + `Text` の 2 件になるので、リング側は最悪 64 打鍵分)。空きが無ければ WM は
  (1) リング内の `Pointer` を落とし、(2) それでも無ければ X4 はカーネル待ち行列から読まない。

**X3 は STOP の救済を優先して raw を読み続ける** (2026-10-02 改訂、T6)。
  CTRL+STOP make は捕捉し、それ以外の配送不能な raw は dropped / OVERFLOW に加算して捨てる。
  raw 満杯時も CTRL+STOP make は末尾の1件を置換して保持し、置換された1件を数える。

WM は取り込みのたびに
  その差分をヘッダの `dropped: u16` に足し、`OVERFLOW` を立てる。したがって**打鍵の欠落は
  WM の取り込み間隔中に起きた分も含めて全部通知される** (打鍵以外: マウスは状態のサンプル
  なので、取り込みの間に完結した押下 + 解放は失われ、数えられない。これは限界として明記)。
  アプリは次の `OP_POLL` で `OVERFLOW` と `dropped` を受け取り (受け取った時点で WM が消す)、
  入力状態を未知として扱う (押しっぱなしの前提を捨てる。押し上げは元々届かないので
  `kbd_is_pressed` で読み直す)。長い処理の途中で `OP_POLL` を挟むのは、この上限に当たらない
  ための作法 (U3)。

X3 は宛先リングに空きがなくても raw を読み、STOP make 以外を dropped / OVERFLOW として捨てる。
  raw 満杯時の CTRL+STOP make は末尾を置換し、捨てた1件を数える。X4 の空き待ちは維持する。

OWNER_EXIT の内部 arg は EXEC_KIND_*。ABORTED (3) は窓の除去前に WM の
abort_seen と退避 raw の CTRL+STOP make を捨てる。

1 個の STOP が前景変更後の相手を二度目に畳まないための内部契約で、
公開 KAPI の変更はない。

- ドラッグ中は WM が XOR 枠だけを描き、ドロップ時に 1 回 `Configure` + `Paint` (DESIGN R2)。

- 規則 (2026-09-05 改訂): **FEP が消費しなかった `Key` は常に届く。印字可能な入力には加えて
  `Text` が届く。** テキストボックスは `Text` で挿入し、`Key` で編集キー (BS / DEL / 矢印 /
  HOME) とショートカットを見る。ゲームは `Key` だけを見る。

- 押下・押し上げ (`down=true/false`) は raw リングから `Key` として配送される。
  WM が消費するショートカット等は配送対象外。実装は
  [`input.rs:393・565–566`](../../../../../userland/gshell/src/input.rs) の `capture_keyboard`。
  クライアントの編集操作は押下だけを扱う。

開く前にアプリへ配った `Button` 押下と対になる**離し**は、モーダル中に起きてもその押下を
  受けたアプリへ届く (WM は押下の配送先を左右ボタンごとに捕捉し、離しは同じ相手へ返す)。
  押したままダイアログを開くアプリでも押下と離しが必ず対になる。モーダル中に新しく
  ダイアログ上で押した分は従来どおりダイアログだけのもの。

| # | 決定 | 理由 |
|---|------|------|
| R2 | **ウィンドウ移動は XOR 枠だけ動かす**。ドロップ時に一度だけ再描画 | 実体を動かすと毎フレーム露出領域の再描画が発生し、386 で最も重い操作になる |
