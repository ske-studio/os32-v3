# tools/tests/fatfs_read_cache_host.c — FatFs 読み取り保持の試験

> 状態: **現行 (2026-10-31)**

製品 fatfs_vfs.c と実 FatFs を組み、diskio 境界だけをメモリ媒体にする。
FD 世代・機器照会・メモリ確保はホストの境界スタブ。製品ロジックは複製しない。
基準側だけ従来の要求ごとの open/seek/read/close を実行する。
実行は [Python 入口](test_fatfs_read_cache.md)。

FAT12/16/32、512/1024B、連続/断片化の12条件で、深いパスの1024クラスタを
1クラスタずつ読み、基準と保持版の要求数・戻り値・全バイトを比較する。
FatFs の関数入口計測で get_fat を数え、523,776→1,023回を要求する。
open=1024→1、seek=1024→0、read=1024、umount で保持 close=1 を確認する。
disk_read の LBA/count 列を記録し、作成時に記録したファイル領域から
データ要求とメタデータ要求を分けて呼出し回数・総セクタ数を表示する。
共有窓と実装置キャッシュを含まないため物理 READ 回数とは呼ばない。

位置試験は128B刻み、境界跨ぎ、前後 seek、EOF超過、空ファイル、size=0、
同パスの別 FD 相当、一括読みの位置0を比較する。LRU は4本交互と5本目の追い出し、
最近使ったキーの保持、別綴りとその更新後の内容を確認する。
更新は上書き・伸長・truncate・空への切詰め・unlink/再作成・祖先 rename・
mkdir/rmdir と失敗時を通す。パス・種別検査で拒否した場合の保持も確認する。

open/seek/read に4種の全破棄エラーを注入する。通常の失敗は該当だけを破棄する。
実 disk_read の途中失敗で部分読込長があっても VFS が負値を返すこと、
後続が開き直すことを確認する。読み専用 close の失敗、書き込み close 失敗、
既存の書き込み回復での再マウント失敗も通す。既存のエラー優先順位は
[stat ホスト試験](fatfs_stat_host.md) でも維持する。

物理 fd1/pdrv0 の世代差、読み取り途中の世代進行、同じ FD 内の複写、
2マウントの独立、HDD の最大4本、umount 後の close がないこと、
mount 失敗と再 mount の空状態を確認する。
