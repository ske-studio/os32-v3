# PowerPC の QEMU の受入の台本 — 落とし穴

> 状態: **現行 (2026-11-19)** — 出所: KAPI の提供者無しを埋める段 (マウス・KCG・表示の公開 P6・`sys_ver_info`・PCI) で、2026-11-19 の 1 日に受入と CI が落ちた記録

対象: `tools/accept/ppc_*.py`・`tools/ppc/*_run.py`・`tools/checks/ppc-*-guest.py` と、`userland/ppc/*prob.c` の probe。
型 (full_only・rc=3・TMPDIR・変異ごとに別の像・NULL を渡さない・出力先を 0 でない値で始める) は [PPC_KAPI_FILL_DESIGN](../../../decisions/ppc/PPC_KAPI_FILL_DESIGN.md) の受入の節に従う。この 1 枚は、その型を守っても落ちた所だけを並べる。

## 1. 画面を撮る時

| 落ちた形 | 原因 | 直し方 |
|---|---|---|
| カーソルの反転を、出す前・出した後・消した後のセルで比べたら、消した後が合わない (マウス) | 3 回の撮影の間に、probe の出力や RSH の行で画面が 1 行流れ、比べたセルの中身が入れ替わった | probe が各状態でキーを待ち、ホストが撮り終えてからキーを送る。撮影の間に端末へ何も出さない |
| `echo` の出力の行の画素の照合が落ちる (表示の公開 P6) | 決まった秒数 (`settle(.5)`) で撮ったので、入力の途中 (`echo restoredshutdo_`) や、カーソルが行の頭の文字に重なった時点を撮った | 秒数で待たない。照合そのもの (字形が画素で一致) を条件にして待つ。比べる中身が字形そのものなら、偽の合格にはならない |
| 次のプロンプト `>` を待って時間切れ (P6) | link-sh で `> ` が付く行は、RSH から送ったコマンドの写し。キーボードで打った行の後には、シェルはプロンプトを出さない | 待つ条件は、その経路で本当に出る物から決める。キーで打った行は、出力の行の字形が一致するまで待つ |

## 2. キー入力

| 落ちた形 | 原因 | 直し方 |
|---|---|---|
| `echho alive` (CI の `check-ppc-usb` で 1 回だけ) | 負荷で USB のキーの間合いがずれ、1 打が 2 回入った (手元では 3 回とも通った) | 1 回なら揺れとして回し直す。probe がキーを順に読む所は、前の段と同じ文字を読み飛ばす (`while ((key = kbd_getkey()) == 's') {}`)。タイプマティックの繰り返しも列に積まれる (`input_usb.c`) |

## 3. 変異の目印

目印 (置き換える文字列) が一意でなくなると、台本は始まる前に `mutation anchor must be unique` で落ちる。製品は正しいのに赤になる。

| 落ちた形 | 原因 | 直し方 |
|---|---|---|
| 共有メモリの受入の変異が、`'pointer': (frozenset({` を見つけられない | slot を公開すると、`sdk/kapi_target_ppc.py` の PROVIDER_GROUPS から、その組の行が消える | 組の名前に頼らず、表の頭 `PROVIDER_GROUPS = {` の直後に足す (`tools/ppc/test_kapi_binding.py` の `insert_group` と同じ形) |
| 互換の試験の「提供者無しの問い合わせ」の見本が成り立たない (`mouse_available`、その前は `pci_count` の隣の行) | 見本にした slot を、後の段で公開した | 見本は、公開の予定が無い組 (`snd_bgm_is_playing` など) から選ぶ。公開の段の完了条件に「見本・目印に使われていないか」を `rg` で確かめる行を入れる |
| マウスの受入の変異 default-bounds の目印 `if (target.width && target.height)` が無い | 先に入った段で、`target` が `console_text.c` の static に移った | 取り込み (merge) の後に、変異の目印を含む受入を回す。目印は、意味の近い 1 行を選ぶ |
| 起動の列の形の試験 (`test_ppc_terminal_work.py`) が落ちる | 固定された並び (hostfs → usb → work → input) の途中に 1 行を足した | 足す行を、固定の並びの外 (前か後) に置く。並びの意味が変わる時だけ試験を直す |

## 4. 期待の出所

| 落ちた形 | 原因 | 直し方 |
|---|---|---|
| `ver` の GFX の行が `800x400` (期待は 800x600) | 製品の共通の不具合: packed 系の初期化が `gfx_current_height` を更新しない (`gfx/gfx_core_init.inc`)。x86 の GeForce にも関わる | 期待を観測に合わせない。期待は QEMU の画面の大きさ (同じ probe で読める) から取り、食い違いは製品の不具合として本線に渡す |
| 表示の復帰の後も、端末の世代が 1 のまま (P6) | 製品の不具合: OF の unbind で adapter の世代が進まず、復帰が古い target のまま「戻り済み」と判断した | 受入は「世代が進む」ことを見ていたので見つかった。復帰の受入には、文字の画素だけでなく世代の番号を入れる |
| 設計の受入の項目が、PowerMac では起こらない (シェル経路の終了・`exec_kill`) | PowerMac は `sh.bin` を通常の USER アプリとして起動し、kill の呼び手も USB の CTRL+STOP も無い | 起こらない場合の受入は作らない。外した項目と理由を、依頼と報告に 1 行で残す |

## 5. CI と回す場所

| 落ちた形 | 原因 | 直し方 |
|---|---|---|
| `ppc-qemu` の 1 本が 30 分の上限で落ちる (2 回) | 新しい受入に `tools/checks/weights.json` の値が無く、予算の 1200 秒で割り振られて、重い受入と同じ 1 本に重なった | 受入を足す段で、`weights.json` に見積もりの秒を足す (近い受入の値)。CI で測れたら `--merge` で作り直す ([os32-ci-inventory](../../../../.claude/skills/os32-ci-inventory/SKILL.md)) |
| 手元の `check-ppc-usb` が時間切れ (rc=124) | 4 コアの機械で、実装者のビルドと host の検査に重なり、負荷が 11〜12 になった | QEMU の受入は、本線の 16 コアの機械 (pc98emu のセッション) に頼む。枝・SHA・検査の名前を渡し、rc・所要・GREEN/RED の行・落ちた所の写しの文字を返してもらう |
| 実装者の報告で QEMU が「未実行」 | 実装者の sandbox ではループバックのソケットが開けず、QEMU を起動できない | 実装者は、変異ごとの像の sha が別々であることまでを確かめる。QEMU は PM が回す |

## 6. 落ちた時の切り分けの順

1. 製品の不具合か、台本の不具合かを、写し (`*.cells`・`*.ppm`) の文字とシリアルの末尾で分ける。11-19 の落ちのうち、製品の不具合は 2 件 (§4 の上の 2 行) だけで、残りは台本・目印・CI の割り振り・負荷だった。
2. 台本なら、§1〜§3 のどれかに当たるかを見る。待つ条件が「その経路で本当に出る物」になっているか、目印が今のソースで一意か。
3. 直した後は同じ機械で 1 回、負荷の違う機械 (CI か pc98emu) で 1 回通す。
