# tools/ci/time_inventory.py — CI の検査の所要の棚卸し

> 状態: **現行 (2026-11-18)** — ユーザー決定 2026-11-18 (QEMU の段を割る・「本線が再開した時にまた重くならないように棚卸し出来るように」)。決まりは [POLICY_CI](../../../POLICY_CI.md) G10、手順はスキル `.claude/skills/os32-ci-inventory`。
ソース: `tools/ci/time_inventory.py`・`tools/tests/test_ci_time_inventory.py` (検査 `ci-time-inventory-host`)。重みの作り直しは `tools/checks/calibrate_weights.py`、割り振りは `tools/checks/run.py` の `shards()`。

## 1. なぜ要るか

CI の待ち時間は、一番遅いジョブで決まる。検査はシャードに割って並べるが、割り振りは検査ごとの重み (`tools/checks/weights.json` の秒) で釣り合いを取るので、重みが実態とずれると 1 本のシャードに重い検査が集まる。2026-11-18 に実際に起きた事:

- 関門を変異込みにした後も、重みは変異なしの計測のままだった。x86 の 6 シャードの検査の秒の和は 40.8〜78.5 分で、最大 ÷ 最小が 1.92。重みと実測が 2 倍以上ずれた検査が 92 本 (例: `splash-probe-host` は重み 49 秒・実測 1,320 秒)。
- PowerPC の QEMU の検査 12 本は 1 本のジョブで直列に回り、53〜61 分かかっていた。重みは無く、宣言の予算の値で代用していた。
- QEMU の検査は x86 のシャードでも名前だけ回り、1〜2 秒で終わる (ゲストを起動しない)。この行を標本にすると、重みが 1 秒になる。

その後に分かった事 (同じ日の最初の回、詳細は `docs/design/tools/ci/gate.md` §5-1): キャッシュは枝ごとで、PowerPC のクロスコンパイラが main のキャッシュに無いと新しい枝の最初の回で各ジョブが 13〜15 分かけて組む。x86 の重みを秒の中央値で作り直しても揃わなかった (記録の秒は並んで回る検査に左右される)。QEMU の検査は x86 のシャードの割り振りでも重みを持つので、実測の重みが無いと予算の値が偏りの元になる。

## 2. 数える物

入力は、成果物 `check-times-<SHA>-<i>` (build の x86 のシャード) と `check-times-<SHA>-ppc-qemu-<i>` (check の QEMU の段) の中の `check_times.tsv` (検査・秒・終了コード)。成功した行だけを数える。

| 出力 | 中身 |
|---|---|
| シャードの表 | 組 (x86・qemu-ppc) ごとに、記録・検査の本数・検査の秒の和。偏り = 和の 最大 ÷ 最小 (記録が 1 本だけ・0 秒の記録がある組は出さない) |
| 重い検査 | 検査ごとの秒の中央値の上位 15 本と、全体に占める割合 |
| 重みのずれ | 中央値と重みが `--drift` 倍 (既定 2.0) 以上違う検査と、重みの無い検査。30 秒未満どうしは出さない |

QEMU を要る検査 (宣言の `env` に `qemu-ppc`) の中央値は QEMU の段の記録だけから、ほかの検査は x86 のシャードの記録だけから取る (`calibrate_weights.py` と同じ決まり)。

検査の秒は、同じシャードで並んで回るほかの検査に CPU を取られた分を含む (シャードの中は並列)。同じ検査でも回ごとに ±5 割ほど動くので、1 回の記録で細かく合わせようとしない。複数の回の中央値を使う。

## 3. 判定

| 終了コード | 意味 |
|---|---|
| 0 | 手当ては要らない |
| 1 | どれかの組の偏りが `--max-imbalance` (既定 1.5) を超えた、または重みのずれた検査が 1 本以上ある。重みを作り直す |
| 2 | 記録が 1 行も無い (成果物の取り違え) |

棚卸しは関門ではない (CI では回さない)。道具の判定の部分は、検査 `ci-time-inventory-host` が偽の記録と変異 15 本で確かめる。

## 4. 手当て

1. `python3 -B tools/checks/calibrate_weights.py [--merge] <DIR>...` で重みを作り直す (成功した回を 3〜5 回分)。`--merge` は、渡した記録に出てこない検査の重みを残す (QEMU の段の記録だけで QEMU の検査の重みを更新する時)。QEMU の段はシャードの中が直列なので、秒がそのまま重みになる。x86 のシャードは並列なので、作り直した後に必ず CI の実時間で前後を比べ、縮まなければ戻す。
2. 割り振りの本数を変える時は、`.github/workflows/build.yml` (x86 は 6) と `check.yml` の `ppc-qemu` (4) の行列と、道具に渡す `i/N` を同じ変更で直す。
3. 1 本の検査が 1 シャードの大半を占める時は、割っても縮まない。その検査の変異の本数と 1 本の所要を見る。

## 5. 範囲の外

ジョブの実時間 (用意・ビルドを含む) は記録に無い。`gh run view <RUN> --json jobs` の開始と終了で読む。check の `ppc-compile` と `static-check` は検査ごとの記録を出していない。
