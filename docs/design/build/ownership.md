# 追跡ファイルの所属と像への依存

> 状態: **現行 (2026-11-27)** — 仕様 §5・§15 の所有宣言と構成別照合。
ソース: `build/sources/ownership.mk`、`tools/ownership.py`、`tests/infra/src_owner.py`、`tests/infra/build_sources.py`。

## 所属を決める単位

追跡パスごとに、実装が提供する機能と、必要な命令・機種仕様・装置から所属を決める。例えば `sys/kern/kprintf.c` の書式処理は共通実装で、出力先は各機種が実装する。SDK の公開物、開発・検査用実装、ビルド定義、文書、資産、第三者の物にも所属を付ける。ホスト試験に使う第三者ライブラリは第三者の所属を保つ。製品にコンパイルされるか、どの像が使うか、SDK に配布するかは別の問いとして扱う。

## P4 の 3の正本と問い合わせ

`python3 tools/ownership.py [--revision REV] -- PATH...` は、対象版の追跡パスについて所有の種類と対象名、ヘッダの役割、公開の有無、判明した像を JSON Lines で返す。現在の問い合わせは `images_complete=false` を返すため、像の空欄だけで依存先なしとは判断できない。ビルドで採用した入力は構成別に展開した Make の選択式と照らす。リンク順、リンカスクリプト、ELF から最終媒体への変換も、ソースの所属とは別に確かめる。[現行の選択式](select.md)

## 自前の一覧を読む箇所

全件の所有を列挙する道具と検査の計画は同じ所有宣言を読む。各検査が扱う入力、SDK の配布物、像のリンク順は個別の契約に従う。

## 追跡パスの所有と配置

作業木では Git の索引のパスと作業木の宣言を、版指定ではその版の木と宣言を組にする。gitlink は第三者の物 1 件、symlink はリンク自身のパス 1 件とし、どちらも先を再帰しない。追跡された生成物にも所属が要る。追跡外の生成物は生成規則の出力としてだけ扱う。個別指定、最も深いディレクトリ既定の順に所属を決める。同順位の異なる値、未所属、消えたパスへの個別指定はパスと宣言元を示して失敗する。

| 配置先の用途 | 許す実装 |
|---|---|
| 共通専用 | 共通実装 |
| CPU・機種専用 | その対象の実装と、配置宣言で認めた共用入力 |
| 装置専用 | その装置の実装と、宣言された共用部 |
| SDK・検査・ビルド・文書・資産・第三者 | 棚の用途に対応する所属。混在する棚では下位の配置宣言で用途を指定 |

配置先の用途の正本は、対象版の build/sources/ に置くディレクトリ単位の配置宣言とする。移動先を含む最も深い宣言から用途を取り、独立に解決したファイルの所属を上表と照合する。適用できる宣言が無い場合と同順位の用途が競合する場合は配置宣言の違反（FAIL）とする。共通専用の棚へ CPU 固有の所属を保ったまま移した場合は配置違反（FAIL）となり、移動先・棚の用途・所属を示す。ファイルの所属を個別指定しても、移動先が許す用途は変わらない。公開ヘッダや同梱資料など別用途の同居は用途と範囲を明示する。

## 構成別のコンパイル登録

PC-98 の製品と部品、PowerMac の core・link・sh・link-sh・shell・neg1 ごとに、条件式とワイルドカードを展開した製品ビルドの翻訳単位を、所属宣言がその構成向けに指定する翻訳単位と双方向に照合する。両集合の差には構成・パス・欠落か誤採用かを示す。存在しない入力、別対象の採用、どの対象にも登録されない製品ソースを失敗とする。

テキストとして取り込む専用入力は親の依存、生成ソースは生成規則と採用先で照合する。診断専用・第三者は採用条件を宣言し、意図して採用しない実装には用途と理由を付す。拡張子だけで翻訳単位を決めない。像の問い合わせで `images_complete=false` の場合は未知の構成・入力を示す。必須構成を展開・観測できなければ ERROR。検査の適用対象は毎回全件とする。

`OWN_PRIVATE_IMPORT` は部品専用の生成マクロヘッダと部品の import メタデータを対応付ける。検査は製品の生成コマンドと、そのメタデータで梱包する ELF の入力を照合する（[層の契約 §9-1・§10](../tools/check_layers.md)）。
