# HAL の契約と実装の配置

> 状態: P1-3 の設計案。A1 で D-4 を確認し、P1-1 の配置台帳に渡す。

## ファイル単位の判断

[対応表](../../tasks/restructure/data/hal_map.tsv)の1行は基点の1ファイルに対応する。P0-6 の HAL・GeForce・直接呼び出しの3表には、同じファイルが操作表の定義、委譲先、呼び出し元として複数回現れる。10本の調査結果に元の3表の確定済みの行を加え、ファイル内の責任と依存先で移設判断を一つにした。たとえば `gfx_core.c` の端末出力は既存の契約を使えるが、同じファイルの `gfx_mode_fits` が PC-98 の表示面だけを特別扱いするため、ファイル全体の判断は P8 となる。

| 仕様 §4 の責任 | 配置と境界の例 |
|---|---|
| HAL 契約・型・共通処理・振り分け | `sys/hal/<分野>/`。入力の `InputOps` は契約、イベントリングは共通処理、`input_getkey` は登録先への振り分け。音源のストリーム状態もここで持つ。 |
| CPU 固有バックエンド | `sys/arch/<CPU>/`。ページ表の走査や RDTSC による計時は CPU 側が提供し、共通の照合・集計には結果を返す。 |
| 機種固有バックエンド | `sys/platform/<機種>/`。PC-98 の表示経路と tick の接続、PowerMac の起動時入力の登録など、機種の配線と初期化順を持つ。 |
| デバイス固有バックエンド | `sys/dev/<装置>/`。GeForce の ROM 命令や CS4231 のレジスタ操作を持つ。装置内部の型・操作表・診断もその装置に属する。 |

HAL の利用者も調査対象に含む。受信後のプロトコル選別は `sys/net/`、IME や画面所有者の規則は入力・カーネル側が持つ。GeForce の候補先は D-2 に引き継ぎ、表示計算や初期化命令の下位ディレクトリを保って同名ファイルの衝突を避ける。

## P3 の移動と P8 の分割

624 ファイルのうち、570 は中身の分割を要しない。このうち P3 で `sys/hal/` へ丸ごと移せるのは 101（契約 21、型 4、共通処理 59、振り分け 17）。ほかの移設先は各所有者の配置に従う。P3 ではパス参照を追従し、P2-1 で生成物の一致を確かめる。

残る 54 本も P3 で兄弟と同じ行き先へ丸ごと移す。このうち 12 本は sys/hal/ に入る。中身の分割は P8 で行う。対応表の移設欄を `P8` で絞ると、各ファイルについて、移動後も残る具体的な依存と変更理由を読める。うち 18 は分割後に一部を `sys/hal/` に置く候補で、分割不要の 101 には含めない。たとえば `keymap.h` は共通の型を HAL に、PC-98 専用の登録宣言を機種側に分ける。`dev.c` は共通の媒体転送と FDD・IDE の実操作を分ける。

初回の「移すだけ」600 本すべてについて、コメントと文字列を除いた識別子を照合した。条件は PTE・CR3・cpuid・inline asm・ポート I/O、または機種・装置の関数名、操作表名、定数（kbd、GeForce、E82557、LGY98、PC-98 など）。395 本が一致した。具体的な操作の呼び先、分岐、提供者と行き先を照合して 30 本を P8 に変更した。たとえば lock.c はキャッシュ属性と現在の CR3 を使う。IME のキー待機は kbd 実装を直接呼び、NIC の IRQ 受信条件は装置名を選ぶ。各行に委譲先を記した。残した候補の根拠は「境界照合」で引ける。FatFs の PTE は区画表の欄、sync_write の空の asm はコンパイラバリアで、いずれも CPU 固有の命令やページ表を扱わない。

## D-4 の推奨案

音・入力のファイルは、装置を差し替えても使える契約と処理を分野別にまとめる。`sound/hal/` のストリーム管理、能力照会、旧 PCM API 変換を `sys/hal/sound/` に置く。`input/hal/` のデバイス登録、イベント状態、キー変換、ポインタ操作を `sys/hal/input/` に置く。入力の文脈・方針、IME のゲート、割り込み要求を扱う6ファイルは `sys/input/` に置く。

`include/*_contract.h` は同じ基準で選ぶ。P3 で丸ごと移す契約ヘッダは次の3本。

| 契約ヘッダ | 行き先 | 共通の呼び出し口 |
|---|---|---|
| `gfx_present_contract.h` | `sys/hal/gfx/` | planar 転送と表示後診断を機種が提供する契約 |
| `mouse_pointer_contract.h` | `sys/hal/input/` | ポインタ状態を採取するバックエンドの登録 |
| `snd_wake_contract.h` | `sys/hal/sound/` | 音源の通知をクロックに登録する契約 |

この3本は P0-6 の対象外で、P1-1 に渡す。D-4 を含む P3 の HAL 移動は 116 本（分割不要 104、P8 対象 12）。P8 では ext2_medium_contract.h の媒体操作表と登録口を sys/hal/block/ に置き、ext2_medium_ide_ops と ext2_medium_loop_ops の宣言は platform/pc98/boot.c が参照する各アダプタの登録用ヘッダに分ける。残りの契約ヘッダは現行の利用者と提供者の境界を保って P1-1 で配置する。たとえば `av_contract.h` は V86 と KAPI 入口も宣言し、`pcm_contract.h` は CS4231 系の版と tick 配線も規定する。いずれもファイル丸ごとの HAL 移設から外す。

もう一案は、音・入力の共通処理と契約ヘッダを今の持ち主の側に置くこと。P3 の音・入力のパス変更と利用者の include 更新は減るが、利用者は分野別の実装ディレクトリと include/ を横断して契約を探すことになり、仕様 §4 の集約には後の移動が要る。推奨案では装置を差し替える利用者が sys/hal/ の契約だけを参照し、具体表の依存は登録側に閉じる。固有宣言の分割は P8 で行う。

## 照合と A1

`tools/restructure/merge_hal.py <P0-6の出力先> <10本の調査の親> <出力TSV>` が対応表を作る。`p1_verify.py` は基点のソースに P0-6 の抽出を適用し、3表のファイル集合と対応表を独立に照合する。元表を渡す場合は `--p0-dir <P0-6の出力先>` でその3表を直接照合する。不足・余分・重複、移すだけの行き先の衝突、判断欄の空を検出し、保留・未確定は A1 用にパスと根拠を表示する。今回の未確定は 0。[構造の関門](ownership.md)に既存の HAL 契約試験と壊して確かめる例を示す。
