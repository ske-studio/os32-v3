## GF6200_4A_DESIGN

- **4a は 0FACh を読まない・書かない**。0FACh は終端の②で recover だけが扱う (recover final §3)。

- 局所cleanupはPTE・IRQ状態・窓占有・安全に分類済みのindex/lockを戻す。BAR測定は測定前BARを復元しCommandは0102h。終端cleanup/verifyはrecoverが一度だけ実行し、その後4aからGPUを再設定しない。PLL/PFB初期化はcold-requiredで保存値書戻し0件（一時PLL補助値も中断後cleanupでは再生しない）。recoverの①GF quiesce（1850=0・1854=0・PMC割込み=0）には次の前提を適用する。quiesce 前に生の PCI config で Command.Mem=1 と BAR0 が snapshot と一致することを確認する。不一致・確認不能なら MMIO quiesce を省き FAILED に固定し、独立に安全を確認できる②（98画面）だけを行う。decode 解放を確認できなければ②でも VRAM に触れず停止する。前提成立時は①と②を呼び、S1成功を返さない。アクセス不能ならFAILEDとして停止する。

- 戻せないもの: DRAM訓練/初期化・失われたVRAM内容・PLL切替途中・副作用/書込専用レジスタ・バス停止。スナップショットを逆順に全部書く「rollback」は提供しない。

## GF6200_4C_DESIGN

通常終了も中止も `gfinit abort <sid> --allow-write` / `recover now <sid>`、RUN中は既存abort frame。cleanupは既存の**local→quiesce→screen**を保つ（`kdebug/recover.c:1091–1109`）。②のS0復帰は元から0FACh→98が先頭で、C専用の順序変更はしない。

quiesceは既存1850=0→1854=0→PMC140=0と既存照合を維持（`kdebug/recover_gf.c:124–127`）。この位置の追加DACCLK解除・DPMS OFF列はnouveauに無いため設けない。mode/DAC/PLLはcold-requiredとしてS0後のrebootに任せる(記録はアーカイブ)。

1850=0を映像停止の証明とはしない。局所窓/index/lockの解放は既存処理を使い、旧timingやmode/DACを追加再生しない；S0復帰とGFの試行前状態への復帰は別に判定する。

PCI照合不能ならGF MMIOを省いてFAIL、独立な0FACh→98は行う。decode解放未確認ならA0000hに触れない。mode/PLL/PFB/VRAMは巻き戻さずcold-required・S0まで。

## GF_STAGES_DESIGN

C planと既存bind/access/local保存・戻しを使う。構造検査・内部CRC/hashは残すが、hostや全段の固定契約にしない。新しいplanなしのバス経路は足さない。

新分岐にも同じ `cleanup` のlocal→quiesce→screenを使い、S0本体を別に書かない。送信が失敗しても記録の成功を前提にせず、独立に可能なS0へ進む。

S0は**local → GF quiesce（1850=0→1854=0→PMC140=0）→0FAChで98 → decode安全確認→98復帰・セル往復・再描画**。実機で通った順を維持（`recover.c:1135,1180`, `recover_gf.c:125`）。

生config不一致なら危険なMMIOを省き、可能な0FACh復帰は続行。legacy解放未確認なら98 VRAMに触れない。Commandは0102、BAR復元失敗ならdecodeを閉じたまま。

PLL/PFB/古いtimingはS0で戻さない。S0成功と完全冷間復元を同一視せず、既存PARTIAL／S1未保証の意味を保つ。無応答MMIO/CPU停止は従来の物理復帰へ（同`:78,120`）。

## REALHW_RECOVER_ADDENDUM_R2

- `restore_limit` は RESTORING 入口から局所後始末・①②・verify・終端ログまでの独立した総経過予算。main の60秒や残余 trial 予算から借りない。

CommandはSAVEDでなくoverride=0102h、BAR復元失敗時のMem再開禁止も規則にする。

## REALHW_RECOVER_DESIGN

- S0 と S1 は別の保証。既定の復帰は S1 のうち安全な項目を戻した後 S0 に収束する。S1 が VGA 窓を再び開く値なら S0 を優先し、その項目を `override` と記録、S1 完全一致を宣言しない。

- write-only の設定記録は読戻しの代用ではない。`verified / shadow / unknown / override` を分け、必須項目が unknown なら成功にしない。

## 3. 軽い順の復帰階梯

| 段 | 処理 | 成功条件・次の段 |
| --- | --- | --- |
| ① snapshot/restore | 書く前に quiesce→安全な値の採取→CRC/valid 確定。終端とエラー出口で profile の順序で復元。cold-required の場合は保存値を書き戻さず quiesce のみ（§5） | 安全な readback が一致。復元不能項目は採取前から明示し、失敗時に②、必要なら⑤⑥へ |
| ② 98 画面 | 0FACh を 98 表示へ (下の手順) → 装置の出力/DMA を止め → legacy decode を解放 → 共通 display restore → テキスト再描画 | S0 の検査。映像の物理入力はユーザー。PCI の decode が解放できなければ VRAM を叩かず停止/⑤⑥ |

- ①②の内部順序は固定の逆順書戻しにしない。装置ごとに quiesce→decode/出力の安全化→依存レジスタ→画面→verify を定義する。cold-required では依存レジスタの書戻しを省き、§5 の quiesce と②だけを自動実行する。

- quiesce 前に生の PCI config で Command.Mem=1 と BAR0 が snapshot と一致することを確認する。不一致・確認不能なら MMIO quiesce を省き FAILED に固定し、独立に安全を確認できる②（98画面）だけを行う。decode 解放を確認できなければ②でも VRAM に触れず停止する。

- **②の 98 画面復帰は全装置共通で、最初に 0FACh を 98 表示へ戻す**。0FACh は [READ/WRITE] (`docs/hw/undocumented/io_wab.md:345-366`、bit7〜2 は常に 1)。手順: 読む → bit1..0 (mask 03h) が 00b なら書かない → 違えば 00h を書いて読み戻し、mask 03h で 00b なら verified、違えば S0=FAIL。Trident の Disable が 0FACh←00h を最初に書く順と同じ (`docs/tasks/realhw/TASK_TRIDENT_DRIVER.md:356`)。I/O ポートで VGA 範囲外なので、MMIO quiesce を省く失敗経路でも書ける。

- **読み戻しはモニタに何が映るかを証明しない** (Ra266 の割当ては [推]、LSI 統合)。経路の最終判定は**ユーザーの目視**。A0000h の往復が確かめるのは CPU→98 テキスト VRAM の到達だけ。

| 項目 | 必須の約束 |
| --- | --- |
| 復元不能 | PLL/PFB 初期化、VRAM 破壊、装置内状態は逆操作が証明できなければ `cold-required`。cold-required 項目への保存値の書戻しは **0 件**。自動の①は §3 の生 config 検証を満たす場合だけ GF の quiesce（1850h=0・1854h=0・PMC 割込み=0）のみとし、②へ進む。PLL/PFB の保存値は再生せず S1 成功を返さない。安全なアクセスすら完了しなければ FAILED として停止し、⑤⑥を手順に組み込む |
| restore 自体の失敗 | 最初の失敗・段・番地を保持し FAILED に固定。同じ危険アクセスを反復しない。独立性が証明された 98 復帰だけ継続。窓復元失敗も成功扱い禁止 |
| 再試行 | 同一 session の二重要求は既存結果を返す。部分失敗後の再開は checkpoint/冪等性が証明された操作だけ。それ以外は再起動・新規採取 |

- Command は descriptor の override 項目とし、snapshot の0106hは記録だけで書き戻さず、目標0102h（BM=0）を生 config の16bit読取りで verify する。SIZE_BARS の独立 trial 終端にも適用する。BAR復元失敗時は decode を止めたまま FAILED とし、目標値のために Mem を再有効化しない。 4a の全終端で元値と目標値・検証結果を override として記録し、元値との相違を未検証にしない。

- 4a の PLL/PFB/メモリ初期化は当初 `cold-required` 推奨。①の quiesce は §3 の生 config 検証成立時だけ行い、不成立なら FAILED として②だけを安全条件内で行い、cold-required 項目は書き戻さない。4a 終了状態を 4b に残す抜け道は設けず、後段も承認された init を含む単一セッションにする。

0FACh は読む→bit1..0≠00b のときだけ 00h を書いて読み戻す (verified)、経路の判定はユーザーの目視

## RECOVER_ROUTE_TEST

- 承認はconfigureの永続設定を変えず、専用呼出しの範囲で `route_write_approved=true` と一回用 `route_test_once=true` を設定。

- screenの最初のread成功後、専用一回用フラグがあれば00bでもwrite分岐へ入る；通常②の条件は変更しない。

- 初回read失敗は書込み0回。消費後の期限切れ等でも再試行しない。書込み後の再入cleanupも許可を再取得しない。

> [要確認] 原文の r->route_test_once を使う概念コードは撤回され、route_test_once/route_test_approved は recover.c の内部 static に置かれている。

- [C4] ポート/98値/maskは既存RECOVER_ROUTE_*定数を再利用。03hは読戻し判定専用、FC→FCでも成功、非00bならREC_VERIFY/S0=FAIL。

- RECは既存route BEGIN/ENDで足りる：成功時step列はread(0)→write(1)→read(0)。ログ自体に値がないため照合成功は終端のS0 verifiedで確認。

- write BEGINだけでは実行済みと断定しない。ログ欠落/期限超過は成功扱いせず、追加の無期限待ちや自動再送は作らない。

- route_write callback が無い場合は REC_CONTRACT として終了し、一回用承認は消費・解除する。
