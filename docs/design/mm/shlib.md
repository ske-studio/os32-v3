# mm/shlib.c — 設計
> 状態: **現行 (2026-10-31)** — 出所: MEMMAP_V3・DESIGN (D1 で移した)
ソース: `mm/shlib.c`

**世代の識別を 4 つ別に持つ** — OS32X ヘッダの形式版・**KAPI ABI 世代**・**メモリ配置世代**・**shlib プロトコル**。互換性を切る世代は一致を要求し、その世代の内側でだけ最低機能版 (min KAPI) を使う

| 指摘 | 答え |
|---|---|
| ③ shlib 184KB | 池から実ページ数、owner=shlib。text は各 AS の私有 PT に RO+USER (`shlib.c:262` の attach を AS ごとに)、data 複製は owner=そのアプリ (**私有総量 2MB の内側**) |

| 何 | なぜ連続 | 対処 |
|---|---|---|
| shlib の text / data 複製 | — | **不要**。ページ単位で各 AS の私有 PT に張る (§2-3 ③) |

### 9.3 共有ライブラリ (採用 2026-09-04)

- GDI 相当 + ウィジェット + クライアントスタブは描画が重く、`gui_call` 越しに
  1 プリミティブずつ呼ぶのは遅すぎる。アプリのリング 3 文脈で直接呼べる
  **固定アドレス常駐・先頭ジャンプ表・位置依存の共有ライブラリ帯域**を設ける
  (KAPI 表の user 版。再配置不要、ローダ変更は帯域のマップだけ)。バージョン番号を表の
  先頭に置き、スタブが初期化時に照合する (KAPI_VERSION と同じ作法)。
- ライブラリ自身の .data/.bss は「同じ仮想アドレスにアプリごとの物理ページ」で持たせる
  (アプリごとの PT を既に持つので現行機構で可能)。
