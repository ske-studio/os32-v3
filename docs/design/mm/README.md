# mm/ — 設計
> 状態: **現行 (2026-10-31)** — 出所: DEP_DIR_C_DESIGN・MEMMAP_V3・API_CONTRACTS (D1 で移した)
ソース: `mm/`

- paging_map_physのdevice UC、surfaceのcache指定、keep_cacheのPCD/PWT継承、DMAプールのWB、V86セッション復元は汎用処理として残す。
- PDE/PT枠、aperture/MMIO窓、APP帯、pool、guard、ledger配置は一切動かさない。memmap.h/pc98.hの既存定数・マクロは他の利用者のため残す。

**システム側は恒等のまま (D1・D20)、物理地図と所有権台帳を先に作り (D2)、アプリ帯だけを RAM の上 0x80000000 へ出す (D11)。**
残りは台帳が owner 付きで配る「池」にする。

| 時点 | 誰が | 何を |
|---|---|---|

| 時点 | 誰が | 何を |
|---|---|---|
| モジュール読み込み | カーネル | SQLite (code・MEMSYS5・代替スタック)・FEP 等を owner=モジュール名で。大きさは読み込み時に確定。失敗は owner ごと巻き戻し (R7) |

  4. **起動時に確保済みのカーネル側資源 (BB・モジュール・DMA プール・KHEAP・シェル帯) はアプリの伸長で奪われない** — R3 / R4 で起動時・読み込み時に取ってあり、池の空き = 登録 − 固定 − 起動時確保 の残りだけがアプリに配られる。

- **R3 カーネル側が池から取るのは起動時・モジュール読み込み時・そして通常文脈のページ表だけ。** 実行中に要るもの (ドライバのバッファ等) は読み込み時に上限を確保しておく。

4. **順序を R4 に結びつける**: 起動時と読み込みの順は「台帳の初期化 → 連続が要るもの (BB・DMA プールの予約・モジュール本体) → 通常 (ページ単位の配布 = 最初のアプリ以後)」。**連続が要る確保は全部、最初のアプリより前に終える** — これが R4 の「池からの新規の連続確保は起動時・読み込み時だけ」の理由で、8MB 機でモジュールが入る根拠 (§4-3) はこの順序の上で成り立つ。

### dma_pool

検出RAMが終端0x800000に届かない場合はDMAを使う装置 (PCM・82557) だけを無効にし、診断を1行出して起動を続ける。一般割当前に `LEDGER_R_DMA / LEDGER_OWNER_KERNEL / WB` で16ページを恒久予約し、物理=仮想・supervisor/RWを保つ。

`dma_alloc(size, align, limit)` — 64KB 境界 ([HW2]) と ISA の 16MB 未満は**割当条件**であって固定帯の理由ではない。DMA プール 64KB (0x7F0000、§2-1) は固定の塊の 1 つとして残す (PCM リング・82557 CB/RFD の顧客は既にある)。

- **R4 連続した物理 — 池からの予約は起動時、固定プール内部の割当は利用時でよい。**

  - DMA プール 64KB (§3-2) は固定の塊として起動時に予約済み。**プール内部の割当 (`dma_pool_alloc` → `dma_alloc(size, align, limit)`) は利用時 (`pcm_open`、82557 の open) の通常文脈でよい** — 池を触らないので R3 に反しない。
PCM の確保時点は変えない。

| 何 | なぜ連続 | 対処 |
|---|---|---|
| DMA バッファ (PCM リング・82557 CB/RFD・FDC/ATAPI) | 装置が物理を見る、64KB 境界 | 固定 DMA プール 64KB (0x7F0000、§2-1) の内側 (R4)。低位の池から起動時に予約し、実行中は一般池から取らない |

### physmem

単位は PFN の半開区間。種別: RAM (source = BOOT / KERNEL_SLACK / HIGH)、MMIO (PEGC 窓・PCI BAR・デバイス窓 — sup+PCD で張る範囲)、予約 (15〜16MB、集積域)、SURFACE (§2-2)。

### paging_app

それを超える PT は**通常文脈で池から 1 枚ずつ取る** (owner=その AS)。
**失敗時は操作全体を巻き戻す**: PT が取れなければ lease は張らない (部分写像を残さない)、伸長は上限を動かさない。

### shm

GUI は SHM の末尾を予約し、`shm_alloc` の管理表で使用済みに固定する。

### kmalloc

`kmalloc` は固定の KHEAP (192KB) からで池を借りない
