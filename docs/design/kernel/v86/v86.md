# kernel/v86/v86.c — V86 実行と例外処理

> 状態: **現行 (2026-10-31)**

V86 ゲストの例外、割込み、終了と表示復帰を扱う。
ROM の I/O 採取はデバッグ部品へ委譲する。

## 落とし穴

- エミュレータの BIOS の画面モード設定は実機 ROM の手順と一致するとは限らない。
  実機固有の表示崩れでは `v86 -g` で実機 ROM の I/O 列を採取して照合する。
  採取の入口は `kernel/v86/v86_gcap.c:6`、記録器は `kdebug/v86_gcap.c:635`。
  溢れや列の順序は `tools/tests/test_v86_gcap.py:45` で検査する。

## 内部設計と契約 (D1)

```c
/* kernel/v86/v86.c: この互換入口だけ残す */
void v86_cui_display_restore(void) { display_restore_98(); }
```

- 共通画面処理は `gfx_state_for_os32` の 6Ah/EGC/GRCG 等と text START を統合して共有。V86 を起動せず、v86.mod 不在でも使える最小の HAL/kernel 入口にする。`PEGC_FF2_STD_GFX` を書くため PEGC GUI の既定構成へは戻せない。CUI での開始を必須とし、GUI 中（CUI を確認できない場合を含む）の開始は書込み前に拒否する。PEGC GUI 復帰は別試験。
- 31kHz を試験中に変更しない。09A8h だけ書いて周波数を変えるのは同期再設定を欠くため不可 (`R/docs/hw/undocumented/io_disp.md:1865`)。
