# sys/kern/irq/irq.c — 設計
> 状態: **現行 (2026-11-07)** — 出所: DEP_DIR_B_DESIGN・DEP_DIR_D1_DESIGN (D1 で移した)
ソース: `sys/kern/irq/irq.c`

- IRQ 表、登録数、共有配送、storm/quarantine は kernel 所有。線一覧・予約・EOI は platform 所有。
- `irq_dispatch` は claim → deliver 時だけ共有配送 → needs_finish 時だけ complete → 未処理報告。claim 失敗時は配送も完了もしない。
- 互換 `irq_finish` は claim → complete → 報告で、dispatch と併用しない。PC98 は固定線を claim せず、IRQ0/7 等の既存 ASM だけが完了する。
- PC98 IRQ15 は配送後に ISR を読み、IRR 選択へ戻し、実 IRQ なら slave → master、spurious なら master のみ。handled から EOI を決めない。
- `irq_topology_check` を PIC 初期化直後・unmask 前に実行。不一致は診断後停止。32線以上の状態は irq_line が正、u32 診断は下位32線だけ。

- irq.h の「全登録者が tick 回収」は **FDC の排他完了通知だけ例外**と明記。FDC は既存 timeout/retry で戻す。NIC 等の tick 保証は緩めず、FDC の新規 poll 処理は作らない。

常駐で解除しない FDC を例外

## PC-98 IRQ12 共有の移行案

2026-11-27 第3稿。初段で CS4231 を IRQ12（slave IR4）に結ぶ条件は、0188h と 0288h の両方で実 FM 音源の不在を確認し、BIOS の WSS 経路が INT5 で、DMA #1 を使用できること。OPNA、26K 相当、別ベースの音源、UNKNOWN では S3 のつなぎとして PCM を INT41 / IRQ10 に結び、起動ログに選択理由を記録する。実音源を使う V86 ゲストは現行のポート素通しと IRQ12 反射を使う。

### S1 の音源判定

PC-98 常駐側は初期値 UNKNOWN とし、FM 部品からベース別の検査結果、確認済みのチップ ID・機能 ID とそのポート、確認できた FIFO 制御ポートを受け取る。未確認の欄は無効とする。0288h は状態・データの両ポートを読み、どちらも連続 FFh の場合に ABSENT、それ以外は UNKNOWN とする。Multimedia Orchestra の OPL3 などと番地を共有するため、0288h・028Ah には書かない。

0188h は従来のネイティブ FM 登録用プローブを一度だけ実行する。安定したチップ ID 1 と停止・クリアを確認できれば OPNA とする。Timer B の新しい立上りと停止・クリア・出力設定の復元が成功した場合、ネイティブ登録は従来の OPN とし、初段の判定には種別未確定の実音源ありを記録する。ID 4 と 0188h の OPNA を照合し、A468h が応答した場合に FIFO 制御ポートを記録する。0188h の ABSENT には状態・データの連続 FFh と機能 ID の整合を求める。

0188h・018Ah が連続 FFh の場合、A460h を 2 回読み、同じ値なら上位 4 ビットで判定する。識別 ID の出所は WATCOM 資料 `undocumented/io_sound.md` 116–125 行、146–175 行。

| A460h 上位 4 ビット | 音源構成 | 開放時の 0188h |
|---|---|---|
| 0111 | FM を持たない内蔵 CS4231。Ra266 の 73h も該当 | ABSENT |
| 1111 | 音源なし、または A460h に識別機能を持たない 26 相当。0188h が応答すればネイティブ判定を使う | ABSENT |
| 0010・0100・1000 | 018xh の FM、または FM を持つ内蔵 CS4231 | UNKNOWN |
| 0011・0101 | 028xh の FM を示す。S3 で FM 非搭載と誤認しないよう保守的に扱う | UNKNOWN |
| 0110 | Nf・Np 内蔵。S3 は拒否 | UNKNOWN |
| その他、または読み値が不安定 | FM 不在を確認できない | UNKNOWN |

0188h の BUSY 解除と Timer B 立上りは、後始末を含め各待ちで最大 10,000 回状態を読む。最後の読みで成立すれば成功、上限まで成立しなければ判定は UNKNOWN とする。書込み前の失敗は contained=1、書込み開始後に停止・クリア（29h を変更した経路では復元も）を確認できなければ contained=0 とする。立上りがなくても後始末が成功すれば contained=1。停止書込みの再試行にも独立の回数上限を用いる。実時間の上限は保証しない。

初回は既存の LAN・PCI bind 後、USB 起動前の FM 検出順を使う。候補線に既登録者がいるか隔離中の場合も、IF=0 の初回判定で、0188h のネイティブ判定が ABSENT、両ベースの状態・データが各 2 組とも FFh、A460h の 2 読みが同値で上位 ID が 7 または 15 なら、書込みなしで両方を ABSENT とし IRQ12 を公開する。それ以外は両診断を UNKNOWN に保ち、ネイティブ FM 登録には従来の判定を使う。正常経路では IMR を書かない。最初の変更から停止・クリア・復元に失敗した場合は IRQ12 を物理マスクし、V86 enter を含む以後の enable を抑止する。初回判定と登録用の結果を常駐側に保存し、部品の再 attach で再プローブしない。

### 後段の実音源共有と仮想 PIC

1. 共有が成立した構成にも S2 の動的配送を適用する。既存の IRQ12 スタブはフレームを現行どおり保存し、IF=0 で一度だけ `irq_dispatch(12)`。物理 EOI はその complete が slave → master に各一回送る。スタブ・装置・仮想 PIC は物理 EOI を追加しない。
2. PCM と実音源の V86 用 handler は各々 `IRQ_F_SHARED` で登録する。PCM は R2.INT と I24.PI に従って ack。V86 側はセッションが所有する実音源の要求を非破壊で読み、該当すればセッション内の pending を立て IRQ_HANDLED。どちらも自分の要求がなければ IRQ_NONE。同時要求では両方が処理され、全員 NONE なら既存の storm 判定が働く。
3. スタブの dispatch 後、保存 EFLAGS.VM=1 の復帰点でのみ pending をゲストフレームに反映する。仮想 PIC の IMR・ベクタ設定と既存のスタック範囲検査を通す（既定 INT 14h）。物理 EOI 後、ゲスト ISR が実音源を読んでタイマ・FIFO の要求を解除し、ゲストの EOI は仮想 PIC に渡す。ホストはゲスト所有のラッチを先に消さない。
4. エッジが重なった場合、一巡後に立った別装置の要求には次のエッジが保証されない。PCM は tick で回収する。V86 はセッション中の既存タイマ復帰点でも音源状態を一回確認する。非 VM フレームでは pending を保存し、VM に戻れる時に再試行する。仮想 IMR で保留した要求は IRR に残し、許可後に配送する。IRQ handler、tick、捕捉 I/O と仮想 EOI 後の再読は同じ採取状態を直列に更新する。タイマ A、B、FIFO ごとに、有効な要求を初めて観測した時だけ採取済みにして IRR に OR する。注入や EOI で採取済みを消さない。基本 27h の成功したフラグクリア（bit4/5）は対応する A/B、86 の A468h の要求クリア（bit4 に 0）は FIFO だけを再採取可能にし、転送直後に再読する。禁止・再許可を含む制御変更でも有効要求を再評価し、非アサートを確認した源だけ採取済みを落とす。転送失敗・解除の成否不明は終了回収へ渡す。実 I/O を通す FIFO も制御書込みは捕捉する。仮想 ISR 中に解除後の新規要求が来れば IRR に保留し、同じ未解除要求を何 tick 観測しても IRR を再設定しない。IRR は線ごとに一ビットで、注入前の複数源は一回にまとめる。仮想 PIC は要求記録（IRR）、候補選択、注入確定を分ける。既存の v86_pic_should_inject の一括更新を分割し、ゲスト IF、両 PIC の IMR、優先順位と既存 ISR を確認する。IRQ0 と slave IR4 が同時なら既定の固定優先順で IRQ0 を先に配送し、後者を保持する。スタック範囲とベクタを検査し、ゲストスタック・復帰フレームの更新に成功した時だけ IRR を消費して ISR（slave IR4 と master IR7 の cascade）を立てる。検査失敗で配送済みにしない。slave/master の仮想 EOI、マスク解除の I/O 復帰点、タイマ復帰点で再評価し、一復帰につき一ベクタを配送する。
5. enter 前に所有権を取得し、仮想 PIC と pending を初期化して登録する。通常の v86_run_limit 復帰、timeout、v86_mem.c の v86_session_end → v86_runtime_end を通ってアプリへ戻る fault の双方で終了処理を一度だけ行う。ゲスト実行を止め inactive・closing とし再入を禁じる。所有中のタイマ出力を禁止してフラグを解除し、実 86 なら FIFO 割込みを禁止して残留要求を解除する。装置の非アサートを確認後、非 IRQ 文脈で自セッションの登録を外し、IRR/ISR・pending・shadow を破棄して所有を返す。IRQ・例外スタックでは release_pending を立て、closing が落ちても再入を拒否する。kill landing から再度入る v86_session_end の前景 release 節で、v86_module_session_release と exec_finish より前に登録を回収する。捕捉不能な命令・BIOS I/O の同期喪失・転送途中の失敗もこの前景 release に接続する。所有取得、登録成功、源ごとの停止書込みと解除確認を記録し、失敗した書込みをゲスト命令として再実行しない。停止未確認の FM は所有を隔離して再入を拒否し、前景で当該セッションの登録だけを外す。PCM の登録・DMA 所有と経路が健全で、物理エッジが戻らない間も tick で PI と DMA 位置を観測する。[PCM の連続性判定・番犬・保証の範囲](../../drivers/sound/cs4231/pcm_cs4231.md#advance-irq10-と-tick-が呼ぶ唯一の入口) に従い、成功した位置取得どうしの間隔が 1 半周期未満なら連続性を保証する。1 半周期に達すると保証外だが、それだけで番犬は発火しない。PI を ack しても位置が -EAGAIN なら last_progress を更新せず、最後の位置進行からの経過を数える。2 半周期ちょうどでは番犬による停止なし、超えた最初の観測で RUNNING は RS_STOP、DRAINING は drain 失敗・STOP_REQ とし、前景 S3 停止を要求する。経路不一致・番犬発火では前景で S3 の停止確認と復元に移り、停止または復元を確認できなければ DMA・リング・経路を隔離する。登録失敗も取得した所有を同じ停止手順で返す。PCM の登録と IRQ2 VSYNC の寿命は独立する。

つなぎの次段は 118 の PCM も BIOS の INT に揃え、FM と PCM で IRQ12 を共有する。後段の開始条件は、FM タイマと FIFO それぞれについて実ボードの設定と物理配送線を照合できること。FM ベースから IRQ を推定しない（io_sound.md:318–321、NP21/W board86.c:150–162、pcm86io.c:330–349）。別線の発生源は IRQ12 の判定から除外し、線が不明なら共有を開始しない。実際に IRQ12 に接続した発生源だけ、タイマのフラグと出力許可、または確認済み FIFO 制御ポートの許可 bit5 と要求 bit4 を照合する。別線 FM のゲスト配送は将来段の入口条件とし、その物理登録、ゲスト IRQ、復帰点と EOI の責任を決めてから扱う。同時要求、保留、fault 回収、ゲスト演奏速度は後段の受入窓で測る。

後段では検出した基本バンクの index/data（0188h/018Ah または 0288h/028Ah）、OPNA の拡張バンク（base+4/+6）を TSS bitmap で捕捉する。バンク別に選択 index を保持し、実ポートへの byte IN/OUT を一度だけ同順で転送する。基本バンク 27h の bit2/3（A/B フラグ許可）と OPNA 29h の bit0/1（対応出力許可）は成功した data 書込みで更新する。拡張バンクの同番号では更新しない。word/dword や文字列 I/O が捕捉範囲に重なる場合は等価な転送を検証できた幅・命令だけ許可し、未知の操作では実音源共有を中止する。開始時は所有取得後に既知の出力停止値を実チップと shadow に設定し、reset・BIOS の音源書込みにも同じ同期を適用する。未観測の経路が残る機種は理由を記録して共有を開始しない。

将来の[ソフト 86 互換](../../../decisions/sound/V86_SOFT86_DESIGN.md)は実 86 のない機械で、仮想タイマ・FIFO が仮想 IRQ12 の pending を立てる入口を使う。CS4231 の物理 IRQ12 到着はこの入口を呼ばない。

### 次段の配線確定と有効化（設計案、基点 c34ee44f1）

PC-98 常駐側が初回 FM 判定後、PCM 初回ロード前に配送方針を一度決める。open、ゲスト enter、部品再 attach はこの判断を共有する。発生源ごとに種別、基本ベース、制御ポート、物理 IRQ、出力可否を固定表に持つ。照合根拠と測定記録は診断側に保存する。IRQ12 の動的公開には BIOS INT5、DMA #1 可、そして IRQ12 を駆動し得る全音源を特定・停止・判定できることを求める。FM が別線または未照合なら IRQ12 の旧経路と V86 素通しを保存する。両ベース ABSENT なら従来の PCM 単独経路を選ぶ。診断済み構成の表は実音源共有を選ぶ時だけ照合し、拒否理由を記録する。稼働中の PCM の経路をゲスト enter で切り替えない。

| 音源 | 共有を選ぶ前の照合 |
|---|---|
| 86（ID 4／5） | 機能 ID が指す基本ベースと OPNA 応答を照合。排他取得して基本 index を保存できる時に 0Eh を選び、data の割込み設定を読み、元 index を復元する。ジョイスティック入力は比較から外す。ボードの割込み許可とスイッチ設定を照合し、タイマと 86 FIFO の線を別々に記録する |
| 118 相当（ID 8） | 実ベースの FM 応答と WSS の存在・BIOS INT を別々に確認する。FM の 0Eh／機種設定と WSS の 0F40h を独立に照合する。86 FIFO を登録しない。拡張機能が別の要求を同じ線に出せる構成は、その出力を抑止・確認できることが必要 |
| 26K 相当 | OPN の Timer B の新規立上りと停止・クリアはチップ応答の証拠。型番・配線は機種設定との照合を別途要する。基本バンク 27h の許可と状態 bit0/1 を使う。OPNA の 29h と 86 FIFO を読まない |
| 028xh／不明 | ID と資料で別ベースを確定し、該当するポートだけを捕捉できる機種を追加する。初段の読み取りだけの UNKNOWN を格上げしない。OPL3 と区別できないアドレスへの試験書込みを避ける |

初回の配線確認は TICK_PROBE_BUILD=1 の排他診断像（CI の diag_tick_s1 入口）で行う。表にない機種でも IRQ12 の既登録者を確認し、いれば登録・IMR・装置に触れず拒否する。空なら登録状態、配送方針と IMR を保存し、旧スタブから診断専用の IRQ12 観測口へ一時切替する。下記の単独窓を一つずつ通し、各窓の終了時は途中失敗を含め、発生源の停止を確認してから自分の登録を外し、配送方針・登録状態を復元した後に元の IMR を戻す。停止または復元を確認できなければ IRQ12 をマスクして隔離し、診断の続行と製品表への採用を禁止する。通常起動では試発生させず、製品ソースに収録した診断済み構成の表を使う。PM が確認した型番・基板版、スイッチ／BIOS 設定、FM・WSS 実ポート、各源の到着線と同線駆動の資料または配線確認記録を一組として登録する。通常起動で実音源共有を選ぶ時は機種識別と BIOS 0F40h、A460h、FM の 0Eh の設定欄を表と照合し、読めない型番・スイッチ位置は対象実機に紐付いた明示設定を要する。欠落・不一致なら未照合とする。0Eh を読むには排他所有と基本 index の既知値（全書込みを追跡した shadow 等）が必要。保存・復元を保証できなければ選択書込み前に拒否する。

io_sound.md 116–175、204–221 行は機能 ID、318–321 行は 0Eh と 73／86 の A460h による別ベース識別、505–511 行は FIFO の許可・要求とクリア、683–707 行は WSS の INT／DMA 欄の根拠。別型の 028xh を追加するにはその型固有の資料とポート照合を要する。1015–1026 行の設定表示と実出力の相違例も考慮する。NP21/W の比較対象は board86.c の reset、pcm86io.c の setopt、board118.c の irqf 選択、fmboard.c の getjoy、opntimer.c の opna_timer。模型の 0Eh 上位 2 bit は 00/01/10/11 が IRQ3/13/10/12 に対応するが、無効設定でも線の符号は読める。実機で同じ対応を採用するには対象ボードの設定と単独発生時の PIC 到着を照合する。FIFO は同一スイッチで配線されると確認した型だけタイマと同じ線を採用する。診断ではタイマと FIFO を一方ずつ許可し、各要求・到着線・解除を記録する。候補線に既登録者がいる通常起動で割込みを試発生させない。実機未照合の型は模型用の対応だけを根拠に有効化しない。

ネイティブ FM と V86 は同一チップを排他所有する。ネイティブの発音は現行 opn_chip の出力抑止を維持し、OPNA の 29h 下位 2 bit、共有線上の OPN の 27h bit2/3 を実書込み時に抑止する。shared_irq の判断元を PCM_IRQ 定数から当該 FM の配線記録へ移す。発音のためだけにゲスト pending を立てない。V86 は所有取得後に実ポートへ転送し、前節の shadow と要求ラッチを使う。タイマ A/B は同じタイマについて状態・27h 許可・OPNA なら 29h 許可を AND し、最後に A/B を OR する。BUSY、別タイマの許可、所有外の状態は要求に数えない。FIFO は実 86 の確認済みポートで許可と要求が共に立つ時だけ配送する。所有交代時は旧所有者の出力停止を確かめ、新所有者の shadow を実書込みで初期化する。

両構成とも NP21/W で同一 SHA・媒体 CRC の次の窓を順に測る。実機受入は、新しく共有を許す型番・設定の単独配線確認と同線併走（後発要求・終了回収を含む）に限る。別線・既登録・両 ABSENT の回帰と停止失敗の注入はホスト検査・NP21/W で行う。req83 の値は設定の観測であり、到着線は各窓で採る。

1. 型番・版・FM/WSS の実ポート・BIOS 設定とスイッチを記録する。排他診断で他出力を止め、FM タイマだけを許可して状態、物理 PIC 到着線、装置 ack 後の解除を採る。86+WSS は NP21/W・実機とも FIFO だけでも繰り返す。次に FM・FIFO 等を止め、WSS だけで R2.INT／I24.PI、物理 IRQ12 到着、PI ack 後の解除を採る。DMA #1 を借りる診断も S3 で取得し、停止確認後に復元する。停止・復元未確認なら IRQ12 をマスクして隔離し、次の窓へ進まず記録を製品表から除外する。118 の FM 設定は WSS と独立に記録する。実機の同線併走へ進むには二つの単独到着に加え、当該型番・設定で両出力が同線を駆動できる資料または確認済み配線を要する。
2. FM を実際に IRQ12 に設定した併走窓と別線窓を分ける。PCM 単独のゲスト反射はゼロ。併走で 0F40h=22h、close 後の元値、played、非無音 frame、基準曲の進行時間とタイマ数を単独窓に照合する。別線窓・線未照合窓はつなぎの受入とする。通常起動から実 open で IRQ10・0x1A、close で元値、前後で旧 IRQ12 経路・V86 素通し・既存登録の保存を確認する。窓 3・4 は同線確認済み構成で行う。
3. 同時要求では一回の物理 dispatch で両源を処理する。後発源が線を保持する窓では追加エッジなしで tick が回収する。各窓で物理 EOI は実到着ごとに slave/master 各一回、tick と仮想 EOI による増分ゼロ。未解除の複数 tick と仮想 EOI 後も同一要求のベクタは一回。ISR 中に解除・再アサートした窓では EOI 後にもう一回。IMR 保留中はゼロ、解除後に一回。
4. ゲスト未 ack の終了で前景回収、PCM 継続、次ゲストの再取得を確認する。停止確認を失敗させた別窓では FM 再取得拒否、追加エッジなしでの PCM tick 回収と played 増加、前景 S3 停止要求と停止・復元失敗時の隔離を確認する。先行赤検査と受入で成功観測間隔を 1 半周期の直前・ちょうどに置き、保証内・外を区別する。PI ack 成功・位置 -EAGAIN を続け、最後の位置進行から 2 半周期ちょうどでは継続、直後には前景停止要求となることを測る。ack で番犬を延命する変異を落とす。

Ra266（73h/20h）の PCM 単独回帰は保存した判定値で検査する。PM は実 86+WSS と実 118 の機材の有無・診断結果を別々に記録し、未取得の構成には「実機未確認」を付ける。
