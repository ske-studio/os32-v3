## serialfs 2 本（6f → 6b）

- **現状と配置**　`platform/pc98/device_fs.c:15-23` の `platform_serialfs_session_begin/end` を `fs/serialfs/device_serialfs.c` へ。共通本体は `serialfs_session_begin/end`、`sfs_finish`、`sfs_send_log`、`sfs_dead_name`。所有確認、排他、HELLO、VFS permit/mount、BYE/解放、LOG/EXIT の組立はここに集める（`fs/serialfs/serialfs_session.c:99-110,125-218,220-321,334-345`）。PC-98 の `sio_put/get/now/idle/can_wait`、`sfs_flush_hold_raw`、`sfs_lan_peer_mac`、82557 foreground acquire/reset/RX ready と sysconfig 選択（同 :46-97,112-123,150-173,247-287,324-332）を `platform/pc98/serialfs_session_io.c` に残す案。resident の MAC 診断もここで実施する。現行 :228-230 の `SfsLan *` キャストは PowerMac の `pm_hfs_transport` に使えない。
- **契約案**　`include/serialfs_session_contract.h` に `int platform_sfs_session_acquire(struct sfs_session_link *out);`、`void platform_sfs_session_release(struct sfs_session_link *link);`。out は既存 `SfsIo const *io`、`void *ctx`、baud、max_payload、任意の `u32 (*hold_take)(u8 *buf, u32 cap)` と `u32 (*hold_dropped)(void)`（それぞれ取得バイト数と欠落バイト数）を持つ。成功 0、使用中 BUSY、待機不能 INVAL、装置/設定障害 IO、利用可能な foreground 経路が無ければ HOSTDOWN。失敗時は取得済み資源を後端で戻し、成功後は全終端経路から一度だけ release。UART は acquire で gate を上げ、release で gate を下ろして raw 残りを排出。UART 隔離は hold 付き経路で共通の `sfs_client_quiesce` を使う。foreground LAN では hold が空で、従来どおり console へ統計と終了コードを出す。時刻は `io->now(ctx)` の既存 tick 単位、deadline は wrap-safe、`can_wait` を確認して `idle` で協調進行。PC-98 の foreground 入口の serial 初期化・IF 判定と BUSY の優先順を保存する。
- **PowerMac の結線**　`platform/powermac/hostfs_boot.c:9-21` が `pm_hostfs_io` を resident に登録し、LINK 像は poll も登録済み。通常の begin/end は共通の `sfs_persistent_scope_begin/end` を使い、foreground acquire を呼ばない。PPC の foreground fallback は `platform/powermac/hostfs_boot.c` で HOSTDOWN を返す。resident 側は既存 `serialfs_persistent.c:53-105,108-135` に所有と再接続を一元化。既設 LINK transport は `hostfs_link_io.c:64-124,126-162` の一件・絶対期限・同フレーム再 OPEN 抑止を使用する。IRQ/EE=0 で進めない。非 LINK 像の既存 transport 選択も保持する。
- **終了コードの差**　resident scope_end は現在 exit_code を捨てる（`serialfs_persistent.c:100-105`）。また `tools/host_sfs_link.py:27-52` の先の `tools/lanfs_host.py:83` では LOG/EXIT が通らない。計画 §5 の QEMU 受入には明示的な配送が必要。案は LINK の SFS CALL 内で EXIT を既存ホストのセッション照合と終了処理（`tools/serialfs_host.py:709-715`）へ通し、共通 resident scope に小さな opt-in を設ける。EXIT は 0 を含む子の code を既存 payload で送り、一件の完了を期限内で待つ。現行 `pm_hfs_put_until` の 0 はキュー受付なので、必要なら既存 poll の完了結果を待つ薄い口を足す。切断時にも scope は解放、SID と mount は resident 所有のまま。PC-98 resident の既存振る舞いは既定値で維持する案。
- **選択**　`build/sources/common.mk:6,10` の session を PC98_PENDING → USERSHELL、同じ組に固定名 TU。6f 時点の x86 選択を維持し、PPC への実選択は 6b の結線と同時に行う。PC-98 後端は `build/platform/pc98.mk:2` の機種集合で USERSHELL と揃える。PPC 側は既存 `C_PLATFORM_USERSHELL`（`build/platform/powermac.mk:9`）内の LINK 分岐を再利用。 `build/select.mk:19-25,266-279` の USERSHELL→EXEC は現行どおり。session への実効的な PC98_PENDING 条件だけを外す。
- **受入**　NP21/W は UART で HELLO→読取→BYE→隔離→LOG/EXIT（非ゼロ code）→gate 解放、HELLO 無応答時の raw 排出、既存 /host の BUSY、連続実行、foreground LAN の acquire 失敗/解放と resident scope の継続を確認。QEMU の LINK+USERSHELL は既存 peer で /host 読取、scope 二重開始、切断後の期限付き復帰・再開と古い FD の stale、EXIT payload の対向取得、SFS CALL の二重発行なしを確認。EXIT 抑止変異で対向取得が失敗することも見る。

## platform loop 3 本（6f → 6c-loop）

- **現状と配置**　`platform/pc98/device_loop.c:20-33` の `platform_loop_dev_attach/detach/status` を `kernel/dev/device_loop.c` へ。V86 専用の `platform_loop_dev_get_geometry/read_chs/read_lba`（同 :4-18、呼び手は `platform/pc98/legacy/v86.c:714-725,822-838`）は PC-98 の TU に残す。実体は `drivers/block/loop_dev.c:165-193,202-350,355-455` の `loop_dev_init/attach_fd/attach/detach/read_lba/write_lba/is_writable/get_fd/get_geometry/status` と形式判定・CHS・Device callback 群。イメージの拡張子や形式に PC-98 由来のものがあっても、実装は VFS と Device だけに依存するため、この仮想装置の一つの TU として両像で使用する。NP2 の 5 本は E、PC-98 の `device_host.c:6-29` に残す。
- **契約案**　`include/loop_contract.h` に既存の `void loop_dev_init(void);`、`int loop_dev_attach(const char *path, int slot);`、`void loop_dev_detach(int slot);`、`int loop_dev_status(int slot, u32 *total, int *bps);` を移し、装置ヘッダから include。attach は 0/既存負値、detach は void で空・範囲外は no-op、status は装着済み 1/それ以外 0、出力 NULL 可、非装着時は出力に触れない。書込可否は O_RDWR で開けたかに従う（同 :287-307）。現行では Device の `blk_write` は登録されず、`loop_dev_write_lba` が別経路（同 :182,254-261,338,386-414）。ext2 用には書込可能な線形媒体だけに Device write callback を設定し、既存 `loop_dev_write_lba` に委譲。RO、D88 は ext2 に渡さない。VFS の seek が int 幅なので、利用可能なイメージ範囲は LBA→byte 変換を含めて検査する。
- **選択と後端**　`build/features/pc98-devices.mk:6` から `drivers/block/loop_dev.c` を外し、固定名 TU とともに `C_COMMON_EXEC` に入れる（`build/sources/common.mk:5`）。`build/select.mk:58-64,267-279` の PC98_DEVICES 制約は他の装置に適用したまま、loop は EXEC で選択。PC-98 は `boot.c:123-124` の登録順を維持。PowerMac は `platform/powermac/root_boot.c:6-23` で一度だけ `loop_dev_init()` を呼び、lo0..lo3 を既存 Device 表に登録。PowerMac の表は BSS 開始（`kernel/dev/ram_ro.h:9`）。既存 root デバイスを消す初期化は不要。結果は共通 loop が返す。
- **受入**　NP21/W は V86 の CHS/LBA、既知 RAW と NHD の容量・BPS、attach 二重時 BUSY、RO の書込拒否、detach の pin 回収を確認。QEMU は VFS の既知イメージで attach→status→detach→status、無効 slot、再 attach、セクタ読出しと媒体境界を確認。RO/書込可能の両方を試すため、書込側 fixture は `init/boot_root.c:26-28` が RAMFS を張る /tmp などの書込可能な VFS 上に置く。容量 +1 変異で status 照合が失敗することを確認する。

## ext2 2 本（6f → 6c-ext2）

- **現状と配置**　`platform/pc98/device_fs.c:5-13` の `platform_ext2_format/format_at` を `fs/ext2/device_ext2.c` へ。 `ext2_format`、`ext2_format_at`、`ext2_format_range`、`fmt_write_super/root/groups/backups`、`fmt_init_groups`、`ext2_layout_plan` を共通で維持する。現行 IDE presence/range と BIOS 根拠、先頭 18 セクタの保護は `fs/ext2/ext2_fmt.c:1-6,156-188,217-263`。下流にも IDE/PC-98 があり、`ext2_dev_for` は hd 名固定、`ext2_find_partition_ex` は PC-98 区画表と BIOS/IDENTIFY 幾何を読む。 `ext2_mount` もそれを参照する（`fs/ext2/ext2_super.c:217-325`）。 `ext2_vfs_mount` も hd 専用（`fs/ext2/ext2_vfs.c:416-430`）。formatter 2 TU の選択変更だけではリンクも再マウントも成立しない。
- **契約案**　`include/ext2_media_contract.h` に `int platform_ext2_media_get(int drv, struct ext2_media *out);`、`int platform_ext2_media_default(const struct ext2_media *m, int for_write, u32 *start, u32 *length);`、`int platform_ext2_media_range_ok(const struct ext2_media *m, u32 start, u32 count);`。media は既存 `struct _Device *dev`（`kernel/dev/dev.h:36` の `Device`）、512B セクタ総数、最初の書込可能 LBA、書込可否。get/default は EXT2_OK または既存 EXT2_ERR_*（媒体なし・I/O は IO、区画なしは NOPART、不適な範囲/幾何は INVAL）。range_ok は 1/0 で論理容量に加えて後端のアドレス限界も検査。共通部は長さ 0、セクタ幅、RO、`count > capacity - start`、実書込長を初回 write 前に照合。既存 `Ext2Ctx.dev` と `dev_blk_read_lba/write_lba` を使い、後端にフォーマット処理を足さない。
- **PC-98 後端**　`platform/pc98/ext2_media.c` に hd 名解決と `ext2_find_partition_ex` の実装、必要な legacy/幾何ログを置く。前者は `platform_ide_drive_present`・`platform_disk_geometry_get`、範囲は `platform_ide_range_ok`。default write は BIOS 幾何必須、read mount は従来どおり IDENTIFY fallback を許す。明示範囲は下限 LBA 18 を維持。 `ext2_format` の区画長と最大グループ数へのクランプ、`format_at` の明示範囲拒否を維持。NP21/W は BIOS と IDENTIFY が違う像、BIOS 欠落、未登録・短い媒体、先頭 18 セクタ・ATA 表現限界、対象外の番兵と、既存 hd の再 mount・ファイル作成を確認。
- **PowerMac 後端**　`platform/powermac/ext2_media.c` が承認した整数指定から登録済み `loN` を引き、`loop_dev_status/is_writable` と Device の I/O から media を返す案。暫定案は drv=0..3 を lo0..lo3、default は使い捨て線形 loop 全体、明示指定は LBA 0 から許可。RO は format を拒否、未接続・D88・512B 以外は対象外。再 mount は default の場合 loN を `platform/powermac/root_boot.c:8-17` の VFS 名表と `ext2_init`（`fs/ext2/ext2_vfs.c:509-512`）に結線。非ゼロ offset は共通 `ext2_mount` の Device＋範囲を受ける入口を切り出し、既知範囲で再 mount する。ゲスト試験にはその入口か承認済みの VFS 範囲指定を使う。format 時の揮発的な「最後に書いた区画」台帳は作らない。
- **選択と受入**　範囲 mount まで含む `ext2_{super,inode,dir,file,fmt,layout,vfs}.c` を `C_COMMON_PC98_PENDING` から `C_COMMON_EXEC` へ移し、固定名 TU も EXEC。PC-98/PowerMac の media 実装は各機種の EXEC 選択に置く（`build/sources/common.mk:5,10`、`build/platform/pc98.mk:2`、`build/platform/powermac.mk:7`）。`build/select.mk:19-25,266-279` の枠組みで ext2 の実効 PC98_PENDING 制約を外す。QEMU は別々の使い捨て loop 上で format と format_at（非ゼロ start）を行い、対象範囲から再 mount、magic・ファイル作成/再読取、直前直後の番兵、RO/範囲外時の無変更を確認。start_lba 無視変異を番兵/再 mount の両方で検出する。共通の LE エンコードと整数レイアウトをそのまま使う。

## 判断待ち（3 点）

1. resident の終了コードを、PPC LINK の scope 終端で既存 EXIT として配送する案の採否。PC-98 resident も同時に対象にするか、LINK を持たない PPC 像には scope のみ提供するかを合わせて決める。
2. PPC の ext2 整数ドライブ番号と default 範囲の規約。lo0..lo3 に固定し、`format` を媒体全体、`format_at` を明示 LBA とする案。非ゼロ範囲の再 mount をゲスト受入用入口で行うか、通常 VFS からも指定できるようにするか。
3. 6c-loop の Device 書込 callback を PC-98 にも共通で公開する時点。共通で公開するなら同段に NP21/W の書込受入を載せる。PC-98 は媒体契約で許可するまでは既存経路のままとする場合、選択移管の差 0 を独立して求められる。
