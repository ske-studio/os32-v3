# os32-decision-fold — ユーザー決定を正典の一覧へ

memory は PM だけが読む。実装者・レビュアー・別の PM は読めないので、memory にしか無い決定は依頼の前提に出てこない。決定はリポジトリの一覧に書き、memory には個人の環境と道具の使い方だけを置く。

## 1. どこに書くか

| 決定の種類 | 書く所 |
|---|---|
| 設計・レビュー・依頼の前提 (何を想定しない、上限、手本の扱い、対象の機種) | [POLICY_DEV](../../../docs/POLICY_DEV.md) §10 の表に 1 行 (前提・中身・設計とレビューでの使い方・決定の日付) |
| 承認の要る操作・要らない操作 | [ROLES](../../../docs/tasks/agents/ROLES.md) §6 の表に 1 行 (操作・承認・条件とやり方・日付) |
| 運用の決まり (並行・待ち方・取り込みの順) | ROLES §6 の「運用の決まり」に 1 項目 |
| 役とモデルの割り当て、検査の分担 | ROLES §0 |
| 絶対の制約 | [CONSTRAINTS](../../../docs/CONSTRAINTS.md) (変える時はユーザーに確かめる) |
| ある票・ある設計だけの決定 | その票の「ユーザー決定」の節 (量は、何の量かを含めて原文で) |
| 現在地・止まっている/動いている | 最新の `docs/tasks/agents/HANDOVER_<日付>.md` |
| 延ばした試験 | `docs/tasks/DEFERRED_TESTS.md` |

書き方:

- 決定が変わったら行を書き換える。「旧: …」「撤回」と注記して残さない (経緯は git)。
- ユーザーの言葉は、量や範囲の意味が変わらないように原文を引く。PM の解釈は「PM の解釈」と分けて書く。
- 既に在る行と同じ趣旨なら、行を足さずに日付を足す。

## 2. 書いた後

```bash
for id in docs_links docs_navigation docs_source_refs docs_status; do
    python3 -B -m tests.infra.ci run --check "$id" || exit 1
done
```

文書だけの変更は、この検査を手元で回して main へ (スキル os32-land の「文書だけ」の行)。依頼文・レビューの依頼には、関係する行を前提として書く (スキル os32-delegate)。

## 3. memory に置いてよい物・置かない物

| 置いてよい | 置かない (正典に書く) |
|---|---|
| 個人の環境 (道具の置き場、`.env` の在りか、別名、ポート) | 方針・承認の範囲・設計の前提 |
| 道具の使い方の罠 (自分のコマンド行に一致する grep など) | 体制・役の割り当て・進捗 |
| 正典の場所への指し先 1 本 | 済んだ仕事の記録 (コミット・取り込みの結果) |

## 4. 畳み直し (memory に方針が溜まった時)

2026-10-06 と 2026-11-18 にした手順:

1. バックアップ: `tar czf <控えの置き場>/memory-backup-<日付>.tgz -C ~/.claude/projects/<プロジェクト> memory`。
2. memory の項目を 1 件ずつ、§1 の表の書く所と照らす。正典に行が無い決定は、行を足す。期限の切れた項目 (解除済みの一時の体制、消えたコマンド) は正典に移さない。
3. 正典の変更を main に入れる (§2)。
4. 正典に移し終えた項目を `memory/archive/` へ移す (削除しない)。索引の控えを `memory/archive/MEMORY_before_<日付>.md` に残す。
5. `MEMORY.md` を、正典の場所への指し先 1 行 + 環境と道具の項目だけに書き直す。

確かめる事: 外す項目の全部について「正典のどの行に在るか」を言えること。言えない項目は外さない。
