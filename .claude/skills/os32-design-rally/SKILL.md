# os32-design-rally — 設計の往復と確定

役の割り当ての正典は [ROLES §0](../../../docs/tasks/agents/ROLES.md) と [HANDOVER](../../../docs/tasks/agents/HANDOVER_2026-10-09.md) §2
(2026-10-21 に通常の体制へ戻した: 実装 = Codex (既定 sol、難所は astra)、sol の差分 → astra、astra の実装・設計票 → Opus reviewer。一時体制 (Fable/Opus) は終了)。
**レビューは PM が代行しない。3 往復で決着しない争点はユーザーへ。**

## 1. 置き場

- **往復の版** (`DESIGN.r1.md` → `REVIEW.r1.md` (PM がレビューの返答を写す) → `DESIGN.r2.md` …、起草者のログ) は `~/os32-tmp/run/<名>/` に置く。リポジトリには入れない。
- **確定版はリポジトリに入れる**: `DESIGN.final.md` と、確定の後の追記 (ADDENDUM・設計者が決めたこと・送り項目) を `docs/tasks/<領域>/design/<名>_DESIGN.md` などに写す (冒頭に出所の 1 行と状態行 `> 状態: **現行 (日付)** — …`、中身は変えず、リポジトリ内の文書への参照だけリンクに直す)。**確定の後に追記したら、同じ取り込みでリポジトリの写しも更新する** (実装者・設計者には写しの方を直接直させてよい)。
  理由 (2026-10-21、ユーザーの指摘): 戻す処理と GeForce 4a の確定設計と追記が ~/os32-tmp にしか無く、票に戻っていなかった。
- 票は `docs/tasks/…/TASK_<名>.md` に「§0 ユーザー決定」と「§1 詳細設計 (確定)」の要約だけを書き、全文は `design/` の写しへリンクする (例: [TASK_REALHW_RECOVER](../../../docs/tasks/realhw/TASK_REALHW_RECOVER.md) §6)。

## 2. 起草の依頼 (トークン節約が最優先)

```
あなたは OS32 (PC-9821 用 32bit OS、/home/hight/os32-v3) の設計者です。<何の> 実装可能な粒度の詳細設計を 1 枚書いてください。
トークン節約が最優先: 下に挙げた所だけ読み、実コードは grep で行を絞る (全文読みはしない)。
前提 (議論しない): シングルタスク・協調切替。9801 互換は考えない。整数演算が第一選択 (POLICY_DEV §2)。CLAUDE.md の [C1]〜[D3]。<決定済みの事項>。
読む所: <票の行範囲>、<関係する確定設計>、実コード (grep で): <関数・ファイル名>
書く物: ~/os32-tmp/run/<名>/DESIGN.r1.md (日本語、<150〜250> 行以内、表と箇条書き中心)。章立て:
1. 実物の確認 (票の前提と実コードの食い違いを file:line で)
2〜. <中身: 構造・関数の形・手順・誤りコード・置き場>。**部品の境目 (他の部品・既存の型とつなぐ関数・構造体・通信の形式・誰が状態を持つか) はコード断片で書く** — 「何をするか」だけで止めない
   **部品の大きさの見積もり** (どの像・部品に入るか、増える KB、起動 FD・MINIMAL・kdebug.bin の上限に触れるか)
n-2. ファイルごとの変更一覧 (新規/変更、おおよその行数)
n-1. 受入の各項目 → 試験 (host / ゲスト) と変異 1 行ずつ、段の分け方 (半日〜1 日、並列の可否、回す検査)
n. 未決 (ユーザー判断が要るものだけ、推奨付き)
返答本文は「書いた / 未決の数 / 実物との食い違いの数」の 3 行だけ。
```

- 2026-10-21 の反省 (ユーザー承認): 戻す処理と 4a の設計で、境目の形が無いために実装者 (sol) が「設計の欠け」で 6 回止まり、追記の往復が r4 と補完 2 回まで延びた。T3 では戻す処理が kdebug.bin に入って起動 FD の空きが下限を割った。上の 2 点 (境目のコード断片・大きさの見積もり) を起草の依頼に必ず入れる。追記で欠けを埋める往復も 3 回の上限に数え、超えたらユーザーに相談する。

## 3. レビューの依頼

```
OS32 の設計票 ~/os32-tmp/run/<名>/DESIGN.r1.md (<中身>、<起草者> 起草) をレビューしてください。設計ラリー第 1 回 (最大 3 回)。読み取りだけ。
前提 (指摘しない): シングルタスク・協調切替、9801 互換なし、過剰防御・マルチタスク前提は不要。<決定済みの事項と確定設計の所在>。
見てほしい点: (1) §1 の食い違いが実コードと合うか (file:line) (2) 実装者がこの文書だけで迷わず書ける粒度か (3) <この設計固有の危険: 回収・世代・固まる・ABI など> (4) 未決の推奨の妥当性とユーザー判断が本当に要るか (5) 段分けと試験・変異の対応。
書式: 指摘ごとに「重さ (P1 実装を誤らせる / P2 欠け / P3 軽微)・節・何が問題か・直し案 1 行」。全体 50 行以内。最後に「r2 が要るか」1 行と、未決の振り分け (ユーザー / PM)。
```

## 4. 往復

1. レビューの返答を `REVIEW.rN.md` に写す (要旨で可、ID と file:line は残す)。
2. 起草者には**同じ文脈に SendMessage** で差分だけ頼む (新しく起こさない — 読み直しのトークンを使わない):
   「REVIEW.rN.md を反映した DESIGN.r(N+1).md を書いて。rN からの差分だけ直し、関係する行以外は読み直さない。冒頭に『rN→r(N+1) の変更』を ID ごと 1 行、反論は末尾に 1 行ずつ。返答は『書いた / 反論の数』の 2 行」。
3. レビュアーにも同じ文脈で「第 N 回の指摘が直ったかと、直しで新しく生じた誤りだけに絞って、20〜30 行以内、最後に『確定してよいか』」。
4. **条件付きの承認で残りが数行なら、PM が直して `DESIGN.final.md` にする** (新しい往復を回さない)。
   直した点は final の末尾に「確定 (日付、誰の第 N 回、PM が反映)」として ID ごとに 1 行。
5. 実装に出した後に分かった決定・送り項目は、final の末尾に節を足して追記する (例「S1 の取り込みで決めたこと」)。追記はリポジトリの写し (`docs/tasks/<領域>/design/`) にも同じ取り込みで入れる (§1)。

## 5. 未決の扱い

- 推奨は基本的に承認 (memory)。**ユーザーに上げるのは**: 仕様の分岐、スコープの拡大、物理操作、ライセンス・法的な判断、決定済みの方針を覆すもの。それ以外は PM が推奨どおりに決めて final と票に「PM 決定」と書く。
- ユーザーの決定は量の意味ごと原文で依頼に書く (memory)。

## 6. 確定の後

- **粒度ごとに分けて写す — 試行中** (ユーザー指示 2026-10-22: 冗長にならないように。**正式に取り入れるかはユーザーが後で評価して決める** — 試した文書: HWDEV の 4 本 (docs/tasks/realhw/TASK_HWDEV.md と design/HWDEV_DESIGN・HWDEV_CORE_API・DEVICE_STATES) とこれから分ける分。評価の観点の案: 冗長さが減ったか、欲しい情報が 1 か所で見つかるか、リンクを辿る手間、更新のときの直し漏れ。評価までは新しい確定版に当て、既存の写しは無理に分け直さない): 1 枚の final をそのまま写さず、(1) 判断と状態 = 票 (`TASK_<名>.md`: 決定・段の表・状態行・送り項目の所在、短く)、(2) 構造 = `design/<名>_DESIGN.md` (分け方・方式の比較の結論・移し方)、(3) 参照の表 = `design/<名>_<API|TABLE>.md` (関数の一覧・ABI・構造体・番号)、(4) 他の設計からも引く要件 = 共通の文書 (例 `design/DEVICE_STATES.md`) に分ける。同じことを 2 か所に書かず、片方はリンクで指す。既存の写しに同じ内容があれば重複させずにそちらへ寄せる。
- `DESIGN.final.md` を `docs/tasks/<領域>/design/` に写す (§1 の形)。以後の追記 (設計者の決定・送り項目) もそのたびに写しへ入れ、写しと ~/os32-tmp の final がずれたら写しを正とする。
- 票の §1 に要約 (段の表・入口・PM 決定・全文の所在 = `design/` の写しへのリンク)、`docs/INDEX.md` から票が辿れるようにし (写しは票から辿れれば孤児にならない)、`make check-docs-links check-docs-orphans check-docs-status MUTATE=0`。
- 実装の依頼は os32-delegate、取り込みは os32-land。
